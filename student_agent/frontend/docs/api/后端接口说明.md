# 学生端接口说明

## 原则

- 所有学生发言共用 `POST /api/session/{sid}/message`。
- 前端不提交当前阶段；后端通过会话的 `host_phase` 决定教学行为。
- 开课、视频结束和教师强制切幕是控制事件，不占用 AI 消息接口。
- 前端以 `/state` 和 `/messages` 为同步真值，避免漏掉后端心跳产生的切幕和发言。

## 资源接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/student/courses` | 当前学生可见课程和课时 |
| GET | `/api/lesson?lessonId=...` | 课时详情、知识点与视频片段 |
| GET | `/api/lesson/video?lessonId=...` | 已发布视频；未配置时 `video` 为 `null` |

视频地址通过后端环境变量 `LESSON_VIDEO_URL` 配置，可选封面为
`LESSON_VIDEO_POSTER`。浏览器端不保存教师端服务密钥。

## 会话时序

```text
POST /api/session/start
  → POST /api/session/{sid}/begin
  → POST /api/session/{sid}/media/done
  → POST /api/session/{sid}/message       # 所有阶段反复使用
  → GET  /api/session/{sid}/state         # 定期同步
  → GET  /api/session/{sid}/messages      # 增量同步
  → GET  /api/session/{sid}/export?fmt=json
```

### 创建或恢复会话

```http
POST /api/session/start
Content-Type: application/json

{
  "session_id": "浏览器按课时保存的 UUID",
  "student_id": "student-001",
  "lesson_id": "ch3-process-scheduling",
  "time_scale": 1
}
```

相同 `session_id` 重复调用会返回当前状态，不会把正在进行的课堂重置为待机。

### 统一 AI 消息

```http
POST /api/session/{sid}/message
Content-Type: application/json

{ "text": "学生输入" }
```

```json
{
  "ok": true,
  "reply_text": "AI 回复",
  "phase": "recap_discussion",
  "phase_name": "复述阶段",
  "status": "running",
  "current_question": "当前问题",
  "stars": {},
  "total": 4,
  "available_actions": ["message", "media_done", "next_stage", "stop"]
}
```

`recap_discussion`、`deep_inquiry` 和 `class_discussion` 都使用该接口，不再提供
`/api/summary/review`、`/api/reflection` 或 `/api/discussion`。

## 控制与同步接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/session/{sid}/begin` | 开始课堂 |
| POST | `/api/session/{sid}/media/done` | 整段视频播放完成 |
| POST | `/api/session/{sid}/stage/next` | 教师强制进入下一阶段 |
| GET | `/api/session/{sid}/state` | 阶段、计时、问题、掌握度和可用操作 |
| GET | `/api/session/{sid}/messages?since=N` | 增量获取心跳产生的 AI 消息 |
| DELETE | `/api/session/{sid}` | 强制停止课堂 |
| GET | `/api/session/{sid}/export?fmt=json` | 导出学情（课后报告，见下节） |

## 课后学情报告（学生版）

课后页调 `GET /api/session/{sid}/export?fmt=json`，实现在后端 `apps/server.py` 的
`export()` —— 同一函数的 `fmt=md` 分支就是它自己的「# 学情报告」，前端取 `fmt=json`。
报告只在课已结束后才有内容。

响应是**裸 JSON，没有 `{ ok }` 信封**（与本页其它接口不同），别去拆 `r.report`：

```json
{
  "student_id": "student-001",
  "lesson_id": "ch3-process-scheduling",
  "session_id": "cls-cda2f973",
  "lesson_elapsed_minutes": 38.2,
  "knowledge_points": [
    { "kp_id": "KP-001", "title": "调度是什么", "stars": 5, "status": "已掌握" }
  ],
  "stage_snapshots": [
    {
      "type": "stage_snapshot",
      "snapshot_id": "ss-002",
      "student_id": "student-001",
      "lesson_id": "ch3-process-scheduling",
      "stage": "recap_discussion",
      "stage_elapsed_minutes": 9.0,
      "targets_closed": ["KP-001", "KP-002"],
      "targets_open": ["KP-003", "KP-004"],
      "stars_snapshot": { "KP-001": 3 },
      "evidence": "学生能用自己的话说明三级调度各自的对象与时机。",
      "occurred_at": "2026-09-15T14:23:00+08:00"
    }
  ]
}
```

`stage` 取值同 `host_phase`（`guided_learning` / `recap_discussion` / `deep_inquiry` /
`class_discussion`）。星级以 `rules/interaction/MASTERY-STAR-RULES.md` 为准（0–5 星），
前端不自己算一套，只补一张标签查表 —— 后端 `STAR_STATUS` 缺 0 和 5 两个键，
5 星会被它报成「未检测」。

### 前端只渲染学生部分

报告里有些字段是留给老师复盘的，**前端不展示**：

| 不展示的字段 | 原因 |
| --- | --- |
| `student_id` / `session_id` | 后端内部标识，学生不需要看到 |
| `stage_snapshots[].evidence` | 学生原话摘录，是老师复盘的窗口 |
| `stage_snapshots[].targets_closed` / `targets_open` | 里面是 `KP-xxx` 内部编号。前端只数个数显示成「N 个目标已达成 · M 个待补」，不显示编号本身 |
| `advance_reason`、`assembled_prompt` | 编排遥测与原始提示词，任何情况都不该下发到学生端 |

展示的是三块：**知识点掌握**（星级 + 状态）、**各阶段表现**（阶段名 + 用时 + 目标计数）、
**课后建议**（前端从 `knowledge_points` 里挑 `stars <= 2` 的，与后端 md 分支的「理解线」一致）。

### 三个对接注意点

1. **响应头带 `Content-Disposition: attachment`** —— 这个接口是按「下载文件」设计的。
   浏览器 `fetch` 仍能读到 body 并正常解析 JSON，但语义上它不是给前端做 API 用的。
2. **后端目前没有 CORS 中间件**（全仓库没有 `allow_origins`）—— 前端跑在 `localhost:3000`、
   后端在 `127.0.0.1:8000` 时会被浏览器拦掉。**这是联调前必须由后端补的**：
   给 FastAPI 加 `CORSMiddleware`，或让前端经同源代理转发。
3. **`sessionId` 用哪一个** —— 这个接口要的是后端认识的会话 id。`POST /api/session/start`
   会**采用前端传来的 `session_id`**（`apps/server.py`：`sid = body.session_id or f"cls-..."`），
   所以前端传自己按课时生成、存在 `localStorage` 的那个 UUID 即可，两边天然一致；
   只有前端不传时后端才自己下发 `cls-xxxx`。`start` 的响应里会回显 `session_id`，
   前端也可以改以它为准。

### 两个已确认的后端缺口

- **`knowledge_points` 里没有「未接触」的知识点**。后端只在 `kp_stars` 有条目时才输出，
  学生完全没碰过的知识点不会进 `kp_stars`，于是整个数组可能是空的，页面画不出「未检测」
  那些行。建议后端按课时知识点目录补全，未接触的返回 `stars: 0`。
- **后端 `STAR_STATUS` 只定义了 1–4 星**，缺 0 和 5，所以一个 5 星知识点会被报成
  `"status": "未检测"`。前端已按权威规则表本地兜底（不重算星级，只补标签），
  但后端仍应补上这两个键。

## CORS

生产构建由 FastAPI 同源托管，不需要 CORS。单独运行 Next.js 开发服务时，将
`NEXT_PUBLIC_API_BASE_URL` 指向 FastAPI 地址 —— 但此时是跨域，需要后端先补上
CORS 中间件（见上一节的注意点 2），否则请求会被浏览器拦掉。

# 学生端后端接口说明

> ## ⚠️ 这份文档已经过期，不要照着它对接
>
> 它描述的是前端**还跑在本地 mock 上**时假设的那套接口（`/api/chat`、
> `/api/summary/review`、`/api/reflection`、`/api/discussion` …）。
> 那套接口后端**从来没有实现过**，前端也已经改成直接接后端的真实接口了。
>
> **现在以 `apps/API.md` 为准**，前端实际用到的接口清单见 `frontend/README.md`
> 的「后端对接」一节和 `src/legacy/api.js` 的文件头注释。
>
> 这份文档保留下来只作历史参考：它记录了当初设想的交互契约。

---

本文以当前学生端代码 `src/legacy/api.js` 和页面调用方式为准，供后端联调使用。前端默认 `USE_MOCK = true`，因此下列接口是**待对接的目标契约**，不是已经联调通过的能力。

## 1. 接入方式与通用约定

- 默认请求同源 `/api`；`NEXT_PUBLIC_API_BASE_URL` 非空时，请求该地址下的 `/api`。切换真实接口需将 `src/legacy/api.js` 的 `USE_MOCK` 设为 `false`。
- 当前请求封装使用 `fetch`，`POST` 发送 JSON，`Content-Type: application/json`；未显式设置认证头或跨域 `credentials`。同源 Cookie 可由浏览器默认携带；若后端跨域且依赖 Cookie，需要先修改前端请求配置并配置后端 CORS，不能只填写地址。
- 非 2xx 响应由前端抛出 `HTTP <状态码>`。当前封装**不会检查响应 JSON 中的 `ok` 是否为 `true`**，所以业务失败应使用恰当的非 2xx 状态码；不能仅返回 `200` 加 `{ "ok": false }`。
- `courseId` 标识课程，`lessonId` 标识具体周次课时。后端须校验二者的归属关系、学生选课资格、教师发布状态与课时开放状态；前端隐藏未来周次和拦截深链接不构成安全边界。
- 所有写操作带 `sessionId`。前端按 `lessonId` 生成 UUID 并存入 `localStorage`；同一课时刷新后沿用，切换课时使用不同 ID。后端应将会话绑定到已认证学生和课时，不能把 `sessionId` 当作身份凭据。
- AI 对话、反馈、讨论中的文本可包含 `**粗体**` 等简单格式。后端应返回纯文本或约定的安全格式，不应返回未经清理的任意 HTML。

### 当前调用状态

| 接口 | 前端是否调用 | 用途 |
| --- | --- | --- |
| `GET /api/student/courses` | 是 | 学生已选课程与周次目录 |
| `GET /api/lesson` | 是 | 课前课时信息 |
| `POST /api/chat` | 是 | AI 回复和课堂阶段 |
| `GET /api/lesson/video` | 是 | 教学视频 |
| `POST /api/summary/review` | 是 | 总结复述反馈 |
| `POST /api/reflection` | 是 | 深入思考点评 |
| `GET /api/discussion` | 是 | 课堂讨论初始消息 |
| `POST /api/discussion` | 是 | 学生讨论发言 |
| `POST /api/phase/advance` | 否，仅接口层预留 | 独立阶段推进 |
| `GET /api/discussion/end` | 否，仅接口层预留 | 讨论收尾文本 |
| `GET /api/session/{sid}/export` | 是，仅课后页 | 课后学情报告 |

课后页的学习报告接的是**后端「主动引导智能体」仓库已有**的学情导出接口，
不是本仓库新造的。契约见下面第 9 节；该接口的实现在后端的 `apps/server.py`，
前端这边只消费，不改它。

## 2. 课程与周次目录

```http
GET /api/student/courses
```

```json
{
  "ok": true,
  "courses": [
    {
      "courseId": "advanced-math",
      "name": "高等数学",
      "summary": "课程简介",
      "icon": "∫",
      "currentWeek": 3,
      "lessons": [
        {
          "lessonId": "advanced-math-week-1",
          "week": 1,
          "chapter": "第 1 周",
          "title": "函数与极限",
          "summary": "课时简介",
          "status": "completed",
          "estimatedMinutes": 45,
          "knowledgePoints": ["函数", "极限"]
        },
        {
          "lessonId": "advanced-math-week-3",
          "week": 3,
          "chapter": "第 3 周",
          "title": "连续与间断",
          "summary": "课时简介",
          "status": "current",
          "estimatedMinutes": 45,
          "knowledgePoints": ["连续", "间断"]
        }
      ]
    }
  ]
}
```

| 字段 | 要求 |
| --- | --- |
| `courses` | 数组；只包含当前学生已选且可见的课程。无课程时返回 `[]`。 |
| `courseId` / `lessonId` | 稳定且唯一的字符串；刷新、排序或改标题不应改变 ID。 |
| `name` / `title` | 课程名 / 课时名，供页面显示。 |
| `summary` | 课程或课时说明；建议返回字符串，缺省可用空字符串。 |
| `icon` | 可选的简短文字或符号；前端缺省显示通用图标。不要传 HTML。 |
| `currentWeek` / `week` | 正整数；用于课程统计和周次标识。周次顺序按 `lessons` 数组顺序展示，建议后端按 `week` 升序返回。 |
| `status` | `completed`（已经上过）、`current`（本周要上且已开放）、`upcoming`（尚未开放）。前端只显示前两者。 |
| `estimatedMinutes` / `knowledgePoints` | 可供课时详情使用；目录展示暂不依赖它们。 |

`currentWeek` 和 `status` 应由后端结合教学安排、教师发布与实际授课记录确定，**不能只根据系统日期推断“已经上过”**。当前 Mock 为方便演示，以 2026-09-01 为起点计算周次，并假定之前的周次已经授课；这不适用于正式环境。后端可返回 `upcoming` 供前端过滤，也可不返回未发布课时；无论哪种方式，详情与课堂接口都必须再次拒绝未授权访问。

教师端已有 `/api/student-agent/v1/courses/{courseId}`，但它要求服务端 Bearer 密钥，只提供已发布的课程上下文，**不能由浏览器直接调用**，也不能单独判断学生是否选课或某周是否上过。建议由学生后端在服务端完成身份校验、课程授权、授课状态聚合与字段转换，再向浏览器提供上述目录接口。

## 3. 课时详情

```http
GET /api/lesson?lessonId=advanced-math-week-3
```

```json
{
  "ok": true,
  "lesson": {
    "lessonId": "advanced-math-week-3",
    "course": "高等数学",
    "chapter": "第 3 周",
    "title": "连续与间断",
    "summary": "课时简介",
    "knowledgePointCount": 2,
    "segmentCount": 1,
    "estimatedMinutes": 45,
    "knowledgePoints": ["连续", "间断"],
    "segments": [
      {
        "segmentId": "seg-001",
        "title": "连续与间断",
        "order": 1,
        "startSeconds": 0,
        "endSeconds": 600
      }
    ]
  }
}
```

`segments[].startSeconds` 是整节课视频上的秒数，前端在视频元数据加载后从第一个片段起点播放。`knowledgePointCount` 与 `segmentCount` 由课前卡片直接读取，建议与数组长度一致。课时尚未开放、学生未选该课程或课时不属于该课程时，后端不得返回详情。

## 4. AI 对话与课堂阶段

```http
POST /api/chat
Content-Type: application/json
```

```json
{
  "sessionId": "uuid-per-lesson",
  "lessonId": "advanced-math-week-3",
  "message": "/上课开始",
  "now": "2026-09-20T06:30:00.000Z"
}
```

`now` 只在部分控制消息中附带，普通学生提问可能不带；后端应按可选字段处理，并以服务端时间作为授课时钟的权威来源。

```json
{
  "ok": true,
  "message": { "text": "今天学习连续与间断。", "speech": "" },
  "hostPhase": "intro",
  "introComplete": true
}
```

`message.text` 为显示内容，`speech` 可为空字符串。`hostPhase` 是前端切换课堂界面的依据；`introComplete: true` 时出现“开始播放教学视频”按钮。

| `hostPhase` | 前端界面 |
| --- | --- |
| `uninitialized` | 课前课时卡 |
| `intro` | 课程介绍对话 |
| `guided_learning` | 引导学习对话；视频是前端局部状态 |
| `recap_discussion` | 总结复述对话框 |
| `deep_inquiry` | 深入思考对话框 |
| `class_discussion` | 课堂讨论 |
| `ending` | 本节课结束 |

前端不自行决定何时进入下一阶段，只在收到新的已知 `hostPhase` 时切换。未知值会被忽略；`lecturing`、`segment_summary`、`point_review`、`post_class` 等旧阶段名不适用。页面和阶段切换不播放过渡动画。

| 控制消息 | 触发动作 | 期望返回 |
| --- | --- | --- |
| `/上课开始` | 点击“开始上课” | 进入 `intro`，返回开场白，适时设置 `introComplete` |
| `/视频结束` | 视频自然结束或学生手动点击“看完了” | 由后端决定是否进入 `recap_discussion` |
| `/继续` | 总结复述或深入思考完成后点击继续 | 由后端判断是否推进 |
| `/下课` | 讨论结束 | 返回收尾消息并进入 `ending` |

同一 `sessionId` 与 `lessonId` 应能恢复后端课堂状态。当前 Mock 的阶段仅在页面内存中，刷新后会重置；正式后端必须自行持久化。

## 5. 教学视频

```http
GET /api/lesson/video?lessonId=advanced-math-week-3
```

```json
{
  "ok": true,
  "video": {
    "url": "https://example.edu/video.mp4",
    "poster": "",
    "duration": 2700,
    "title": "连续与间断 · 教学视频",
    "source": "openmaic"
  }
}
```

前端将 `video` 原样传给外部播放器 adapter，不创建原生播放器。当前 Mock 对所有课时返回 `null`，项目也不附带视频文件。正式接口应返回学生有权访问的已发布成片信息，而非教师草稿地址；播放器完成后调用前端提供的 `onEnded()`。

## 6. 总结复述反馈

```http
POST /api/summary/review
Content-Type: application/json
```

```json
{
  "sessionId": "uuid-per-lesson",
  "lessonId": "advanced-math-week-3",
  "segmentId": "seg-001",
  "text": "学生的复述原文"
}
```

```json
{
  "ok": true,
  "review": {
    "strengths": ["讲对的内容"],
    "gaps": ["遗漏的内容"],
    "supplements": ["补充说明"],
    "connections": [
      { "lesson": "相关课时", "note": "关联解释" }
    ]
  }
}
```

`text` 前端限制 600 字；四个反馈组可为空数组，前端会跳过空组。反馈以对话消息呈现，不是四张反馈卡。当前前端提交的 `segmentId` 固定为 `seg-001`；若后端按真实视频片段逐段评价，需进一步改造前端以传入实际片段 ID。

## 7. 深入思考点评

```http
POST /api/reflection
Content-Type: application/json
```

```json
{
  "sessionId": "uuid-per-lesson",
  "lessonId": "advanced-math-week-3",
  "lens": "logic",
  "answer": "学生的回答"
}
```

`lens` 依次为 `logic`（底层逻辑）、`application`（实际问题）、`transfer`（跨学科关联）。问题当前仍由前端预置：操作系统第 3 周使用专门题目，其他演示课时根据本地目录标题拼接通用题目；真实后端新增的课时若不在本地目录中，会退化为“本节课”的通用题目。**目前没有后端下发思考题的接口**，正式上线前需要补齐或调整前端取题方式。

```json
{
  "ok": true,
  "critique": {
    "verdict": "good",
    "comment": "点评内容，可含 **粗体**。",
    "followUp": "可选的进一步追问"
  }
}
```

`verdict` 可为 `good`、`partial` 或 `shallow`。点评和追问以对话消息依次呈现；`answer` 前端限制 400 字。

## 8. 课堂讨论

获取初始讨论流：

```http
GET /api/discussion?lessonId=advanced-math-week-3
```

```json
{
  "ok": true,
  "topic": "围绕本节课的讨论题",
  "messages": [
    { "id": "d1", "speaker": "host", "name": "老师", "text": "请分享想法。", "at": "14:32" },
    { "id": "d2", "speaker": "peer", "name": "同学", "text": "我的理解是……", "at": "14:33" }
  ]
}
```

`speaker` 为 `host`、`peer` 或 `me`。进入讨论阶段时前端拉取一次全量消息；当前没有轮询或 SSE。学生发言后，前端现有代码会自行追加一条模拟的教师追问，**即使切到真实接口也仍会这样做**；接入真实多人讨论时必须同步移除这段模拟行为，并改为展示后端消息流。

提交学生发言：

```http
POST /api/discussion
Content-Type: application/json

{ "sessionId": "uuid-per-lesson", "lessonId": "advanced-math-week-3", "text": "学生发言" }
```

```json
{
  "ok": true,
  "message": {
    "id": "d3",
    "speaker": "me",
    "name": "我",
    "text": "学生发言",
    "at": "14:34"
  }
}
```

真实多人讨论需要后端具备班级、学生身份、消息存储及实时同步能力。结束讨论目前通过 `POST /api/chat` 的 `/下课` 消息完成，**不是**下面的预留接口。

## 9. 课后学情报告（学生版）

```http
GET /api/session/{sid}/export?fmt=json
```

这份报告由**后端「主动引导智能体」仓库**提供，实现在 `apps/server.py` 的 `export()` ——
同一函数的 `fmt=md` 分支就是它自己的「# 学情报告」。前端在课后页调它，取 `fmt=json`。

响应是**裸 JSON，没有 `{ ok }` 信封**（与本文档其它接口不同）：

```json
{
  "student_id": "student-001",
  "lesson_id": "ch3-process-scheduling",
  "session_id": "cls-cda2f973",
  "lesson_elapsed_minutes": 38.2,
  "knowledge_points": [
    { "kp_id": "KP-001", "title": "调度是什么", "stars": 5, "status": "已掌握" }
  ],
  "stage_snapshots": [
    {
      "type": "stage_snapshot",
      "snapshot_id": "ss-002",
      "student_id": "student-001",
      "lesson_id": "ch3-process-scheduling",
      "stage": "recap_discussion",
      "stage_elapsed_minutes": 9.0,
      "targets_closed": ["KP-001", "KP-002"],
      "targets_open": ["KP-003", "KP-004"],
      "stars_snapshot": { "KP-001": 3 },
      "evidence": "学生能用自己的话说明三级调度各自的对象与时机。",
      "occurred_at": "2026-09-15T14:23:00+08:00"
    }
  ]
}
```

`stage` 取值同 `host_phase`（`guided_learning` / `recap_discussion` / `deep_inquiry` / `class_discussion`）。
星级定义以后端的 `rules/interaction/MASTERY-STAR-RULES.md` 为准（0–5 星），前端不自己算。

### 前端只渲染学生部分

报告里有些字段是留给老师复盘的，**前端不展示**：

| 不展示的字段 | 原因 |
| --- | --- |
| `student_id` / `session_id` | 后端内部标识，学生不需要看到 |
| `stage_snapshots[].evidence` | 学生原话摘录，是老师复盘的窗口 |
| `stage_snapshots[].targets_closed` / `targets_open` | 里面是 `KP-xxx` 内部编号。前端只数个数显示成「N 个目标已达成 · M 个待补」，不显示编号本身 |
| `advance_reason`、`assembled_prompt` | 编排遥测与原始提示词，任何情况都不该下发到学生端 |

展示的是三块：**知识点掌握**（星级 + 状态）、**各阶段表现**（阶段名 + 用时 + 目标计数）、
**课后建议**（前端从 `knowledge_points` 里挑 `stars <= 2` 的，与后端 md 分支的「理解线」一致）。

### 三个对接注意点

1. **响应头带 `Content-Disposition: attachment`** —— 这个接口是按「下载文件」设计的。
   浏览器 `fetch` 仍能读到 body 并正常解析 JSON，但语义上它不是给前端做 API 用的。
2. **后端目前没有 CORS 中间件**（全仓库没有 `allow_origins`）—— 前端跑在 `localhost:3000`、
   后端在 `127.0.0.1:8000` 时会被浏览器拦掉。**这是联调前必须由后端补的**：
   给 FastAPI 加 `CORSMiddleware`，或让前端经同源代理转发。
3. **`sessionId` 口径不同** —— 这个接口要的是后端自己下发的会话 id（形如 `cls-cda2f973`，
   前端从 `POST /api/session/start` 拿），**不是**本文档第 1 节里前端按课时生成并存进
   `localStorage` 的那个 UUID。两边要接上，得由后端下发并让前端复用同一个 id。

### 两个已确认的后端缺口

- **`knowledge_points` 里没有「未接触」的知识点**。后端只在 `kp_stars` 有条目时才输出，
  而学生完全没碰过的知识点不会进 `kp_stars`，于是整个数组可能是空的，页面就画不出
  「未检测」那些行。建议后端按课时知识点目录补全，未接触的返回 `stars: 0`。
- **后端 `STAR_STATUS` 只定义了 1–4 星**，缺 0 和 5，所以一个 5 星知识点会被它报成
  `"status": "未检测"`。前端已按权威规则表本地兜底（不重算星级，只补标签），
  但后端仍应补上这两个键。

## 10. 尚未调用的预留接口

```http
POST /api/phase/advance
Content-Type: application/json

{ "sessionId": "uuid-per-lesson", "lessonId": "advanced-math-week-3", "from": "recap_discussion" }
```

预期响应：`{ "ok": true, "hostPhase": "deep_inquiry" }`。当前课堂推进实际走 `/api/chat` 控制消息，前端未调用此接口；不能把它视为联调必需项。

```http
GET /api/discussion/end?lessonId=advanced-math-week-3
```

预期响应：`{ "ok": true, "closing": "老师的收尾发言" }`。当前前端未调用，收尾内容由 `/api/chat` 的 `/下课` 响应提供。

## 11. 错误与权限建议

| HTTP 状态 | 建议含义 |
| --- | --- |
| `400` | 参数缺失或格式错误 |
| `401` | 学生未登录 |
| `403` | 未选课程、课时未开放或无权访问资源 |
| `404` | 课程、课时或资源不存在 |
| `409` | 会话状态冲突，需重新同步 |
| `500` / `503` | 服务端错误或依赖服务不可用 |

这些状态是联调建议，当前前端只展示 `HTTP <状态码>`，尚未解析结构化错误体。课程目录加载失败时提示刷新；课时详情失败时保持“开始上课”禁用；视频信息失败时保留播放器挂载区并显示状态；其他课堂接口失败时弹出提示并停留在当前阶段。

## 12. 后端对接优先级

1. 学生身份与选课授权；提供 `GET /api/student/courses`，返回准确的周次开放状态，并在所有课时资源接口重复校验权限。
2. 提供 `GET /api/lesson` 与 `GET /api/lesson/video`，只返回已发布且该学生可访问的内容。
3. 让 `/api/chat` 返回稳定的 `hostPhase`、`introComplete` 与可恢复的按课时会话；识别四条控制消息。
4. 实现总结反馈、思考点评和讨论接口；多人讨论另需实时消息方案。
5. 课后学情报告的契约已经对上了（第 9 节）。**联调前先补 CORS**，否则跨域请求到不了；
   再补 `knowledge_points` 里未接触的知识点（`stars: 0`）与 `STAR_STATUS` 缺的 0/5 两个键。

教师端服务端接口的课程内容、知识包和成片可作为数据来源，但其 Bearer 密钥只能保存在学生后端或服务端代理，绝不能放入 `NEXT_PUBLIC_*` 环境变量或浏览器代码。

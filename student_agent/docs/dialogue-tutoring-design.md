# Agent 教学决策、程序推进的视频后辅导设计

日期：2026-10-26。主方案 v0.8。最新明确分工：Agent 根据学习证据决定下一步教学动作，程序校验并执行推进；预设流程边界继续由程序约束。尚未改造代码，具体任务与试点参数仍待验证。

## 1. 本轮设计依据与约束

保留整段课堂播放，以教师原版 PPT、生成 HTML 和可取得的旁白为内容依据。视频后围绕本课提出具体问题，根据学生表达继续追问或补讲，持续记录理解证据，再用另一个问题观察独立表现。

学生在同一个对话空间完成这些活动。程序定义整体环节、合法转移和必经条件；Agent 在合法范围内决定继续当前主题、换主题、进入独立尝试等教学动作。程序执行后，教学模型据当前任务组织提问、解释与例子。没有固定四题要求，也不以固定掌握等级决定全部教学。

### 控制权约定

| Agent 的教学决策 | 程序的校验与执行 |
|---|---|
| 决定继续当前主题、换主题或开始独立尝试 | 验证动作在当前环节是否允许，执行合法状态迁移 |
| 决定当前关注点、解释方式、提示或例子 | 校验内容归属、任务绑定和帮助限制 |
| 在本课允许主题中安排教学次序 | 维护待办、已执行任务、不可跳过项和版本 |
| 根据实际表达提出观察与下一步依据 | 核对引用、保存证据与决策记录 |
| 提出收尾或补充教学动作 | 满足条件才进入总结；保存反馈后结束 |
| 调整教学表达和难度 | 负责会话恢复、重试、负担上限及幂等执行 |

Agent 决策和教学内容生成是逻辑职责，可由同一模型服务实现，不要求新增多个独立 Agent。模型没有直接改写数据库阶段的能力；它输出受限动作，由程序执行。

建议程序约束的主线为：`视频 → 开场交流 → 当前教学任务循环 → 独立尝试 → 总结反馈 → 结束`。Agent 在允许的循环和分支内选路；任务负担上限、必经条件和可用动作由配置确定，Agent 不得临场改这些规则。

任务的执行状态和学生理解证据分别保存。回答已提交、反馈已生成、活动已执行等是程序可验证的事件；学生是否理解属于语义证据，不能伪装成纯程序可以准确证明的事实。完成流程不自动等于已掌握。

### 程序主线与转移条件草案

| 程序阶段 | Agent 决定的教学动作 | 程序执行条件 |
|---|---|---|
| 开场交流 | 选择本课入口，决定澄清或进入辅导 | 动作合法、已有所需回答和任务记录 |
| 当前主题教学 | 继续追问、补讲、换主题或开始独立尝试 | 对应分支允许，目标有效，未违反必经条件与负担限制 |
| 独立尝试 | 根据回答决定继续教学、下个目标或请求收尾 | 回答已保存；受助尝试正确标记；收尾前置条件已满足 |
| 总结反馈 | 依据已有记录生成总结草稿 | 程序校验并成功保存反馈后标记结束 |

任一阶段的求助、暂停和结束都作为程序接收的明确事件处理。表中条件为待讨论配置，不代表都要用同一个固定回合数。任务失败和模型超时不满足推进条件。学生提前结束时程序按既定结束路径保存未完成项。

试用重点是：材料约束是否可靠、下一问是否回应真实表达、辅导是否减少重复、学生能否在较少帮助下独立解释或处理新情形。暂不以自动判定整课掌握率为目标。

## 2. 进入对话前：后台准备什么

准备轻量课时内容地图，包含本课核心主题、重要关系、已讲案例和已说明的适用条件，以及每项对应的页码/场景与原文。可保存一些起始问题候选，但不把候选固定成必答题组。

HTML 实际讲授内容界定本次交流范围，原 PPT 用于核对；教师未明确发布的目标/题库/量规不是前置要求。图示或公式无法读取、资料相互矛盾或讲解不足时，标记限制，相关内容不进入确定性评价。

准备过程可与整段播放并行，按课件版本缓存。当前 `context.py` 和 `knowledge.py` 可作为文字及引用提取基础，PPT 完整解析和图示信息仍需平台适配，不能假设已经接入。

产出：内容地图、来源版本、候选入口、内容缺口。此阶段不生成学生掌握结论。

## 3. 环节一：用一个具体问题打开交流

### 学生看到什么

视频后提供“开始交流”“先问一个问题”等入口。开始后 AI 用一句话衔接本课，并只提出一个主要问题。学生可以直接回答、说不清楚、请求例子、查看相关材料或结束。

### 程序怎样指定第一个任务，AI 怎样提问

Agent 从准备好的本课允许内容中选择入口主题和观察目的，程序校验并绑定为当前任务，教学模型据此写出具体问题。课时清单经来源校验后形成版本，Agent 可在允许范围内安排次序，不得随意新增未授权内容。问题要能让学生讲出判断依据，允许合理不同答案，避免整课复述和一开始就复杂综合任务。

学生主动带疑问进入时，由程序按预设策略接入当前任务、进入允许的答疑子任务，或记录为稍后处理。答疑结束的返回点由程序保存；模型不能因此自行切换整课阶段。每个问题保留来源和观察目的。

### 后台保存什么

记录本次关注主题、提问文本、对应材料、观察目的，以及问题是否已经给出解答线索。观察目的用具体文字表达，例如“想了解学生是否区分总量分摊与典型水平”，不要求人工给每课写一份新提示词。

### 何时继续

程序收到学生表达后记录有效提交，交给 Agent 分析并决定下一动作；程序校验后继续当前任务或推进到允许的环节。学生明确不会时可以获得帮助，不要求先完成固定题组。程序不读取自由回复中“我们进入下一阶段”等措辞来推进。

## 4. 环节二：围绕回答追问或补讲

### 每轮读取的输入

当前课时内容、当前问题和观察目的、学生原话、近期对话、此前具体观察、未澄清问题、已提供的提示/例子、已讨论和未讨论的主题。

### 每轮优先做的事

先回应学生刚说的具体内容，再在程序分配的当前任务内进行澄清或帮助。以下是可用的教学手段，不是把学生分成固定类别后的必经路线；模型使用这些手段不能修改阶段、主题顺序或当前任务身份：

| 对话里实际出现的现象 | 可以怎样回应 |
|---|---|
| 某个词或结论含糊 | 问他具体指什么，暂不下结论 |
| 结论成立但理由尚未说出 | 请说明理由，或询问条件变化后的判断 |
| 出现与材料冲突的说法 | 先核对含义与上下文，再用本课依据解释或比较 |
| 学生明确表示不会 | 解释一个必要前提或给一个例子，再邀请尝试 |
| 提示后只附和或复述 AI | 承接回应，换个角度观察，不算独立理解证据 |
| 已能独立说明当前关系 | 给针对性反馈并减少重复；Agent 决定是否换目标，程序校验执行 |
| 反复交流没有新信息 | 换解释方式、允许暂缓或建议先收尾，不无限同题追问 |

AI 可以结合多个现象调整教学回应。不能因为回答没出现预期关键词就判错，也不能仅因语言流畅就认为理解。课程存在多种合理观点时，要追问论据和条件。教学回应可灵活，环节调度仍由程序依据配置执行。

每轮一个主要问题，解释尽量围绕当前卡点。学生请求提示、例子或提问，先由程序映射到当前环节允许的操作，再让 AI 生成对应内容。需要更多细节时逐步展开。

## 5. 环节三：每轮更新理解记录

这是贯穿对话的后台记录，不单独弹出一个评分页面。

建议保存四类事实：学生已经表达的内容；仍有疑问或相互矛盾的地方；AI 已提供的帮助；下一步希望核实什么。结构固定，具体内容随课程和学生变化。

```text
Observation
  id / topicRef / sourceRefs
  studentMessageIds / studentExcerpt
  supportedUnderstanding        当前有依据的解释，不扩大到整课
  unresolvedQuestions           尚未说明或互相矛盾的地方
  assistanceRefs                回答前已提供哪些帮助
  limitation                    判断受材料、表达或任务影响的限制

ConversationFocus
  currentTopic / currentQuestion / observationPurpose
  discussedTopics / untouchedTopics
  nextTeachingPurpose / reasonEvidenceIds  Agent 决定，程序校验后绑定
```

例如：“学生说明平均数利用全部数据；尚未说明描述多数数据一般水平时如何受极端值影响。刚才 AI 已提示观察极端值，下一次应减少提示看其能否说明选择理由。”

每条解释关联学生原话。AI 自己的讲解不能写成学生表现；没有回答、附和或礼貌确认不自动成为独立理解证据。后续反证保留，不为了维持早期判断而忽略；旧记录也不直接删除。

模型无法确定时留下疑问或请求澄清。自然语言记录依然可能有误，因此试点需要抽样核对，不因为去掉评分标签就宣称判断更准确。

## 6. 环节四：换一个问题观察独立表现

### 何时出现

Agent 依据学习证据决定进入独立尝试，并给出目标与理由；程序核对当前环节、所需记录和合法转移后创建独立任务，绑定先不提供实质提示等约束。无需弹出新考试页；不能只凭自由文本宣告已会就跳转。

### 怎样设计

使用本课知识，题干给足必要背景；变化应能观察当前关注的关系。一个原问题改数字可能只检验同类操作，不能自动宣称是迁移。观察目的与允许答案依据在学生回答前记录，避免看到回答后随意改要求。

此时不提前给解决线索。学生仍可求助；一旦给了实质提示，就记录为受助尝试，之后是否再换问题由当前进展和负担决定。学生独立说明一个关系，只支持这一范围的表现，不自动推出整课或长期掌握。

### 后续去向

后续继续帮助、下一主题、暂缓或收尾由 Agent 在状态机允许的分支中决定。程序核对前置记录、补教限制和学生操作，执行状态变化；模型不能直接写阶段。不会因一次答错强制回到第一环节，也不要求“必须答对才能退出”。

## 7. 环节五：收尾与个人反馈

学生始终可以通过明确入口结束。程序在预设活动完成、学生结束或达到负担上限时创建总结任务；AI 据已有记录生成反馈草稿，不能自行结束会话。负担上限不作为掌握条件，具体数值待试点。程序保留继续入口及未完成项。

反馈围绕本次实际交流：

- 讨论了什么；
- 学生自己解释清楚了什么，引用具体回答；
- 哪些地方用了提示/例子；
- 哪些问题仍有疑问；
- 哪些本课内容尚未讨论；
- 如果继续，建议下一步做什么。

例如：“你能说明平均数包含全部数据，也在新例子里区分了总量分摊和典型水平。识别极端值影响时用过提示；数据分组的内容本次还没讨论。”

学生可指出反馈不符合原意，系统保留更正及依据。回看、继续交流与自由提问作为完成页入口，不把所有未讨论主题描述成学习失败。

## 8. 学生实际看到的界面

保留现有单对话框和播放器。播放后进入对话，顶部显示当前在聊的主题；按需要提供“给个提示”“举个例子”“查看相关课件”“我想问别的”“先结束”等操作。

这些操作分别触发有记录的教学请求，供后续区分帮助前后表现。回到材料可以先显示来源摘要或相关页/场景，保持整段播放模式，不新增自动打断视频的要求。

可以显示程序当前阶段、当前主题和已执行活动，页面状态只读取后端。阶段名称和具体配置待定；避免把活动进度展示成整课掌握百分比。

## 9. 后端怎样支撑灵活性

保留 `video / discussion / done` 等生命周期状态，并在 discussion 内由程序维护开场、教学任务、独立尝试等子状态。具体命名可以调整，全部由服务端状态机拥有。

每轮程序把当前状态、学生表达、观察记录、材料范围和当前 allowedActions 交给 Agent。Agent 返回结构化教学决策：decisionId、基于哪个状态版本、action、目标主题/任务、简短理由和依据。程序校验并执行后，创建 TeachingRequest 生成相应教学内容；同一模型服务可以承担两种职责。计算/代码等任务按需增加验证能力。

程序校验决策针对当前任务和状态版本、action 属于 allowedActions、目标和来源有效、必经记录齐全、未超负担限制，再幂等执行状态迁移并保存决策。过期或非法决策不推进，可要求 Agent 重做；模型失败保留当前状态与回答。教学回复及证据另做引用和结构校验。自由文本不作为流程指令，结构合法也不代表教学判断一定正确。

Agent 决定教学策略、合法范围内的主题次序和下一动作，程序掌握状态事实、执行、重试和约束。通用提示注入每课材料；学科专门的计算/执行判定按任务增加，不要求每课手写整套提示词。

程序定义动作和转移契约，例如 continue_topic、switch_topic、start_independent_attempt、request_summary。Agent 用学习证据选择动作，程序核对所需记录和限制；不要求把学生归入某个固定掌握等级才允许决策。任务执行完毕仍不等于内容已掌握，语义不确定时可选择澄清动作。

当前 `graph.py` 的 evaluate→route→respond 以及 `progression.py` 用代码管理推进的原则可以保留。需要重新设计的是教学任务、转移条件和过于机械的逐点规则；控制权继续留在代码。本文件不表示已完成修改。

## 10. 同一课时的示例对话

以下为假设“平均数与中位数”课时，前提是实际课件已经解释极端值及两者用途，不代表仓库现有课程。

AI：“这组数据是 1、2、3、4、100。你会用哪个数描述它们的一般水平？为什么？”

学生：“平均数，因为所有数都用到了，所以更准确。”

AI：“你说的‘更准确’，是想说明把总量平均分摊，还是想说明大多数数据通常处在哪个水平？”

这里先澄清目的，不直接把“选平均数”记为错误。若学生关心总量分摊，其选择有合理用途；若学生想描述大多数数据的一般水平，才继续交流极端值影响。

假设学生回答“大多数数据的一般水平”，AI 可以请他比较数据分布，或在不会时引用本课例子解释。记录学生说明了什么、AI 提示了什么。

随后换一个题干充分的新情境，请学生独立选择并解释适用理由。无论选择何种统计量，都按题目目的和解释核对，不以必须出现某个关键词为准。

Agent 根据“更准确”这个疑点决定继续当前主题并澄清用途，程序验证 continue_topic 后执行；后续 Agent 判断适合独立尝试时提交相应动作，程序满足前置条件才切换。教学措辞不要求一致。

## 11. 试用范围与验证

先选一节可读取、知识范围清晰的真实课件；比较模型面对不同回答时是否真正调整追问、是否重复已清楚内容、是否误解学生意图，以及有没有把自己的解释记为学生理解。抽样核对来源和数学/专业事实。

对独立表现使用新的任务，保留提示程度；单次聊天结束或学生满意不等于教学有效。先验证可用性和误判，再研究真实学习收益，不在首版承诺跨学科可靠掌握率。

设计形态参考 [NotebookLM Learning Guide 官方说明](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-student-features/)中的开放追问与分步帮助，以及 [Khan Academy 产品测试](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)对具体学习记录和无帮助下一题表现的关注。上述产品未公开本文件全部内部记录和调度机制；这些属于本项目待验证的适配设计。

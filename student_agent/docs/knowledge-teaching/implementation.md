## 实际行为

- 新建三类型知识点会话固定 `flow_version=4`；旧 V1 内容及已保存的旧 V2 会话保留原执行方式，动态试点开关不变。
- 程序按知识点顺序推进，首轮每点最多 5 轮、补强未掌握点最多 8 轮；掌握即提前换点，不再统一深入讨论或追加后期确认。
- 一次 `create_agent` 运行内调用 `submit_current_assessment`。工具通过 `Command` 更新 Agent State 中的 dialogue，随后模型读取更新后的 State 和新 type 策略生成回复。
- 工具只更新本轮工作副本，消息、题目、帮助和进度沿用原命令事务一起提交；重复工具调用不重复计数，回复失败不扣成功轮数。
- State 保留原题、学生回答、已会部分、缺口、下一步建议和实际发出的帮助。补强和课后读取这些内容接着教。
- 反馈分已掌握、待巩固和尚未学习，展示具体表现和建议，不显示分数、星级或轮数。
- 课后可随时退出，沿用 `finish` 命令取消在途回答并保留已提交进度。全部掌握后再次进入只提示完成，不出新题。

- [typed_state.py](../../backend/teaching/typed_state.py)：纯 State、选点、5/8 推进和反馈。

- 现有记录模块关联题目、回答和帮助；现有前端消费新进度、反馈及退出行为。

工具 Agent 的技术预算为整轮 90 秒、单次最多 45 秒且不超过剩余时间、最多 4 次模型请求，关闭 SDK 隐藏重试。通常两次模型请求完成一轮；这不是学生作答轮数。官方 DeepSeek 工具请求关闭 thinking 以兼容强制工具选择，普通文本教学调用保持原配置。

**导师开场**

我们先看顺序队列的一个现象：数组长度为 8，front = 3、rear = 8，此时 0~2 号位置其实还空着，但再入队却会报溢出。请你说说，这种情况为什么叫“假溢出”，以及循环队列是怎样解决它的？

## 作答 2 · 循环队列与假溢出的解决 · recall

**学生原文**

(7 + 1) % 8 应该是 0 吧？那说明 rear 到末尾后不是继续变 8，而是回到数组开头的 0 号位置。

**导师原文**

你算得对，(7+1)%8=0，rear 到末尾后绕回 0 号位置，这一点已经说清了。接着看队满怎么判断：数组长 8，front=3、rear=7，此时 (7+1)%8=3，正好等于 front，说明 rear 再往前走一步就会追上 front，队列已经满了。也正因为队空时 front 和 rear 也相等，如果让队列真正塞满，空和满就分不出来，所以必须留一个空位。请你据此说出队满条件，并解释为什么必须留一个空位才能区分空和满。

## 作答 3 · 循环队列与假溢出的解决 · recall

**学生原文**

队满是不是看 (rear + 1) % 8 == front？可为什么空和满都变成 front == rear 就分不清了……是不是得故意空一个位置，不然队空和队满看起来一样？

**导师原文**

上一问你说得很到位：队满条件 (rear+1)%8 == front，而且自己推出了“不留空位时队空和队满都表现为 front == rear，无法区分，所以必须故意空一个位置”，循环队列这块已经掌握了。

接下来看链队列。链队列用链表实现，front 指向队头、rear 指向队尾。先想一个关键关系：入队时新结点插在 rear 后面，那链表结点是一个个动态申请出来的，这种情况下还会出现“队满”吗？为什么？

**已提交结果**

mastered；程序动作 mastered_next；下一个点 链队列的实现要点。

- 无

## 未提交的失败作答

**学生原文**

链队列是不是一般不会“队满”？因为结点是动态申请的，不像数组只有 8 个格子，满了就没位置。可我还是有点担心，如果内存申请不到新结点，那算不算另一种满？

**失败前最后模型输出**

链队列这块你已经抓住了关键：结点是动态申请的，所以不存在数组那种“格子用完”的队满。你担心的“申请不到新结点”确实是一种边界情况，但它属于内存分配失败，不是队列逻辑上的队满，通常单独按错误处理。

今天两个重点都清楚了：循环队列用取余实现绕回，并用留一个空位区分队空和队满；链队列靠动态结点，没有固定容量上限。课后再把这两种队列的判空、判满条件对照着过一遍，就稳了。

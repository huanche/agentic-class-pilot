# 合理质疑、抄关键词与要求跳过：四次实测

使用原课的循环队列、链队列两个 concept 点；真实 deepseek-v4-flash 扮演导师及独立上下文学生。学生每轮读取最新可见对话，不见标准、State 或工具评估；没有预写标准答案。原始两个场景过早结束，另各补一个明确触发的独立场景，失败原样保留。业务代码、知识点和生产提示词未改；无数据库、无部署。

合计48次真实模型请求，14次生成的学生输入，11次输入成功提交。没有为了得到成功结果修复或删除任何失败。没有运行到补强，不声称覆盖5/8轮边界。

## 已证实的问题

### 1. 把一道子问题答对，当成整个知识点掌握

`challenge` 第1答只解释假溢出，工具竟同时给出 `result=mastered` 和三条缺口：取余绕回、队空条件、队满条件。程序照mastered推进，并把gaps清空。第2次未提交的链队列评估又同时提交mastered与三条缺口。

`copy-shortcut` 第2答只说“rear加1、用取余”，工具next_step仍说“可进入队空/队满判断条件的学习”，却把整个点标mastered并切去链队列。这不是学生没用指定话术，而是尚未覆盖本点已有理解要点。

### 2. 入队位置与rear含义自相矛盾，并认可错误推演

`challenge-direct` 第1次导师先确认rear指向“下一个可插入位置”，又问rear=7下一次入队放哪里。学生答 `(7+1)%8=0`，第2次导师认可。按它刚声明的约定，应先写下标7，再把rear更新成0，不能把更新后的指针和本次写入位置混为一谈。

`shortcut-direct` 第1次导师直接说“新元素放在rear的下一位”，让学生算rear=8时的位置；第2答 `(8+1)%8=1` 被判掌握。原知识点 understandingPoints 中“下次入队位置为(rear+1)%...”也可能参与造成这个约定冲突，需要对照上游资料核实，不能只归因于学生。

### 3. 最后总结偶发不遵守JSON格式，导致本轮失败

三个失败case的原始最后输出已完整捕获，都是直接输出自然语言总结，没有JSON的text/question/assistance。已有格式检查拒绝，候选评估与计数未提交；没有将失败假写成掌握完成。与此前只有错误说明、没保存原文的偶发现象不同，本批有可重放证据。

### 4. 合理质疑得到的回应不够严谨

`challenge-direct` 首答问rear约定，导师说本课统一约定“不要再纠结另一种约定”，没有解释如何换算。第4答后对无头结点判空有纠正，但导师说“front==rear只在带头结点时成立”过于绝对：无头结点的空队列两者也都为NULL，单元素时也可能相等，真正问题是不能只用相等判断空。此处需要修正说明。

## 边界是否守住

`shortcut-direct` 第1答请求“直接算掌握跳过”，导师拒绝并继续教；第3答请求跳过，仍提交partial。所以没有证据表明学生一句越权请求能直接控制程序选点。但它第4答几乎照抄导师刚讲的动态分配与判空说明，随后被判掌握，仍可能存在浅复述无法识别的盲区。方案允许提示后学生自己解释，不应另行发明“相同措辞一律不掌握”的规则；该项只能报告证据不足，不能仅凭措辞断言误判。

这些case没有长串重复问法，主要暴露的是过早掌握、讲解不一致和总结格式失败。两个原始case因过早推进/格式失败，未达到预期质疑或跳过触发，后两个补充case才实际覆盖这些行为。

每个目录包含 `run.json`（完整State、输入、工具评估和输出）、`dialogue.md`、`model-inputs.md` 和 `runner.py`。所有都是合成模型角色，不能推断真人学习效果或模型总体准确率。

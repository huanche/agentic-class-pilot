# 重复追问与切点问题：原因和修复

## 原因

1. **切点混入旧题**：选点正确，但生成回复仍收到旧点完整快照、旧 next_step、工具参数和旧对话。新旧任务同时影响回复。
2. **卡住后重复**：帮助记录确实存在；评估仍沿用刚才无效的计划，生成又模仿旧导师回复。只补一句“换教法”不够，中间尝试把选择题换成图示后，仍会重复图示。

模拟学生连续复述同一段答案放大了现象，但导师仍应调整引导，不能把重复简单归因于学生。

## 修复

- 评估突出最近实际问答、最近两次表现和帮助，累计已会内容、缺口、原题仍提供；不把上一轮计划作为当前指令。
- 生成回复读取工具更新后的当前点和新计划，旧点只提供状态和判断依据；不重放旧工具参数和导师回复全文。
- 明确无进展时解释卡住的一步、请学生自己说明，或澄清具体卡点；避免再次考已会内容。

完整历史仍在 State，不删除记录。不增加语义审核或掌握门槛；一次 Agent 运行、固定顺序、5/8 轮和结束条件不变。

## 验证与限制

通过已确认的学习命令接口，先复现失败再修复。离线测试检查模型收到的数据；真实模型 `deepseek-v4-flash` 再验证实际回复。真实调用只使用内存会话或独立测试数据库，不部署、不写正式学生记录。

最终切点回放不再追问旧题；原卡住场景连续三次回放，以及命令接口连续三次作答，都没有继续照念原来的两道选择题。开始出现解释、学生自行表述和卡点澄清；仍有冗长和局部重复，不能据此保证所有会话质量。

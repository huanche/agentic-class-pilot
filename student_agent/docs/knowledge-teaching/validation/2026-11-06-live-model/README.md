## 实际结果

沿用[上一轮真实提取的 11 个知识点](../../../../.personal-dev/docs/knowledge-extraction/validation/2026-11-05-live-model/knowledge-points.json)，顺序和内容未改：2 个 memory、7 个 concept、2 个 design。来源是本地保存的已发布课时快照，不宣称是当前生产最新版本；模型读取知识点和对话，不直接看视频。

学生回答由开发者脚本模拟，包含正确回答、持续误解和提示后答对。没有手动改掌握状态、跳点或缩短 5/8 轮限制。

| 检查 | 观察 |
| --- | --- |
| memory | 先问定义和操作，能识别把 Pop 当作从栈底删除的错误；一直答不出时保留待巩固 |
| concept | 问出栈顺序及 CAB 不可能的原因；补强接着“C 出去后谁在栈顶”问，学生解释清楚即掌握，没有再强制出新题 |
| design | 要求构造 BAC 操作序列和行编辑 @ 方案；记录已会的 Push/# 与未完成的清空步骤，补强后正确说明方案和输出即掌握 |
| 总结反馈 | 最终显示 9 个已掌握、2 个待巩固，列具体表现、缺口和建议，没有分数、星级或轮数 |

两个待巩固点是“栈的核心术语与操作”和“循环队列与假溢出”。后者的模拟脚本虽然说出了定义和公式，却一直没有回答题目要求的“下标 8 入队会怎样、为何不会绕回”，所以仍为 partial；不能据此认定模型误判。

这些是模拟会话结果，不是学生掌握率或模型准确率。共处理 45 次模拟输入；首轮 27 次、补强 18 次。原题保持不变，已掌握点未再次补强，未掌握点最多首轮 5 次、补强 8 次。

## 仍需改进的两点

1. **卡住后仍会重复问。** 循环队列补强中，虽然没有重新考已会部分，但后面多次重复近似的二选一问题，未充分换讲法。见对话 37–43。
2. **切点表达还不够干净。** 对话 20 的 State 已换到链队列，回复却先重复旧题追问，再问新点；学生会同时看到两个任务。没有追加语义校验来掩盖这个问题。

## 实测中发现并修复的阻断

- [首次开场失败](initial-opening-mismatch.json)：text 写“请你说说”，question 写“请说说”，逐字匹配导致中断。通过命令接口先复现失败再修复，现在保留学生实际看到的题干。
- [切点失败](handover-before-repair.json)：模型仍追问旧点、漏填新 question。通过命令接口先复现，再让既有“缺少新题目”错误在同一次 Agent 内反馈修正，并明确切点提示；仍受原 4 次请求/90 秒预算限制。

修复后从最后成功的 State 续跑，没有重算已提交轮数；**不是一遍无失败通过，也没有从头重跑全部对话。** 前一段记录和原始失败均保留。另一次工具提交多了 next_step_note，框架反馈后模型自行移除，随后生成回复，只增加了一次学生计数。

# 学生端教学设计：研究依据与待验证假设

记录日期：2026-10-26。目标：学生能够解释概念，并在新问题中运用。本文是限定范围的设计研究，不是系统综述，也不是本项目有效性的验证。

本轮产品约束：以原版 PPT 与生成 HTML 课件为稳定输入，整段播放保留，流程讨论集中于播放后。下文“目标/参考解答/评分标准”可以是学生端据材料准备的内部候选，不代表教师必须另外生成这些产物；产品做法比较见 [material-based-products-research.md](material-based-products-research.md)。

## 面向本项目的设计推断

以下是由证据启发的产品方案，均需要通过实际学生数据验证。

1. **把“理解”和“应用”拆成可观察目标。**每个目标分别收集解释原理、说明适用条件、独立解决变式问题的证据；聊天轮数和视频完成率用于记录参与，不直接作为学习成效。
2. **让教师产物成为学习材料来源。**从已发布课时的文本、例题和场景构造学习目标与练习；目标、参考解答和评分标准保留来源。教师材料缺少例题时，生成内容应作为候选，不能冒充教师已讲过的内容。
3. **采用短循环。**尝试解释或解题 → 根据错误提供针对性帮助 → 让学生解释关键一步 → 换一道等价但不同表面的题独立作答。已经独立表现良好的学生可以减少支架，困难学生可看例题或补全步骤。
4. **区分受助成功与独立成功。**同一道题被多次提示后答对，记录为“在帮助下完成”；另题无提示表现才构成更强的独立应用证据。概念理解、应用和保持分别记录，避免单一 mastered 布尔值掩盖差异。
5. **保留有边界的重教路径。**连续失败时换解释、定位先修缺口或记录待教师处理；不要无限重复同一道问答，也不要仅按轮数宣布掌握。
6. **单独设置验证任务。**教学中使用的题与课末独立测验区分；在后续约一周安排等价新题检查保持和应用。具体间隔与题量是试点参数，不是上述论文给出的普适最优值。

## 怎样验证是否帮助学生

建议先选少量有清楚目标、例题和评分标准的课时做试点，冻结内容版本和评估题，比较现流程与新流程。尽量平衡先前水平、学习时间和教师材料；条件允许时随机分组，避免把班级差异误判为流程收益。

主要观察：独立解释得分、无提示新题应用得分、延迟等价题表现。辅助观察：完成率、时间、提示依赖、退出点。教师或人工盲评一部分答案，检查模型评分的一致性、错误放行与错误拦截。没有实际对照和延迟结果之前，只能说方案具备研究依据，不能宣布已经提升掌握率。

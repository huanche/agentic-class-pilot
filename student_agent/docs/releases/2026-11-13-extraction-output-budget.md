# 长课程知识点整理的输出预算修复

41场景的C语言选择结构课整理时，三次工具参数输出均在8192 token处截断，finish_reason=length；对截断JSON要求结构修复仍受同一上限限制，最终失败。此前把max_tokens直接交给ChatOpenAI也无效：SDK将其改名为max_completion_tokens，而当前DeepSeek接口仍使用默认输出限额。

提取模型现在显式请求32768 token的输出上限。DeepSeek适配器通过extra_body传递其原生max_tokens，保留thinking关闭设置；其他兼容接口沿用SDK的标准参数。仅课前知识点整理的单次请求上限调整到120秒、总预算180秒，仍最多3次调用、无隐藏SDK重试。

课堂教学继续使用原工厂默认预算；没有改提问轮数、教学评估、知识点结构、原始材料或播放器。EXTRACTOR_HASH由既有提示词/结构版本计算，不因传输预算变化而改变，已完成的整理结果不批量重算。

回归通过真实ChatOpenAI/OpenAI SDK与MockTransport检查实际出站JSON：DeepSeek收到原生max_tokens而非被忽略的别名，42点工具提交完整通过；课堂模型不继承新的输出上限。原结构修复、最多调用次数及总截止时间测试继续保留。

真实模型验收使用生产同一份41场景材料，在独立进程中仅只读查询课程资料，不改学习记录。上线后按现有重试流程处理此前失败的当前课时，不清除历史学习数据或改写已绑定的课程版本。

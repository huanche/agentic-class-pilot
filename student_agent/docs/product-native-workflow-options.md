# 真实产品原生学习流程：作为学生端方案选择依据

日期：2026-10-26。根据用户要求，本文件按产品原生操作流程组织，不再把自行组合的教学活动命名为外部已有方案。证据为官网、官方帮助与带界面截图的操作文档；未登录产品实测。只讨论公开能确认的行为，不据功能说明断言学习收益。

固定项目条件：教师原版 PPT、生成的 HTML 课件；保留整段播放；播放后先用具体问题初步了解学生，再开展辅导。这一前缀是本项目要求，不是下面每个产品的原生流程。

## 1. StudyFetch：材料生成练习，依据表现回到材料与辅导

### 官方可确认的原生流程

上传课程材料（明确支持 PPT/PPTX），建立学习集，生成练习或进入 AI 辅导。[官方格式及学习工具说明](https://www.studyfetch.com/docs/docs/6a067a05f983a7215b738de1)

QuizFetch 的一次作答包含：作答或选“不知道” → 记录信心 → 显示反馈；可以从题目打开来源，聊天入口保持可用。[官方作答操作文档](https://www.studyfetch.com/docs/docs/6a6158da457ace81fcedf3ba)

连续错误较多时，系统暂停推进并建议先复习材料；统计页区分已正确、需练习和未回答。暂停或达到题目掌握条件后，会推荐 Tutor 等基于同份材料的工具。[官方测验结果与后续推荐](https://www.studyfetch.com/docs/docs/quizfetch/quizfetch-results-and-recommendations)

Guided Chat 是另一个有明确入口的模式：选择主题 → 接受或修改活动计划 → 逐项活动 → 总结；每项活动保存状态，完成后由学生决定继续。测验中辅导侧重提示。[官方 Guided Chat 操作文档](https://www.studyfetch.com/docs/docs/ai-chat/guided-chat)

### 与本项目的适配判断

最接近当前“以既有教师课件为起点”的输入条件。可以把整段播放后的检查、错误处的材料复习和 Tutor 入口作为主要参考。

公开资料没有证明“做完少量诊断题后必然自动生成弱点专属 Guided Chat 计划”；不能把测验推荐入口和计划模式合写成完全自动执行的既有功能。若我们要这种自动衔接，属于新增设计。

原生即时反馈/重复题规则与本项目前版建议“先收完诊断回答再辅导”有区别，反馈时点需要选择。其信心和重复答对定义的 mastery 也不能直接替代独立应用的证据。直接支持本项目 HTML 课件的方式仍待适配。

## 2. ALEKS：先独立诊断，再个性化学习，周期性确认

### 官方可确认的原生流程

初始 Knowledge Check → 个性化 Learning Path/ALEKS Pie → 学习主题 → 后续 Knowledge Check，循环更新学习路径。[官方学生流程概览](https://www.aleks.com/independent/account)

课程级初始检查通常约 20–30 题，会根据先前回答调整题目；检查时不即时告诉正误，允许选“不知道”。诊断用于确定已知、未知和准备好学习的主题。[官方 Knowledge Check 说明](https://www.mheducation.com/prek-12/support/knowledge/what-is-a-knowledge-check.html)

在学习模式中可看具体题目的分步解释，然后尝试新题；周期复查未保留的内容会重新进入待学路径。[官方学生 FAQ](https://www.mheducation.com/prek-12/support/knowledge/aleks-frequently-asked-questions-faq-for-students.html)

### 与本项目的适配判断

这是“先了解当前状态，再安排后续学习”的直接产品参照，评估与教学分离也有明确产品依据。

但它按特定课程和可学习主题组织，不是把任意 PPT 上传后直接实现完整诊断。官方课程检查的规模、题目生成和主题可学性判断，不能缩成几道课后题就声称具有相同诊断精度。借鉴其流程需要先建立可检查内容、题目和关联；不应承诺第一版复现其能力。

## 3. NotebookLM：材料自测、解释与来源回看

### 官方可确认的原生流程

添加来源 → 生成测验（可调主题/难度）→ 作答，按需提示/解释 → 查看结果 → 回顾或重做。官方同时提供闪卡，其错卡重练规则不应套用为所有测验都自动做弱点诊断。[官方测验与闪卡帮助](https://support.google.com/gemininotebook/answer/16958963?hl=en-GB)

解释可带回原材料的引用；Learning Guide 是另一个引导学生逐步思考的对话选项。[官方功能与操作示例](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-student-features/)

### 与本项目的适配判断

可作为最轻的“课后自测＋材料解释”参考，不要求教师额外提供题库。但上述资料没有展示“测验结束后系统自动建立完整个性化补救课程”，不能按 ALEKS 式诊断系统描述它。

适合优先完善出题、解释、引用和回顾；要达到用户希望的根据初步表现主动辅导，还需要我们另行设计活动衔接。

## 4. Khan Academy/Khanmigo：技能练习中的辅导和后续考查

官方支持内容学习、技能练习、当前题辅导以及后续测验/技能更新之间的关系，但不要求每名学生按一个固定视频后流程走完。其数学辅导可使用人工习题、步骤、提示、解答和校验工具。[官方数学辅导工程说明](https://blog.khanacademy.org/khanmigo-math-computation-and-tutoring-updates/)

因此它适合作为任务型辅导参照，直接复制需要补上可靠题目及判定体系。完整原生流程和证据见 [khan-workflow-reference.md](khan-workflow-reference.md)，不要把一次辅导后的表现检测描述成产品必然具有一个单独的“独立验证”页面。

## 5. 按项目条件比较

以下为基于公开能力的适配判断，不是产品效果排名。

| 外部参考 | 最值得参考的机制 | 当前输入适配 | 主要缺口 |
|---|---|---|---|
| StudyFetch | 从材料练习，错误较多先复习，提供后续辅导与活动入口 | 较接近 PPT 输入 | HTML 提取、初步检查与辅导自动衔接、可靠判定 |
| ALEKS | 初始诊断决定学习路径，复查可把内容重新列为待学 | 课程内容结构要求较高 | 主题与题目关联、可学性和诊断机制 |
| NotebookLM | 材料生成自测，解释能回到出处 | 适合材料型课后工具 | 主动规划、针对性辅导衔接没有足够公开原生证据 |
| Khan Academy/Khanmigo | 明确题目中的辅导、练习和独立考查 | 需要已组织好的课程和任务 | 从 PPT/HTML 形成可靠任务体系 |

## 6. 当前建议及理由

优先把 **StudyFetch 的材料型练习与后续辅导入口**作为第一版产品参照，因为它的输入假设最接近现状；把 **ALEKS 的诊断与学习分离、复查更新路径**作为诊断机制参照。这里的推荐是项目适配判断，不是证明其中某产品在理解与应用效果上优于其他产品。

最新决策：用户在质疑固定题组和表现分类后，同意尝试“整段视频后具体问题 → 按回答动态追问/补讲 → 记录证据 → 新问题观察独立表现”。具体适配以 [dialogue-tutoring-design.md](dialogue-tutoring-design.md) 为准，本文件保留外部原生流程参考。

补充控制权约束：用户明确要求程序运行预设主线，AI 只处理当前教学任务。外部产品的计划或调度功能不构成把本项目流程控制交给 LLM 的授权。

必须保留的边界：几道初步题只能提供局部证据；产品显示掌握不能自动当作迁移能力；公开帮助未说明的自动分流与调度算法均标为未知。

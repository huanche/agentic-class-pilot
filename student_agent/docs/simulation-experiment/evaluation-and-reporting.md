# 评估、证据数据与问题报告

配套[主方案](../student-simulation-experiment.md)与[学生设定](student-profiles.md)。状态：待实施规范；下面的字段和示例不是现有API新增字段，不是已运行结果。

## 1. 每个trial保留四种独立状态

不能用一个 pass/fail 同时代表工具运行、学生模拟、教学效果和产品缺陷。

| 字段 | 取值 | 含义 |
|---|---|---|
| executionStatus | completed / preparation_error / preparation_timeout / system_error / transport_ambiguous / harness_truncated / simulator_error / setup_error | 工具执行是否完整；completed不等于掌握或无缺陷 |
| simulationValidity | valid / invalid / uncertain / not_applicable | 学生是否遵守画像；UI纯恢复操作可不适用 |
| scenarioCoverage | reached / not_reached / not_applicable | G/U目标前置条件是否真正发生 |
| reviewStatus | ungraded / candidate / confirmed / rejected / needs_more_evidence / no_issue_found | 评估和人工复核状态，不覆盖原始轨迹 |

另存 endReason（system_wrapup、student_action、policy_exit、script_action、turn_cap、wall_clock_cap、cost_cap、request_error等）及 `systemPhaseAtStop`、`systemStageAtStop`、`feedbackAvailable`。到wrapup还没有调用end的情形不能等同反馈已保存；正常系统收尾、学生提前结束、外部工具截断分别计数。

单条轨迹可以“completed + valid + confirmed”：流程正常结束，但发生了错误掌握。也可以“harness_truncated + valid + candidate”：讨论持续未结束，但还需核查是否存在重复无效帮助。

## 2. 规则检查：只断言可观测事实

| ID | 检查 | 当前合同与判定边界 |
|---|---|---|
| R01 | 消息追加和归属 | 成功message新增本轮学生/导师消息，学生属请求前stage，导师属请求后stage；比较完整序号不只比较末条文本 |
| R02 | 复述计数与上限 | 在对应stage学生一次成功提交计一次；求助/不会也计数；模型失败后不应在内存提交本轮。数据库部分写入单列取证 |
| R03 | 掌握与下一点/阶段一致 | 当前代码首轮>5才掌握需要加强确认；不把确认本身判重复实现bug |
| R04 | 讨论结果与概念分离 | 讨论答错不应直接清掉概念已掌握；讨论未答对不应正常推进index |
| R05 | 排除项与任务队列 | 用内部队列验证排除标记；“新题暗含排除知识”交语义评估，不能靠词命中直接判定 |
| R06 | 退出与反馈 | /end可提前结束，done后反馈可读取；早退未触达点不能全判掌握；重复end不得新增课堂消息或改变已保存反馈 |
| R07 | 恢复与隔离 | sid/课时/用户别名/发布绑定、消息次序、计数和任务恢复一致；禁止跨trial混入；刷新和重启分别验证 |
| R08 | 课后与反馈更新 | phase=done合法；postclassStage/任务类型匹配；课堂原反馈保留，当前反馈只因相应证据更新 |
| R09 | 准备与内容版本 | pending不能当已准备；ready/partial绑定当前材料hash；抽取内容对应实际课时，不把partial默认为完整覆盖 |
| R10 | 工具完整性 | 没有盲目重发、预算超限、跳过未完成任务或隐藏无效模拟；工具异常归测试工具问题 |

所有规则输出 pass/fail/unknown/not_applicable、事件引用、预期合同和实际值。R02/R03等默认参数读取会话实际保存值，不能只用环境默认值8/4。缺失快照、状态或必要前置条件时输出unknown/N/A；不能因为没有观察到错误就判pass。

## 3. 独立AI评估维度及锚点

每个适用维度给0/1/2和具体证据：0=观察到明确问题；1=存在局部问题或证据混合；2=在本次已触发条件下表现合适。unknown/N/A独立取值，不能强行映射成1或2。不合成一个“教学质量总分”。

| ID | 维度 | 0分锚点 | 2分锚点 | 不足以判差的情形 |
|---|---|---|---|---|
| J01 | 回应求助 | 明确请解释，后续仍同义反问，没有解释/示范或必要澄清 | 回应具体不懂处，给适合当前缺口的解释/例子/可操作线索 | 先澄清学生究竟不懂哪个词 |
| J02 | 追问是否提供新价值 | 同点连续追问已回答关系，或只是反复“再想想” | 指明尚缺关系、换有效帮助或承认暂缓 | 原题没换但给了新的必要解释 |
| J03 | 判断与学生证据匹配 | 仅附和/照抄却升级掌握，或充分解释仍因措辞被拒 | 结合学生累计表达及帮助范围判断，不把AI解释计为学生回答 | 有提示后学生用自己的话解释，按当前合同可掌握 |
| J04 | 材料与任务范围 | 编造本课结论、错误讲解、考查未给足的课外前提 | 解释有出处、题干信息充分、范围清楚 | 有一般性补充且明确区分，并未当本课必答要求 |
| J05 | 难度、负担与收尾 | 持续困难仍重复要求完整复述，不解释可用路径 | 问题可回答、帮助随困难变化，结束时准确保留未完项 | 教学需要合理重复；按现合同做后期确认；学生自行提前结束 |
| J06 | 最终反馈可信度 | 与轨迹不符，掩盖未完成项，把受助/附和宣称独立会用 | 对应本次表达、帮助、概念/应用差异和未覆盖范围 | 反馈依据某错误业务评估生成：记传播链，根因先查评估 |

J05中的“负担”是依据交互轨迹的产品风险判断，不是AI测出了人的疲劳。当前反馈没有显式帮助等级，单纯缺字段先记可观测性/设计改进；只有文本作了与证据相反的断言，才报反馈错误。

### 3.1 两次隔离评估

第一遍给脱敏对话、课时人工标准和事件ID，不给版本臂名、业务掌握结论或问题假设。先判断学生实际表达覆盖、帮助和可能问题。

第二遍再给白名单状态差异、评估历史和反馈，比较系统判定与第一遍证据。两遍不能互相替学生作答。模拟有效性审计另行读取画像和账本，不把审计者的隐含知识猜测当作教学评估真值。

评估器优先使用与导师不同模型家族；可用资源限制时至少分离会话、提示和上下文，并在报告披露共享模型的偏差风险。针对所有高严重度候选、全部分歧及随机20%的“无问题”有效轨迹进行第二评估/人工复核，不只找另一个模型来附和第一判断。


## 4. 如何定义“耗在那里”

不能只统计总轮数。较长对话可能在有效学习，短对话也可能过早放弃。

- **一次求助事件**：学生明确表达不会或请求解释/例子。对同一未解决缺口连续重复请求合为一个episode，避免人为增加分母。
- **及时有效帮助**：后续导师针对该缺口给出解释、例子、示范、必要澄清或可操作的具体线索；仅“想想课上说了什么”不自动算有效帮助。
- **无进展候选区间**：同一内容单元/任务至少连续3次成功学生提交，无新增相关学生表达，且导师没有带来新的有效帮助或核实目的。先由规则定位窗口，再由裁判确认。长但持续补充理解的对话不命中。
- **重复考查候选**：此前学生已充分表达某关系，导师再次要求同一内容，且没有新的必要条件、澄清目的或代码明确的后期确认依据。若是现有固定确认导致负担，记设计风险而非实现错误。
- **任务停滞**：到外部上限仍未推进，单独记录可观测事实；只有结合重复无效帮助等证据才确认教学缺陷。固定“始终不会”脚本的停滞只说明鲁棒性边界。

3轮、下表的2轮响应窗口均为实验筛查阈值，C0后冻结，不宣称最佳教学策略。

## 5. 主要指标与分母

所有比例显示 n/N；N=0记N/A。A/G/U分开，按课时、画像、阶段分层；不把同会话的80轮当80个独立学生。

| 指标 | 定义 | 分母与排除 |
|---|---|---|
| 求助响应延迟 | 从求助学生消息到首次有效帮助，紧随回复为0，下一次导师回复为1 | 可审计的求助episode；结束/截断前未获帮助记右删失及未响应数，不填0 |
| 2轮内求助未响应率 | 当轮与下一次导师回复均无有效帮助 | 至少观察到这两次回复的有效episode；未观察足两次单列删失 |
| 无进展区间 | 经复核区间数量、最长长度、涉及trial比例 | 有效且相应区间可观测的trial；同时报告全部启动trial中的未知/截断数 |
| 错误掌握率 | 独立证据不支持但系统发生mastered通过的事件数 | 可观察的mastered通过事件：概念状态升级、加强确认通过、讨论结果通过分别计算；无通过事件时为N/A |
| 充分回答未获认可率 | 独立标准已满足当前任务，但系统未按现合同认可的判断事件 | 全部独立判为充分且状态可观察的判断事件；合理加强确认不算违例 |
| 无依据重复追问 | 经复核的重复事件数及涉及trial数 | 有充分先前表达且后续继续追问的可评估事件；同时报n/N与总数 |
| 完成/主动退出/截断 | 三类数量与阶段分布 | 所有计划启动与实际启动数分别列出；系统/工具错误不能排除后再称100%完成 |
| 反馈不一致率 | 至少有一条经复核不一致的反馈份数 | 已产生且证据充分的反馈；没拿到反馈另报，不当无问题 |
| 状态/恢复错误 | 规则违例数量、影响trial及路径 | 实际触发相应状态条件的trial；U04没重启则不能进入重启恢复分母 |
| 覆盖范围 | 人工内容单元已触及、可判、未触及数量 | 按课时包单元，partial和映射不确定分别列出，不等同掌握率 |
| 接口延迟 | 准备延迟、成功message延迟中位数及范围；样本够时显示p90/p95 | 成功与失败/超时分开，不能删去慢失败再称整体更快 |
| 成本 | 批次总成本、各角色成本、每启动/有效trial成本 | 包含准备、失败、无效、评估和复核；用量未知单列，不能从有效成本掩盖失败消耗 |

接口延迟不包含真人思考、阅读和打字。画像按预算退出产生的时间只反映设定政策。少量样本主要用于发现缺陷，给出计数和范围，不报告夸大精度的显著性或跨课程普遍效果。

## 6. 校准、人工复核和盲评

离线准备24条短轨迹锚点：J01～J06每类2条明确有问题、2条无问题；包括必要澄清、合理提示后解释、合理后期确认等反例。锚点由人工根据标准标注，来源可为C0摘录或明确标注为合成的对照，不能与正式结果混合。

建议校准门槛：裁判对24条的有/无问题判断至少20条与人工一致，其中12条明确无问题至少10条正确识别；引文和事件引用必须全部可定位。该门槛是可用性检查，不足以证明泛化准确率。未达门槛调整规则、裁判提示或模型并重新校准，保留失败版本。

正式复核队列包括：全部P0/P1候选、掌握误判候选、无效/不确定模拟、模型评估分歧，以及按画像/课时分层抽取至少20%的其余有效轨迹（向上取整，覆盖无问题项）。裁判等级与人工等级分开保留。人工无法核实的项目记needs_more_evidence，不为关闭队列强行确认。

抽样核查两名人工评估者可以提高一致性；如果只有一名，报告注明单人复核。统计复核接受率和误报例子，不把AI置信度当经校准概率。后续有真实学生时先用少量真实对话核对画像和缺陷，再安排学习效果试点。

事件至少包含：batchId、trialId、eventId、requestSeq、UTC时间、单调耗时、eventType、actor、messageId、taskRef、stageBefore/After、stateRef、sourceRefs、redactionVersion。按Asia/Shanghai显示人读日期，保留UTC原始时间。事件不存在的字段用null并注明不可观测，不补造AI内部推理。

状态白名单建议：phase、agentStage、postclassStage、preparation和coverage、flow/curriculum版本、current point别名、last_point_id别名、transition、strategy、各点计数/完成标记/概念结果/讨论结果、队列索引、新增assessment_history及反馈；真实sid/用户等在受限映射内。快照不是发送给模拟学生的上下文。源材料可能含学生姓名等，进入模型前同样脱敏。

数据生命周期建议：受限原始凭据/快照最多保留14天完成复核；脱敏可复现轨迹与报告保留90天，之后只留必要回归片段；具体按项目实际制度调整。日志不得打印cookie、Authorization、launch_token、服务密钥或原始browserSnapshot。报告共享前执行字段扫描与人工抽查。

## 8. 问题分类、严重度与去重

`issueType`建议枚举：help_ignored、unproductive_loop、false_mastery、false_rejection、redundant_probe、content_error、scope_violation、exit_or_restore、feedback_mismatch、state_integrity、content_preparation、observability_gap、simulator_invalid、harness_error。

每项再记录 `findingKind`：implementation_violation（现合同违例）、product_design_risk（按当前规则仍有体验问题）、content_limitation、test_tool_defect。不要用“程序要求继续”证明模型坏了，也不要用“程序照规则运行”否认产品问题。

| 严重度 | 例子 | 处理 |
|---|---|---|
| P0 | 确认跨用户数据混入、破坏记录等严重状态错误 | 停止受影响批次，保留证据，人工核查隔离配置与实现 |
| P1 | 错误判掌握、关键概念讲错、可复现阻断且无可用退出/恢复 | 首批修复候选，必须人工确认并定向复现 |
| P2 | 多轮无效追问、已会仍重复、帮助迟缓、误导性反馈 | 按影响范围、可复现性和修改成本排序 |
| P3 | 非阻断文案/呈现问题、可观测性不足 | 归入改进或测试能力建设，不冒充学习失败 |

同一缺陷按 `issueType + findingKind + 阶段/任务 + 证据模式 + 待核查机制` 聚类，不以相同措辞或同一标题机械合并。保留所有occurrence及课程/画像分布；一个10轮问题不能报成10个独立缺陷。不同根因不因为都“耗时长”而合成一个。

复现率报告 `确认复现数 / 有效且目标条件已触发的重复数`，另列未触发/无效/错误数。仅2/2也只能称“这2次复现”，不推断真实用户百分比。严重但只出现一次的案例保留，安排最多3次新trial定向复现，另列新增成本和版本，不覆盖首次结果。

## 10. 人可读问题单模板

```text
标题：[严重度][阶段/任务] 触发条件与实际问题
状态：候选/确认/否决/待证据；类别：现合同违例/设计风险/材料限制/工具问题
影响：哪些课时和画像，已确认的范围；未知或未覆盖范围
复现：基线版本、材料hash、画像/脚本/裁判版本、有效重复n/N
步骤：合法进入课程 → 必要setup → 具体学生表达/动作 → 查看何处
预期依据：当前代码合同/人工材料标准/明确标记的实验产品判据
实际证据：逐字短引文、messageId、请求前后状态和轨迹链接
反例核查：是否必要澄清、已有帮助、合理确认、模拟越界或测试截断
归因：已证实事实；尚待核查的提示词/状态规则/内容/界面因素
建议验证：最小改动候选和需保持的行为；本轮不实施修复
回归：什么输入/条件重跑，哪些状态与语义证据支持修复，哪些不能机械断言
复核：人工结论、姓名别名、日期、分歧与限制
```

输出问题单不自动发GitHub issue，不自动写入教师/学生账户或通知他人。报告是本地可审查产物；是否建立外部工单另按用户授权执行。

## 11. 总览报告结构与后续比较

summary.md依次展示：版本和范围、实际启动/有效/触发/完成/退出/截断/错误数量、经人工确认的问题及证据、各层指标n/N、正常案例、候选/分歧、未触发条件、成本、限制和下一步最小验证。

三臂比较先盲化为随机标签，裁判完成后再解盲；学生/裁判参数不随被测版本优化。对每个课时×画像簇报告问题计数、帮助延迟和完成类型，不能将同簇重复当完全独立大样本。目标问题减少但false_mastery增加时不能宣告改造成功；版本改动造成内容提取点变化也要报告，不能把少提了知识点产生的短对话称为更高效。

正式交付至少包含：90个正式计划trial的去向（包括未执行原因）、12个C0的单列结果、全部确认高严重度问题的证据和复现入口、无问题样本的抽检记录、明确标注的不可观测项和未测试功能。若受预算提前停止，只报告实际覆盖范围，不声称完成全部实验。

# 学习产品比较：整段课堂播放之后可以怎样做

调研日期：2026-10-26。范围：NotebookLM、StudyFetch、Quizlet、Khanmigo 的公开官方说明；未登录实测。项目约束以用户确认为准：稳定输入是教师原版 PPT 与生成的 HTML 课件，保留整段播放，讨论播放后的学习流程。教学目标、知识点文件、题库和评分标准不能视为必有输入。

## 1. NotebookLM：从材料到自测，再带着问题回材料

**官方已说明的用户流程：**

1. 建立 notebook，添加来源。当前帮助列出 PPTX、PDF、文字、Google Slides 等；网页导入只抓 HTML 文字，不导入图片、嵌入视频或下级网页。[来源类型官方帮助](https://support.google.com/gemininotebook/answer/16215270?hl=en)
2. 在 Studio 生成测验或闪卡，可以调整难度、数量与关注主题；题目有提示，答案可要求解释；结束后查看结果、回顾或重做，闪卡可只重练答错的卡。[测验与闪卡官方帮助](https://support.google.com/gemininotebook/answer/16958963?hl=en-GB)
3. 点击解释后，获得解说及回到原材料的引用；另有 Learning Guide 对话模式，用开放问题、分步拆解引导理解。[官方功能发布说明](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-student-features/)

**对本项目的适配判断（设计推断）：**

- 可以借鉴“看完 → 少量自测 → 看解释/出处 → 追问 → 再练”的短闭环，不需要教师先提供完整题库。
- 引用最好定位到 PPT 页或 HTML 场景，让学生明确回看哪部分；网页抓取的限制提示我们需要自行提取和校验图表、公式与动态课件内容，不能把 HTML 文字等同于完整课件。
- 题目主题可从课件提出候选，但这只是系统对材料的推断，不能包装成教师明确规定的课程目标。

**没有从上述材料确认的内容：**没有确认其自测成绩怎样证明新情境迁移、开放回答评分是否可靠，或测验是否自动驱动完整补救课程。公开功能说明不能作为学习效果证明。

## 2. StudyFetch：将材料、题目与辅导组织成可跟踪活动

**官方已说明的用户流程：**

1. 上传课程材料形成 study set。官方 FAQ 明确支持 PPT/PPTX，材料可用于 AI 对话、闪卡和练习测试，不要求教师先交付配套题库。[官方 FAQ](https://www.studyfetch.com/docs/docs/6a067a05f983a7215b738de1)
2. QuizFetch 先作答（包括简答和“我不知道”），再评定信心，随后看答案反馈；正确率与信心共同影响题目再次出现的安排。页面保留聊天求助，题目来源编号可打开材料出处。[官方测验操作说明](https://www.studyfetch.com/docs/docs/6a6158da457ace81fcedf3ba)
3. Guided Chat 让学生选择主题、接受或修改短计划，再逐项进入材料、闪卡、测验等活动；保存当前步骤及完成/跳过状态。每步结束由学生决定继续。测验期间辅导偏向提示与概念指导，结束后总结并建议下一步。[官方 Guided Chat 说明](https://www.studyfetch.com/docs/docs/ai-chat/guided-chat)

**对本项目的适配判断（设计推断）：**

- 值得借鉴的是“有明确活动与下一步的学习会话”，不必复制整套闪卡、音频、游戏工具。播放后可以只有理解检查、针对性辅导、独立练习三类活动。
- 学生信心可用于识别“答对但不确定”和“答错却确信”，作为选择后续追问的辅助信号。
- 应记录活动、作答与帮助程度，聊天作为贯穿活动的辅导入口。学生能查看当前目标和剩余步骤，也能结束或跳过。
- PPT 可作为基础来源；官方列出的格式未确认直接支持我们生成的 HTML。我们需要自己的 HTML 内容提取、场景定位和版本绑定，不能假设上传网页就能完整理解课件。

**没有从上述材料确认的内容：**内部调度算法、开放回答评分一致性、独立迁移能力的验证方法均未公开充分细节。其“掌握”标签描述的是产品规则，不等同于已证明学生具备迁移能力。官网自报成绩改善比例不在本次结论中采信。

## 3. 对播放后流程的讨论建议

以下属于本项目建议，不能当成上述产品的已验证效果：

```text
整段播放（保留）
  → 简短理解检查：解释/辨别/小应用，附“我不知道”
  → 针对困难：追问、提示、例子、打开课件出处
  → 一个减少帮助的新问题：检查能否独立完成
  → 本次反馈：独立完成 / 提示后完成 / 仍待练习 / 未验证
```

两款产品都支持“从已有材料开始”，因此第一版不必等待教师端增加多套强制产物。真正需要新增的是学生端的材料整理和题目质量检查：出题依据是否存在、是否超出讲授范围、评分要点是否能被原材料支持。图片、公式或讲解信息缺失时，应限制题型或要求补充材料。

用户已选择播放后先来一组具体问题，再根据回答辅导。自由提问始终保留，题量与辅导细节再通过真实课时讨论和试用确定。不要把闪卡重复正确、信心高或一次 AI 判对直接转换成“已掌握理解与应用”。

## 4. Quizlet：根据练习表现调整复习范围

官方 Learn 说明提供逐渐增加难度的题目和个性化学习顺序；学习路径可以从已有 set 开始。[官方学习模式说明](https://help.quizlet.com/hc/en-ca/articles/360030841732-Studying-on-Quizlet)、[学习路径设置](https://help.quizlet.com/hc/en-au/articles/360048314692-Setting-up-a-study-path)

Progress 根据作答正误把内容分组，学生可选择尚未学、仍在学或已掌握的组继续练习。[官方 Progress 操作说明](https://help.quizlet.com/hc/en-ca/articles/360048803491-Using-Progress-for-targeted-studying)

本项目可借鉴“根据表现安排下一项”和“集中处理困难部分”，但不能把术语熟悉度直接当作情境应用能力。题型与目标要适配学科，不必把每页 PPT 都转换成记忆卡。官方智能评分的宽松模式还存在语言限制，不应假定其中文能力与我们的开放回答要求等价。[官方评分选项说明](https://help.quizlet.com/hc/en-ca/articles/360048313652-Using-smart-grading)

## 5. Khanmigo：题目驱动的辅导，以及辅导后独立表现

官方示例展示先询问学生识别到的信息，再逐步指导解决当前题目。[官方辅导示例](https://blog.khanacademy.org/khanmigo-can-ai-help-you-solve-the-most-missed-math-problem-kl/)

2026 年官方产品测试报告使用“下一题正确率”：接受辅导后，下一道同技能题没有 Khanmigo 帮助时是否答对；同时看响应延迟、认知参与和答案泄露等指标。报告称近期练习表现和先修缺口等结构化历史有帮助，但增加某些题型示例或推荐链接未改善该指标。[官方测试报告](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)

适配推断：对我们最实用的是“有明确题目与卡点的辅导 → 新题独立尝试”，以及保存近期实际表现，不只传整段聊天。官方测试结果不能原样迁移到本项目；下一道同技能题主要提供即时、较近迁移的证据，不能替代长期保持与跨领域应用验证。Khan Academy 已有课程与题目体系，我们从 PPT/HTML 自动准备任务的质量仍需额外检查。

## 6. 四种做法怎样组合

| 产品 | 本次可借鉴的重点 | 本项目需要补的能力 |
|---|---|---|
| NotebookLM | 材料自测、解释与出处关联 | PPT/HTML 内容提取、场景/页码定位 |
| StudyFetch | 活动有进度，辅导贯穿活动，学生可调整节奏 | 持久化活动与任务，保留跳过和未完成状态 |
| Quizlet | 将后续练习集中于困难部分 | 内容覆盖记录、正误及帮助程度摘要 |
| Khanmigo | 围绕实际问题提供帮助，再检查下一题独立表现 | 可靠任务与判定依据、辅导/验证分离 |

上表是设计推断，不是产品完整评测，也不是学习效果排名。

## 7. 三个版本的比较记录（用户已选 B）

### A. 复述优先

整段播放 → 学生概括关键内容 → AI 澄清与追问 → 一个新情境 → 反馈。

接近当前产品，交互自然、便于观察表达。缺点是长文本负担和重复感，学生未主动说出的内容不容易区分为遗漏、不会或表达困难。

### B. 短任务优先（当前优先建议试用）

整段播放 → 少量代表性任务（解释/辨析/简单应用）→ 仅处理出现的困难 → 新任务独立尝试 → 反馈。

任务可以以对话方式呈现，不必做成考试页。学生能选择“我不知道/给提示/看课件/先提问”。任务后按证据继续，不要求所有知识点走同样轮数。代表题只能支持局部结论，不能由少量题宣布整课掌握。

### C. 案例优先

整段播放 → 一个实际情境或案例 → 学生作出选择并解释 → 卡点辅导 → 更换情境 → 反馈。

与理解和应用目标接近，适合内容中已具备案例、原理或方法的课时。缺点是生成难度、难度控制和评分歧义较大；纯概念导入课也不一定适用。

主路径已选 B，A/C 可用作其中的任务与辅导形式。下一步可用同一个真实课时演示“不同初步回答 → 不同辅导”，再收敛细则。不要同时默认叠加复述、全量题组、案例、长讨论等全部活动。短检查中的学生信心只辅助判断是否需要追问，不直接决定掌握。

## 8. PPT 与 HTML 的最低输入处理

当前学生端主链只消费场景文字与可获得的旁白。新版若使用原 PPT，需要由平台提供解析、页码和图示/公式信息，不是声明输入可用就已实现读取。

以课堂实际呈现内容界定本次检查范围，原 PPT 用于核对与补充解释；原 PPT 中未呈现的知识不直接作为必答内容。若原 PPT 与 HTML 有冲突，保留冲突并暂停相关确定性评价。所有系统生成任务保留出处，材料不足时减少题目或转解释，不补造教师未讲内容。

补充源码核查：部分课件生成与归档路径会调用 `ensureLessonReviewFiles` 自动补建目标/知识点草稿；新文件为 draft。它们存在于某些路径不等于必然发布给学生，所以仍不列为基线。该事实不改变用户确认的 PPT+HTML 约束。

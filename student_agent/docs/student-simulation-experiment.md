日期：2026-10-27。版本：v1.0，待实施的实验设计。

## 1. 实验要回答什么

首先发现并复现当前系统的问题：哪些学生表达会导致无进展追问、求助未被回应、掌握误判、重复考查、讨论停滞、退出或恢复异常、反馈与对话不一致。随后依据证据决定修改提示词、程序规则、界面还是内容准备。

本轮结果可以说明“在这些课程和模拟条件下出现了什么”，不能推断真实学生发生率、真实学习增益或长期掌握。模拟学生最终答对，只是模拟轨迹的表现，不能证明系统教会了真实学生。来自真实反馈的案例应优先进入用例库；数据可用时先脱敏，不以额外采集真人数据为本次设计前置条件。

可检验的初始假设：

| ID | 假设 | 需要的证据及反例 |
|---|---|---|
| H01 | 明确不会时，初始复述过多使用低信息提示 | 同点求助事件、后续教学动作、学生新增理解；若及时解释且产生新表达则不支持 |
| H02 | 附和或复制答案会被错误标为掌握 | 学生原话、此前 AI 答案、当前点状态变化及独立评估，排除学生先前已说清的情形 |
| H03 | 正确但口语化的回答会被反复追问 | 课时标准、学生累计回答和追问缺口；必要关系仍未说出不是重复考查 |
| H04 | 讨论或课后任务持续困难时缺少自然收尾 | 目标阶段真实到达、连续交互、可用退出操作；有退出按钮不代表导师自然收尾良好 |
| H05 | 请求前后阶段变化会导致反馈或历史归属错误 | 请求前后状态、消息阶段和 assessment_history；正常阶段切换不能误报 |
| H06 | 刷新、重启、提前结束后继续，会丢失或重复学习任务 | 相同会话恢复前后、当前题、次数、反馈；需区分刷新和真正服务重启 |

假设未命中也要报告。不得为了证明初始复述有问题，要求模拟学生永远拒绝学习，然后把所有长对话判成教学失败。

## 3. 实验结构与职责

```text
版本固定的课时材料 + 学生画像 + 场景脚本 + 批次清单
                         ↓
                  调度器 / 身份隔离
                         ↓
            学生模拟器 → 真实学生 API → 当前导师工作流
                  ↑            ↓
           学生可见历史     状态观察与事件记录
                               ↓
                  规则检查 + 独立 AI 评估
                               ↓
                    人工复核 → 问题库/回归集
```

这是测试工具的职责划分，不要求增加业务 Agent。多个学生是独立测试会话，不共享学习记忆；并发运行不意味着它们在系统里相互协作。

| 角色 | 允许输入 | 不允许或不负责 |
|---|---|---|
| 调度器 | 批次、预算、账号引用、运行状态 | 不替系统回答、不因评估不佳而偷偷重跑 |
| 学生模拟器 | 画像片段、本人可见对话、受控知识状态、界面可用操作 | 不接收后台状态、标准答案、缺陷假设和评分标准 |
| 知识状态更新器 | 先前状态、最新导师可见说明、课时核对依据 | 不把“模型原来知道”当作本轮学会，不按轮数自动升级 |
| 观察器 | 请求响应、受限测试快照、数据库事件 | 不把完整后台内容转发给学生，不改变业务状态 |
| 独立评估器 | 脱敏全程对话、材料标准、结构化事件 | 不给学生提示、不操作导师流程、不把系统 verdict 当真值 |
| 人工复核者 | 带来源的证据包、候选问题、评分分歧 | 不只看总分，不把模拟率当真人发生率 |

## 4. 课程材料和学生设定

选2节已发布、文本依据足够的真实课时：L-A 以概念和关系为主，L-B 包含步骤、条件或小应用。优先选择已出现用户反馈的课时。每节建议约3～5个适合独立检查的内容单元；这是选样建议，不人为改业务提取点数。实际课时和账号尚未在本轮选定，样例清单保留 null，运行前必须补齐。

每课由一次人工核对形成实验专用材料包：

- 课程、课时、发布与课堂ID，以及实际场景文字/旁白的 hash、原始版本和顺序。
- 允许检查的核心关系、必要条件、常见误解、可接受口语解释及其原文出处。
- 导入/未讲内容清单；图示或公式无法提取等覆盖限制。
- 六类学生各自的初始知识片段和错误理解，所有片段关联来源。
- 供评估者使用的参考解释和必要要点，与学生输入分离。

内容包不能直接照抄当前 Agent 提取结果作为唯一真值，否则无法发现提取过细、遗漏、重复或误提导入。真实提取结果每次保留，并映射到人工内容单元；映射不确定记 unknown，不按标题强行一一对应。材料不足的课时可改列“材料限制”专项，不能用常识补齐评分标准。

初始画像定义为“看完视频后的理解状态”，不是课前基础、不是对视频学习效果的评估。六类画像的输入、可变化范围、示例和有效性检查见[配套设定](simulation-experiment/student-profiles.md)。

## 5. 批次数量与执行顺序

先校准工具，再保存当前版本基线。下表数量是计划启动的 trial 数，不是保证有效完成的数量。

| 批次 | 组合 | 计划数 | 作用 |
|---|---|---:|---|
| C0 校准 | 2课 × 6画像 × 1次 | 12 | 检查学生是否串知识、评估是否有依据；不并入正式比率 |
| A 基线自由对话 | 2课 × 6画像 × 5次 | 60 | 发现不同表达下的教学与流程问题 |
| G 固定场景 | 2课 × 6脚本 × 2次 | 24 | 可重复触发求助、复读、跳过、讨论、课后和长历史条件 |
| U 浏览器检查 | 6项各1次，分配到两课 | 6 | 验证实际界面与恢复路径 |
| 合计 | 校准12 + 正式90 | 102 | 不含未决问题定向复核和未来版本对照 |

每个重复有独立 trialId、账号/会话、随机标识和输出目录。模型支持 seed 时记录 seed；不支持则记 unsupported。即使设置相同 seed，也不宣称网络模型完全可复现。

先串行运行 C0；校准通过后按画像和课时打散 A/G 执行次序。API 初始并发为2，限流或错误升高时降到1，不为“凑满批次”不断重试。U 串行、独立浏览器 context。并发压测另设专项，不能把模型供应商拥塞混成教学问题。

六个固定脚本为 G01 明确不会并求讲解、G02 仅附和/复读、G03 暂缓与明确结束、G04 讨论持续困难、G05 课后任务与反馈、G06 累积回答与历史窗口。触发前置条件、预期证据和非失败情形见[脚本表](simulation-experiment/student-profiles.md)。

## 6. 如何批量调用当前系统

### 6.1 环境与前置条件

后续实现独立工具，建议放在 `student_agent/evals/simulation/`，本轮不创建该代码目录。使用隔离的 platform/student 服务和测试数据库，保留当前业务逻辑及默认轮数。教师内容可导入隔离环境，播放器地址应确实可访问；不在运行时修改已发布材料。

为每个独立 trial 分配独立测试学生身份与选课关系。至少保证 `(user, course, publication, lesson)` 不和别的并行 trial 或既往学习历史共用；同一 trial 的刷新、课后、重启恢复沿用身份。即使 fresh=1，跨会话 mastery 表仍会写入，不能共用账号后再用最高星级判断本次表现。账号准备属于测试 fixture，不修改教学业务。

运行前 validate 必须确认：隔离实例与数据库目标、测试账号和选课、发布与播放器、服务健康、模型配置、材料 hash、学生/评估提示版本、价格或用量计量可用性。不能打印配置里的密钥。无论机器能否启动，当前只有演示摘要的 demo 模式不满足真实课时主实验条件。

### 6.2 当前接口合同

student base URL 为目标服务根地址；平台 API 另用 platform base URL。路径均为当前真实接口，返回字段以实际响应为准。

| 顺序 | 方法与路径 | 输入 | 检查与记录 |
|---|---|---|---|
| 0 | 平台 `POST /api/v1/courses/{course_id}/student-workspace` | 已登录测试身份 | 取得 launchToken；认证状态单独保存于受限内存/凭据存储 |
| 1 | `POST /api/session/start` | `{launch_token}` | 返回目录和 sessionId，保存状态 |
| 2 | `POST /api/session/{sid}/begin/{lesson_id}` | 无 body | 绑定实际返回的 sessionId，确认课时和 video；begin 可能恢复既有会话 |
| 3 | `GET /api/session/{sid}` | 无 | 每2秒轮询 pending，最长180秒，记准备延迟与覆盖情况 |
| 4 | `POST /api/session/{sid}/discussion` | 无 body | 必须确认 phase=discussion，不能把仍为 pending/video 当作成功进入 |
| 5 | `POST /api/session/{sid}/message` | `{text}`，1～2000字符 | 同 sid 串行；保存请求前后状态及新增消息 |
| 6 | `POST /api/session/{sid}/end` | 无 body | wrapup 后明确调用；或学生主动选择结束时调用，保留提前结束证据 |
| 7 | `GET /api/session/{sid}/feedback` | 无 | 返回反馈本体，不是完整 state；结束前409是合同内行为 |
| 8，按场景 | `POST /api/session/{sid}/postclass/start`、`.../postclass/message` | 后者 `{text}` | 后端 phase=done，使用 postclassStage 和任务类型 |
| 9，按场景 | `POST /api/session/browser-restore` | `{snapshot, launch_token}` | 只使用服务返回的合法原始快照；不伪造或编辑签名内容 |
| 10，按场景 | `POST /api/session/{sid}/playback` | `{launch_token}` | 刷新回看授权，核对内容绑定和历史不变 |

准备 error 记为 system_preparation_error；partial 可以继续，但独立标记并记录未覆盖内容。主 A 批次不自动重试准备；另开恢复场景可调用 `POST .../prepare` 一次。显式重试前后的结果分别保留，不能用成功覆盖首次失败。

### 6.3 单个 trial 的循环

1. 校验清单并创建 trial/受限身份绑定，取得新会话，保存准备过程和实际提取点。
2. 将 opening 等学生可见消息传给模拟器；不传原始 state/课程全文/评估结果。
3. 校验模拟器输出的动作枚举、文本长度和画像约束；非法输出记 simulator_error，不提交给系统。
4. message 动作按当前课堂或课后接口提交；end_lesson 是独立动作，仅在合法课堂状态映射到 /end；浏览器模式必须点击真实按钮。
5. 记录导师回复、结构化评估和状态差异；基于可见教学内容更新模拟知识状态，下一轮再生成学生表达。
6. 达到 wrapup 后执行 end，并标注 `endInitiator=system_wrapup`；学生主动退出标注 `student_action`。正常得到课堂反馈后，A 批次结束；G/U 若指定课后则继续附加阶段。
7. 到预算、轮数或时限时停止生成，保存截止证据，标记 harness_truncated。主实验不为了拿反馈而自动调用 /end；如需采集截断反馈，另记 cleanup 动作与独立产物，不能改写截断前结果。
8. 运行画像有效性审计、规则检查、独立评估；把候选问题提交人工复核。

不要因为“连续3轮没进展”就由运行器替系统换知识点；该条件用于标记风险，继续观察到正常结束或外部上限。否则测到的是工具的补救能力。

## 7. 状态观察、失败与预算

### 7.1 不改业务代码怎样取证

默认 fresh=1 时，state() 已返回 browserSnapshot。测试观察器在本地从服务响应的快照中解码 JSON，提取 dialogue、评估历史、当前点计数等白名单字段；解码不是签名验证，不接受任意第三方快照作为可信证据。恢复时原始签名快照按原样发送。解析失败记 observation_unavailable，不向快照补造字段。

原始快照含身份、上下文、全部消息，有恢复能力，只放受限目录，不能发给学生模型、通用报告或提交 Git。外部评估输入只含脱敏材料、随机身份别名和必要状态字段。若 fresh 关闭，使用测试数据库 `student.learning_events` 的 `agent_state` 及 `student_messages`、`student_sessions` 作为只读观察通道；不要为本实验增设管理 API。数据库事件按 session、消息序号和 payload.version 关联，不能只按 eventId 字典序取“最新”。

每轮保存 stateBefore 和 stateAfter。学生消息的 phase 是请求前 stage，助手 phase 可能为推进后 stage。用 requestSeq、last_point_id 和新增 assessment_history 定位被评估点；不能把助手的新阶段归到学生旧回答上。没有内部状态时可做对话行为评估，但掌握误判/计数断言标为不可观测，不能判通过。

### 7.2 运行上限与失败处理

| 参数 | 初始值 | 含义 |
|---|---:|---|
| A/G 每 trial 已提交学生消息上限 | 80 | 包括场景 setup、课堂与课后；GET/结束不算学生消息，不是业务轮数 |
| 每 trial 总墙钟上限 | 30分钟 | 包含准备、接口等待和模拟器调用；不模拟整段视频时长 |
| 准备轮询上限 | 180秒 | 超限记 preparation_timeout，阶段未进入则教学项 N/A |
| HTTP 读超时 | 210秒 | 当前每个模型请求45秒且允许一次重试，正常轮有2个串行模型调用；此值是外部预算，不保证所有请求在内完成 |
| HTTP 连接超时 | 10秒 | 独立记录网络不可达 |
| 同一 trial 同时在途写请求 | 1 | 不对同一会话并发发言 |
| 运行器自动重发 message/end | 0 | 当前无请求幂等键，超时后不能盲目重放 |
| A/G 同时运行 trial | 2 | C0/U 并发1，按供应商限流降低 |

GET 可做最多2次退避重试，保留所有尝试。写请求超时或503后先 GET 对账：以请求前消息数/序号和本次新增消息核对，不仅比较文本。确认已提交则接收该轮；无法确认、仍在执行或记录部分写入时标记 transport_ambiguous/partial_commit，停止该 trial，不自动再次发送。同 session 的 GET 也可能等待锁，不无限对账；一次对账仍超时就保留不确定结果。

若需验证“失败后人工重试”，单列 U05，必须先确认第一次没有提交及后台已结束；这不能作为所有正常 trial 的通用重试策略。当前数据库多个写步骤不全部处于同一整轮事务，需同时留意数据库与响应状态，不能假定503意味着完全没写入。

每次模型调用前校验剩余费用、调用数和时间；本轮方案不预设人民币金额，清单的费用上限 null 会阻止运行。实施时填实际预算和供应商价格日期，覆盖导师、知识准备/修复、模拟器、知识更新、审计、评估和复核；并发在途调用的最大费用也要预留。

当前 _completion 只返回文本，不能直接从业务 HTTP 取得精确 token usage。用供应商用量账单/可归属到该隔离批次的用量数据计量；若需实时硬费用限额，可使用经过验证的测试模型代理做计量，另做等价性冒烟，不改导师内容。没有可靠用量时用保守 token 上界和调用数预算阻止超支，费用列 estimated/unknown，不能填0或声称精确硬费用保证。

普通学生消息通常含2次导师调用，最后讨论反馈路径等例外另计。仅 A/G 的学生消息理论上限是84×80=6720轮，普通路径约13440次导师调用，尚未计模拟器、更新器、知识准备和评估。因此应先用 C0 的实际用量给正式批次定预算；80轮上限不是预计每个 trial 都跑满。

## 8. 六个浏览器检查

现有 Playwright 配置入口为 `frontend/playwright.config.mjs`。后续新增单独实验配置，沿用选择器习惯，不替换现有 mock 回归。浏览器自动化可以运行真实对话；评估不能只凭截图，需关联网络与状态。

| ID | 场景 | 必须保存的证据 |
|---|---|---|
| U01 | 平台进入→播放→讨论→正常结束 | 实际课程/播放器、学生可见开场、加载状态、反馈与接口状态 |
| U02 | 学生主动点击提前结束 | 退出前回答、真实点击事件、done/endedEarly、未评估与未完成项 |
| U03 | 当前课时刷新继续 | 相同 browser context 的 localStorage、刷新前后当前点/次数/消息，避免重复 opening |
| U04 | 服务重启后浏览器恢复 | 独占隔离实例确实重启，恢复合法快照、身份和课程；仅调用 browser-restore 不算重启测试 |
| U05 | 可控模型失败后的恢复 | 独立故障注入环境、失败发生位置、输入保留与错误提示、已确认未提交后人工重试；不用自然随机错误代替可控场景 |
| U06 | 提前结束→课后继续→回看→再进入 | 原课堂反馈与当前反馈、课后任务、回看绑定、消息/次数保持 |

U01 保留整段播放链路；API 批次从假定“已观看后的学生状态”进入，不能声称它验证了学生看视频的行为或视频学习效果。U04 有其他 trial 时不得重启共享实例；单独时段执行。U05 若缺少可控测试代理，记未执行及依赖，不用修改业务函数或偷偷 mock 全部导师来宣称真实 E2E。

## 9. 评估、复核与问题输出

完整规则见[评估与报告](simulation-experiment/evaluation-and-reporting.md)。核心是三条独立结论：

1. 模拟器是否遵守画像和信息边界；无效模拟仍保存，但不用于相应教学指标。
2. 系统是否遵守现有代码/接口合同；实现违例可以由状态证据支持。
3. 即使遵守当前合同，教学互动是否存在可改进之处；例如必须答对才推进，属于产品设计风险，不能自动贴实现 bug。

规则检查覆盖计数、阶段、消息、数据隔离、退出与反馈一致性；独立 AI 按具体证据评估帮助、重复、误判和内容范围，允许 unknown/不适用。人工复核全部高严重度候选、评估分歧、模拟无效和一部分无问题轨迹。

报告输出：总览、按画像/课时/阶段的指标、每 trial 轨迹、候选问题 JSONL、已复核问题 Markdown、复现清单和回归候选。所有发生率带分母与有效性条件；固定脚本、自由对话和 UI 分开汇总。没有确认问题也要显示未触发场景、截断、不可观测和样本限制。

## 10. 基线之后怎样判断改哪里

先保存原始基线和人工复核后的问题，不立即“让另一个 AI 自动改系统”。定位时保留如下证据：导师已知材料、评估结果、程序策略、最终措辞和学生表现。

| 证据模式 | 优先检查位置，仍需人工核查 |
|---|---|
| 程序允许解释，导师却忽略求助 | 提示词、输入上下文和生成质量 |
| 程序要求继续同点、禁止提前切换 | progression/任务合同/退出分支 |
| 评估与独立证据不符 | EVALUATION_PROMPT、上下文窗口、判据和模型能力 |
| 提取把导入当知识或必要解释缺失 | context/knowledge/源内容 |
| 后端能结束但学生看不到入口或等待无提示 | 前端交互和状态呈现 |
| 反馈正确复用了一个错误评估 | 先修评估或证据记录，不只改反馈文案 |

后续改造获准后做三臂比较：B0 当前版、B1 仅提示词改动、B2 流程与提示词改动。固定课程内容包、画像、模拟器/评估器版本、起始条件、预算，随机交错运行。A 主矩阵每臂60个，共180个新 trial；旧 B0 仅在供应商/时间/配置可比时复用，否则重跑。G/U 做对应回归，成本另算。

多轮自由对话允许分叉，不把旧学生台词硬塞给新导师；固定脚本只固定行为条件，引用 AI 原话等动作根据新轨迹生成。同一课时/画像重复是一个小簇，不能把所有轮当独立学生，用几条短对话宣布显著改善。

成功判据：经复核的目标问题减少，同时错误掌握、内容错误、未完成项丢失没有增加；轮数或费用下降只能作为辅助指标。提前结束和截断必须保留，不能以更早退出制造更好完成率。模拟器新题答对不能作为真实学习增益。

## 11. 后续实施拆分及交付验收

本轮的“完成”是设计交付，下面是未来测试工具的实现顺序，不表示已实现：

| 次序 | 建议模块/能力 | 验收 |
|---|---|---|
| 1 | manifest validator、材料包和账号映射 | null/未核对来源/生产目标/预算缺失拒绝启动，dry-run不调用模型或写学习记录 |
| 2 | API driver、snapshot observer、trace writer | 单 trial 走真实链路，阶段前后归属正确、无盲目重试、隐私字段不外发 |
| 3 | student policy、knowledge ledger、script engine | 六画像/六脚本可独立运行，模拟不合规能识别而非冒充系统问题 |
| 4 | rule graders、AI graders、review queue | 有锚点案例、可引用原话、unknown与否定案例、分母正确 |
| 5 | scheduler、budget limiter、report builder | 中断后只恢复未开始项；在途不确定项不重发；报告可追溯 |
| 6 | browser driver、受控故障与重启 | 六场景各有网络/状态证据；未达前置条件不判通过 |

建议未来工具命令职责为 validate、dry-run、calibrate、run、grade、report、reproduce；目前没有这些可执行命令，本方案不提供伪装成现成脚本的启动命令。运行结果写入独立输出目录，例如 `student_agent/eval-runs/{batchId}/`，受限原始产物默认不入 Git；忽略规则在工具实施阶段补充。

开始正式批次前：补齐2节真实课时和来源、独立测试身份、模型部署标识、数值预算、有效性审计与评估校准。C0 未通过先修模拟器或评估器，不能先改被测业务让它“通过校准”。执行中任何变更生成新 manifest hash；原失败和无效记录不得删除。

## 12. 方法依据及使用范围

- [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)，2026-01-09：多轮试验、重复运行、区分 transcript 与实际 outcome、组合不同 grader。用于实验结构，不提供本项目教学有效性的证明。
- [Scarlatos 等：Simulated Students in Tutoring Dialogues: Substance or Illusion?](https://arxiv.org/abs/2601.04025)，2026-05-05 修订版：在真实数学辅导数据上分析模拟质量，指出提示词模拟的局限。用于要求模拟有效性审计，不据此断言任何单一模型能代表本项目学生。

所有阈值及批次数量均由本方案提出，不能归因于上述研究给出的标准。

# 播放后初步检查与自适应辅导：细化讨论稿

日期：2026-10-26。对应主方案 v0.5。本文用于共同讨论，尚未实施代码。

最新状态：固定4题结构与表现分类受到用户质疑，当前不按该结构进入实现。用户同意尝试动态对话方向，当前细化见 [dialogue-tutoring-design.md](dialogue-tutoring-design.md)。本文仅保留此前推演，不作为现行题型/阶段要求。

## 1. 已确认与建议参数

已确认：输入为教师原版 PPT 和生成 HTML；保留整段播放；视频后先用几道简单题了解当前表现，再由大模型据此安排辅导；题型为选择/判断为主，配一道简答。

建议的首版参数：一组 4 题（3 道选择/判断＋1 道简答）；各题覆盖核心内容，避免细枝末节和长篇表达。4 题是产品起点，不是研究证明的最优数量，课时较短或可检查内容不足时可减少。反馈时点、帮助轮次和时长上限仍待讨论。

```text
PPT + HTML/讲解内容
  → 材料整理和可检查内容
  → 出题蓝图 → 候选题及判定依据 → 质量校验 → 固定题组
  → 整段播放后收集首次回答
  → 逐题表现 → 按理解点汇总 → 初步整体概况
  → 大模型提出辅导安排 → 系统校验 → 执行当前活动
  → 新表现更新证据 → 独立尝试/补充教学/暂缓/结束
```

## 2. 题目怎样生成

### 2.1 先整理内容，再生成题目

当前 `backend/content/context.py` 已提取场景文字与可获得的 speech；`backend/content/knowledge.py` 已检查模型引用能否在原文定位。继续保留这些能力，但本设计还需增加 PPT 页内容适配、可检查理解点、题目与判定依据等对象。

每份材料保留资源、发布版本或内容 hash、PPT 页/HTML 场景定位。课堂实际呈现内容是本次检查范围，原 PPT 用于核对和补充说明；未呈现内容不直接成为必答知识。图表/公式无法可靠读取、PPT 与 HTML 冲突或没有足够讲解时，记录限制，不强行凑题。

模型先从材料生成“可检查理解点”，每项写明：核心内容是什么；学生能回答什么才算有理解证据；能引用哪部分材料。它们是系统推导的内部候选，不等于教师已经制定的课程目标。

### 2.2 用蓝图控制覆盖与难度

| 题目角色 | 建议形式 | 观察什么 |
|---|---|---|
| 核心含义 | 单选或判断 | 是否识别本课的关键含义/关系 |
| 条件或辨析 | 单选/情形判断 | 是否混淆条件、对象或容易混淆的概念 |
| 简单应用 | 短情境单选 | 能否把本课方法用于一个轻量问题 |
| 理解依据 | 一道短简答 | 能否用自己的话解释某个关键原因/关系 |

这是候选结构，不是四种题必须机械齐全。每题标一个主要检查目标，可有次要关联，但不能答对一道题就更新所有相关概念为掌握。题组应覆盖本课多个重要方面，允许简答与某道客观题形成交叉核对。简单应用所需信息应在题干给全，避免依赖额外背景知识。

### 2.3 同时准备答案、依据与后续变式

模型批量准备候选题，每题至少包含：

```text
Question
  id / version / lessonPackageId
  role: diagnostic | practice | independent_check
  primaryTargetId / optionalSecondaryTargetIds
  prompt / type / stableOptionIds
  answerKey                      客观题答案
  criteria[]                     简答要点及各要点出处
  acceptableAlternatives[]       允许的不同表述或合理解法
  sourceRefs[]                   页码/场景ID、引用文本
  distractorHypotheses[]         错误选项可能反映什么，非确定诊断
  familyId / relatedQuestionIds  题族、练习及验证变式关系
```

在学生作答前固定题目、答案和判定要点，不随回答临时改标准。答案与量规留在服务端。客观题按选项 ID 判定，显示顺序随机也不影响判分。

初步检查、练习和独立验证使用不同任务 ID；验证题保留在服务端，需要时才下发，不提前展示答案。换数字或换名称不自动构成新情境，是否验证应用要看任务是否要求实际运用概念。

### 2.4 出题质量校验

规则检查题目格式、来源与定位有效性、选项 ID、答案存在、重复及覆盖；模型复核题干是否充分、答案是否唯一、其他选项是否也合理、简答标准是否超出材料。适合计算/有限规则的题可追加可执行或确定性校验。

引用检查只能证明文本可定位，不能证明知识或题目语义正确。模型复核也不保证可靠；试点先抽样核对题目、答案、干扰项和评分要点。不能因为换一个提示词或再调用一次同一模型，就把结果当作独立专家认证。

不合格候选剔除或重生成，有效内容不足时减少题量并保留未覆盖项。不要把“必须四题”放在质量前面。

### 2.5 生成时机

同一发布内容的题目准备一次、按版本缓存，可在首次进入或视频播放期间后台完成。不同学生采用相同蓝图和已校验候选，避免每次临场自由生成造成质量和难度漂移。补充练习可后生成，但同样要通过校验。

## 3. 怎样判断学生当前掌握情况

### 3.1 先保留初始回答

建议逐题显示，完成这一小组前不展示答案和长篇纠错。允许“不知道”、跳过或提问。中性澄清题意与提供学科提示区分记录；若已经看材料、看提示或改答，保留首次回答和帮助后的回答，分别计入证据。

题目有歧义、答案错误或模型无法判定时，标记待核查，不把系统问题归给学生。

### 3.2 客观题与简答分别判断

客观题正误由预先固定的答案规则判定；错误选项只能产生误解假设，不能直接断言学生的思维过程。客观题答对是初步证据，不证明能独立解释或应用。

简答由模型按预设要点逐项输出“满足/部分满足/未体现/存在矛盾/无法判断”，附学生回答原文片段及简短理由。接受同义改写、口语和合理替代解法，不强求原文关键词；遗漏不自动等于错误，表达不清先澄清。模型无依据时输出 uncertain，不凭空补写学生意图。

一条 AttemptEvidence 至少记录题目和版本、原始回答、首次/改答、帮助等级、逐标准判定、引用依据、评估版本、是否题目待核查、是否计入学习状态。失败重试保留已提交答案，不重复计数。

### 3.3 按内容形成可解释状态

| 状态 | 证据含义 | 常见下一步 |
|---|---|---|
| 初步有理解证据 | 客观题或短回答支持当前理解，但证据有限 | 减少重复，必要时补一个应用检查 |
| 理解不完整 | 部分要点成立，关键条件或关系未体现 | 有针对性地澄清/补讲 |
| 疑似误解或证据矛盾 | 回答出现相反概念，或不同题表现冲突 | 先确认，再用对比/反例纠正 |
| 应用需要支持 | 能说明概念，解决情境问题仍有困难 | 例题或分步练习，再撤去帮助 |
| 未确定/未覆盖 | 未答、题目无效、模型不确定，或根本没检查 | 后续补查或保留未验证 |

这些状态描述“内容上的表现”，不给学生贴能力标签。理解与应用分开记录，帮助程度另外记录。多道题冲突不能简单平均成一个分数；尤其要避免“定义选对＝概念完全掌握”。

整体摘要由这些结构化结果生成。例如：“本次抽查中，A 有初步理解证据；B 可能混淆适用条件；C 的应用需帮助；D 尚未覆盖。”同时列出证据和覆盖范围。

可以显示答题正确数作为活动结果，但不能把 3/4 正确写成“整课掌握 75%”。不使用未经校准的模型自报置信度或贝叶斯掌握概率。初步检查不是课前测，不能单凭它计算视频学习增益。

## 4. 大模型怎样据此安排辅导

### 4.1 输入与产出

规划模型获得：本课范围与来源；题目、首次回答及判定；按内容整理的理解/应用状态；已使用提示与已展示题目；当前未完成项；可用材料与练习；会话已有进展和约定负担限制。

它输出简短、结构化的安排，而不是先写一篇长讲稿：

```text
TutoringPlan
  id / version / basedOnEvidenceIds
  priorityItems[]
    targetId / reason
    activityType
    sourceRefs / taskId
    successEvidenceNeeded
    nextIfNeedsSupport
  deferredTargets[] / uncheckedTargets[]
```

学生只看到简短说明：“你已经能识别 A；我们先分清 B，再练一次 C。”模型选择解释方式和活动顺序，但来源、题目和状态字段需要程序校验。

### 4.2 选择辅导活动的规则建议

| 观察到的情况 | 模型可选择的活动 | 推进依据 |
|---|---|---|
| 只是回答含糊 | 一个短澄清问题 | 澄清后再评估，不先判不会 |
| 关键关系没有理解 | 引用本课材料简短解释、举例 | 学生能解释或正确辨析相关关系 |
| 两种情况混淆 | 对比两个情形或给反例 | 学生指出关键差异及理由 |
| 知道概念但不会做 | 示范例子或提供第一步，学生继续 | 随后在较少帮助下完成新任务 |
| 已独立表现良好 | 略过基础重复，转应用或结束当前目标 | 没有新的关键反证；记录仍未验证的部分 |
| 多次没有进展 | 换一种解释、分解任务或暂缓 | 不无限追问；暂缓不计掌握 |

初步优先处理会影响当前任务的核心误解，再处理应用困难。只有明确证据支持的先修关系才用来重排，不为了规划而生成一整套假定知识图谱。初始计划保持短，后续新证据出现时调整；不必每发一句话就重做全课规划。

### 4.3 一轮辅导怎样执行

确定当前目标与活动 → 生成解释或问题 → 学生作答 → 按既定标准评估 → 保存证据 → 选择继续帮助、独立尝试、下一目标、暂缓或结束。

模型逻辑职责分为“准备题目、评估回答、安排辅导、生成导师回复”，可以复用同一个模型服务，不意味着一定部署多个 Agent。程序管理可用动作、当前任务、帮助记录和阶段状态，防止回复文本自行把任务宣告完成。

如果回答评估不确定，先澄清或暂缓，不把不确定当作错误或答对。模型请求失败不增加学习轮次；规划失败可保留原计划或按明确优先级给出基础安排，不覆盖原始证据。

### 4.4 何时认为可以结束一个目标

提示后说对记录为“支持下完成”；随后使用未展示解答的新任务检查独立表现。若独立任务仍需要提示，继续记为练习，之后再选合适任务检查。

本次独立完成可作为当前目标的新增证据，不直接代表长期掌握。核心条件应满足、没有关键误解，具体通过标准由任务确定。轮次/时长上限用于控制负担，数值待试点；到上限可记录待巩固并结束，不能自动判通过。学生主动结束时保留未完成和未覆盖项。

## 5. 串联例子

以下为说明性例子，不代表仓库已有该课；假定课堂实际讲过以下内容：相关不等于因果；第三因素可能同时影响两件事；比较学习活动效果时要留意学生原有水平等差异。没有讲过的研究设计知识不列为必答要求。

| 题目 | 简化题干与判定依据 |
|---|---|
| Q1 判断 | “两件事同时增加，就能确定一件导致另一件。”正确为否，对应相关/因果关系 |
| Q2 单选 | “天气越热，冷饮销量和中暑人数都增加。更合理的解释是什么？”选项包含第三因素同时影响二者，以及直接因果等干扰项；题干已给出必要条件 |
| Q3 单选 | “自愿参加某活动的学生成绩更高，能否直接认定活动有效？”选“还需了解原有水平等差异”；不能推出活动肯定无效 |
| Q4 简答 | “为什么了解原有学习水平有帮助？用一两句话说明。”要点是原有水平可能影响成绩，不能把组间差异直接归因活动；接受合理口语表达 |

假设学生 Q1 答对、Q2 答错、Q3 答对，Q4 写“活动组分数高就说明有效”。

逐题表现与解释存在矛盾。初步概况应是“能识别部分正确说法，但在解释和具体情境中对因果依据仍不稳定”，不能据 2/3 客观题正确直接判掌握。

建议规划：

1. 先问一个澄清问题，确认 Q4 是否只是表达不完整。
2. 若确有误解，利用 Q2 对比“同时变化”和“谁导致谁”，回到本课依据。
3. 让学生解释原有水平会怎样影响对活动效果的判断，记录提示程度。
4. 给未展示答案的新情境，必要条件在题干说明，让学生独立判断并说明理由。
5. 独立完成则更新为本次有独立解释/应用证据；仍有困难则保留待巩固，不推翻已有的其他正确表现。

## 6. 对现有后端的落点

- `context.py` / `knowledge.py`：保留材料隔离和引用定位，增加可检查理解点和题组准备；题组按发布来源缓存。
- 新的题目和作答记录：独立于聊天保存题目版本、选项、原始回答、判定标准与帮助记录。
- `graph.py`：从只评估当前复述知识点，扩展为围绕明确任务的评估、规划和回复职责。
- `progression.py`：现有确定性推进思想保留，后续用计划、任务完成证据与帮助记录替代所有人固定走一遍 recall/reinforce/discuss 的规则。
- `feedback.py` / `persistence.py`：保留概念与应用结果分开，保存初始概况、计划版本和新表现；保留本次证据，不用历史最高星级替代。
- 运行态新增建议阶段：video / diagnostic / tutoring / done；verify 作为辅导活动类型即可，是否另设阶段待接口设计确定。

每次提交使用幂等标识；作答、评估、学习状态和下一活动写入同一业务事务或明确的可恢复状态。记录模型/提示词版本，便于回看“为什么这样安排”。这些是新增实现要求，不是当前已具备能力。

## 7. 验证设计与开放决策

先在代表课时检查出题质量、判定是否与教师一致、错误辅导和过度放行的情况，再检查无帮助新题表现和学习负担。模型自评一致不能替代教师/人工样本核对；更多模型调用也不自动解决同源偏差。

已确认的题型不再反复征询。后续需要共同确定：

1. 是否用 4 题作为首版默认及何时减少；
2. 是否先完成初步题组再展示详细讲解；
3. 辅导每个目标的负担上限，以及多次无进展时怎样退出；
4. 用哪门课的真实 PPT/HTML 做第一个串联样例。

## 8. 外部依据与设计归属

- [ALEKS Knowledge Check](https://www.mheducation.com/prek-12/support/knowledge/what-is-a-knowledge-check.html)：检查中不即时告知正误，并据结果安排学习。支持将独立检查与后续教学分开的参考；不支持声称四题具有其课程诊断精度。
- [StudyFetch 测验结果与推荐](https://www.studyfetch.com/docs/docs/quizfetch/quizfetch-results-and-recommendations)：困难较多时建议回材料，提供后续学习工具。支持按表现衔接补学的产品参照；未公开完整内部误解推理和调度算法。
- [Khan Academy 产品测试](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)：关注同技能下一题无帮助正确率，也研究结构化作答历史。支持记录实际表现和独立新题的参照；不等于本项目已验证有效。

本文件的四题组合、状态对象、规划字段及控制规则均是适配当前项目的讨论建议，不冒称某产品完整原生实现。

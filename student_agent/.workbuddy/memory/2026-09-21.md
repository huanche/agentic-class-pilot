# 2026-09-21

## 做了什么：把编排器接进真实对话（新增 apps/ 会话层）

用户目标："让他接入对话，能在课堂上运行"。诊断后确认编排核心已完整（`run_one_turn` 是现成接入点），
缺的是外围。本次交付：

- **`apps/server.py`** — FastAPI 会话层：`POST /api/session/start`、
  `/{sid}/message`、`GET /{sid}/state`、`/messages?since=N`、`/export?fmt=md|json`、`DELETE /{sid}`。
  后台心跳线程（默认 10 秒）+ per-session `threading.Lock`（心跳与学生发言会并发打同一张图）。
- **`apps/static/index.html`** — 学生端页面：对话区 + 顶部阶段/进度条 + 学情按钮，2 秒轮询。
- **`apps/smoke_test.py`** — 课前彩排脚本，`auto`（不发言跑完整节课）/ `chat` / `export` 三模式。
- **`orchestrator/agent.py`** — 心跳改造（详见下）。

## 关键设计决策

1. **心跳不改变编排语义**：`tick_only` 只是"这一轮没有学生输入"。路由让心跳走 teach
   （否则讲解阶段不会自动推进段落），是否开口由 teach 内部按"有没有新内容"决定：
   讲到新段落 / 抛出新一问 → 说话；其余（还在同一段、问题已挂起等学生答、ending）→ 静默。
   `tick` 每轮清空 `reply_text`，否则静默轮会把上一句重复推给前端。
2. **不用 LangGraph checkpointer**：`langgraph-checkpoint-sqlite` 装不上；`load_plan` 幂等，
   所以每轮把上一轮完整 state 全量回灌即可续上，持久化只需一个 JSON（`runtime/sessions/<sid>.json`）。
   新增 `run_turn_stateless()` 承载这个调用方式。
3. **`time_scale` 由会话层注入**（不是环境变量），保持图是纯函数。`?scale=30` 把 45 分钟压到约 90 秒，
   课前彩排用。注意倍速越大，心跳采样越粗，会跳过一些段落（正常现象）。
4. **切幕/下课要说人话**：原先 `advance_stage` 往 reply_text 里塞 `[切幕] 进入X（预算 n 分钟）`
   这种内部日志，会直接念给学生。改为 `stage_opening()` / `_ending_remark()`，LLM 润色 + 模板兜底。
   下课总结放在 advance_stage 里当场生成（因为切到 ending 立刻置 `student_status=ended` 停心跳，
   等下一轮 teach 再说就永远没人说了）。

## 验证结果

- `run_demo.py` 编排结果与改造前逐行一致（四个幕的切换时间点不变），说明改动没破坏编排。
- 端到端：**全程零输入，90 秒自己上完一节课**（讲解→复述→探究→下课），自动讲段、自动抛题、自动切幕。
- 学生发言：AI 反馈正常；讲解阶段不涨星是正确的（星级靠复述/探究阶段记）。

## 踩到的坑

- **pip 用清华源对 pip 进程解析不出包**（curl 能拿到页面但 pip 报 "from versions: none"）。
  解决：`pip install -i https://pypi.org/simple --trusted-host pypi.org`。
- Bash 里 `sleep` / `tail` / `ls` 不在默认 PATH，需先 `export PATH="/usr/bin:/bin:$PATH"`。
- 长跑脚本会被 Bash 工具超时 SIGTERM，要么缩短要么显式给 `timeout`。
- 课堂实战提醒：**时钟是真实的**，电脑休眠一晚唤醒后课时会跳变直接走到下课（已写进 README）。

### 这个环节踩的坑（下次照抄即可）

1. **bat 内容必须纯 ASCII**。Python 在 `C:\Users\陈怡凡\...` 下，中文路径写进 bat 会被 cmd 按 GBK 解码成乱码。
   绕法：用 `%USERPROFILE%\.workbuddy\binaries\python\envs\default\Scripts\python.exe` 拼，
   中文由系统变量提供，bat 里一个非 ASCII 字符都不用写（文件名用中文没关系）。
2. **8.3 短路径不可用**：本机 `C:\Users\陈怡凡` 没有生成短名（`dir /x` 看不到），此路不通。
   另注意 `New-Object -ComObject Scripting.FileSystemObject` 被安全策略拦，别用。
3. **`print` 必须 `flush=True`**：stdout 重定向到文件时是块缓冲，双击启动的用户看到的窗口一片空白，
   直到 Ctrl+C 才把横幅吐出来。start.py 所有提示行都加了 flush。
4. **`cmd //c xxx.bat` 在 Git Bash 里不生效**（MSYS 路径转换吃掉 `/c`，cmd 进交互模式），
   验证批处理要用 PowerShell 工具 + `run_in_background=true`，输出重定向到文件再读。

## 追加 2：事件驱动改造（用户定调：前端给另一位同学做，我只做后端 + 命令行）

真实课堂流程 = **进教室待机 → 老师按「开始上课」→ 前端放视频、每播完一段上报 →
复述/深度探究学生答题 → 老师按「下一环节」一步步走 → 下课导出**。为此：

- **agent.py 新字段**：`lesson_status`(idle/running/ended，图内不判 idle，由会话层兜)、
  `external_event`(begin/media_done/next_stage，每轮由会话层显式传值覆盖)、
  `segment_cursor`+`played_media`。
- **judge_advance**：外部事件优先级最高，next_stage 无条件切幕（跳过 min_stage_minutes/
  evidence/预算三道门槛）；media_done 在 guided_learning 且游标越界（素材播完）→ 自动进下一环节。
- **teach guided_learning 段落游标双驱动**：时间（`_cursor_for_elapsed`）与 media_done 取
  max，游标只增不减。**next_stage 轮 teach 必须静默**（否则出现"刚抛一个问题又宣布换环节"
  的缝合怪回复）。
- **advance_stage 切到提问阶段当场挂第一问**（question_queue/pending_question/current_question
  一起设 + reply 追加"先来第一问：…"）：不然前端拿到 current_question=None，
  要干等一轮心跳（10 秒）才听到题目。
- **server.py**：start 只建会话（idle，不计时；幂等）；新增 `POST /begin`（起课铃，一轮跑完
  load_plan→intro 开场白→切进第一环节）、`/media/done`、`/stage/next`、统一入口 `/event`；
  每个写接口和 /state 都返回 `available_actions`（前端照此渲染按钮，别猜）；
  心跳只推 running 会话；`_get` 恢复磁盘会话时若 running 会把心跳线程接回来。
- **apps/cli.py**：命令行上课窗口（/begin /video /next /state /stars /msgs /export /new /stop，
  打字=学生发言），走 HTTP 与前端同源，可当联调参照。
- **apps/API.md**：给前端同学的对接文档（时序图 + 全接口 + curl 示例 + 注意事项）。
- **smoke_test.py 加 stages 模式**：用三个按钮走完整节课（不依赖真实时间）。
- 验证：stages 11 步走完（起课→视频×6→复述答1题→next→探究答1题→next→下课总结）；
  auto 40 倍速心跳驱动走完；run_demo 回归不变。

## 追加 3：讲解阶段改「整段视频」模式（用户纠正：视频是一次全播完、无讲解词、但计入课堂时间）

之前的理解错了（以为是每段视频逐段报、AI 逐段讲解词）。用户澄清后改造：

- **lesson-plan.json**：guided_learning 加 `"delivery": "video"`（narration 为默认，保留 AI 逐段讲解的课用）。
- **agent.py `stage_delivery()`**：读配置。video 模式三件事：
  1. teach 在 guided_learning **全程静默**（唯一动作：media_done 那轮把 `segment_cursor` 推满
     + 全部段落记入 `played_media`）；
  2. judge_advance：video 模式讲解阶段**只认外部事件**（media_done/next_stage），
     时间预算不切幕——视频可能比阶段预算长，不能没放完就被时间赶走；
  3. 开场白（host_event intro 与 stage_opening）提示"请看讲解视频"。
- **`media/done` 语义 = 整段视频全片播完，播完报一次** → 自动切进复述 + 第一问。
- 视频时间计入课堂：begin 起计时，播放期间 status=running，lesson_elapsed 照涨（进度条正常走）。
- demo（run_demo.py）：TURNS 加第 4 列事件，10:22 一轮 `("", host, EVENT_MEDIA_DONE)`。
  run_one_turn 加 external_event 参数。

### 再补一刀（用户二次纠正）：视频前面连"进入讲解环节"的开场白也不要

起课铃（begin）的开场白保留（宣布上课+说明讲解是视频），之后 **AI 完全静默直到视频播完**：
advance_stage 切到 guided_learning 且 video 模式 → 不生成 stage_opening（空串），
学生听到的第一句 AI 互动话是复述板块的开场白+第一问（"有头有尾"）。
分板块原则：**每个板块切进来才说这个板块的话，讲解板块（视频）没话说就不说**。

### 重大坑：外部事件轮被路由进 host_event（已修）

`route_after_classify` 原来只看 tick_only/speaker：demo 的 media_done 轮 speaker=host 且 msg 非空
→ 走 host_event → **teach 不执行 → segment_cursor 没推满 → media_done 切幕分支不触发**。
demo 里碰巧 10:22 也是 22 分钟预算耗尽，靠时间切走了幕，差点看不出 bug。
修复：`external_event in (media_done, next_stage)` 一律路由到 teach（事件处理逻辑全在 teach/judge）。
教训：**事件轮必须走教学层，host_event 只管开场白和插话**；以及"切幕时间点碰巧对"要警惕——
看 advance_reason 是不是预期的那条（这次是"预算耗尽"而非"讲解素材已全部播完"暴露的）。

- **服务进程内存里的会话在测试后会持续写脏 runtime**：`rm runtime/sessions/*.json` 只删了磁盘，
  进程里 SESSIONS 还在、心跳还在跑，`git checkout -- runtime/` 之后立刻又被写脏。
  正确清理顺序：先 `DELETE /api/session/<sid>`（或重启服务），再删文件再 checkout。
- class_discussion 在本课 lesson-plan 里 enabled:false，所以探究 next 直接下课——
  这是配置行为不是 bug；哪门课要讨论环节就在 lesson-plan.json 里开。

- **多人会话不隔离**：`write_state` 把 `runtime/DIALOGUE-LOG.md` 与 `data/mastery-state.json` 写死路径，
  第二个学生会覆盖第一个的档案。用户本次选择"单人先跑通"，所以没改，已记入 README 已知缺口（高优先级）。

   DIALOGUE-LOG.md 仍是共享文件（只影响日志可读性，不影响判定），暂不动。

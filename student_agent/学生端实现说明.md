# 学生端是怎么工作的（新手版）

这份文档按“学生从平台进入课堂后发生什么”来解释项目中的学生端。先记住三个角色：

- **前端**：浏览器里看到的页面，负责显示课程、视频、聊天框，并把操作发送给后端。
- **后端**：运行在服务器上的 Python 程序，负责登录令牌校验、读取课程、保存课堂状态和调用 Agent。
- **Agent**：后端中的 AI 教学流程。它读取视频资料、整理知识点、判断学生回答，再决定下一步如何引导。

可以把它想成餐厅：前端是服务员和菜单，后端是厨房和订单系统，Agent 是负责按课程资料做教学判断的老师。数据库则是保存课程记录的账本。

## 1. 学生端代码在哪里

新版学生端放在 `student_agent/`，结构如下：

```text
student_agent/
├── frontend/    浏览器页面（Next.js / React）
├── backend/     HTTP 接口（FastAPI）
├── agent/       AI 流程、提示词、知识点和学习进度规则
└── scripts/     本地启动脚本
```

旧版学生端代码已移除。当前 `agent/database.py` 直接读写平台数据库中现有的 `student` 表；数据库表与学生端服务仍由平台统一维护。

## 2. 一堂课从头到尾的流程

```text
学生登录平台并加入课程
        ↓
平台签发 launch_token，学生点“进入学习”
        ↓
前端把令牌交给新版后端，后端向平台读取已发布课时
        ↓
学生选择课时并点“开始上课”
        ├─ 后端立即把课堂阶段设为 video
        └─ 后台同时整理视频画面文字和讲解旁白，提取知识点
        ↓
前端嵌入教师端现有播放器；准备完成后可进入“复述与讨论”
        ↓
每次学生发言 → 后端调用 LangGraph → AI 评估/回复 → 保存消息和状态
        ↓
学生结束本节课 → 生成个人知识点反馈 → 可回看视频或继续课后对话
```

视频播放器沿用已有的平台播放器，通过 iframe 和浏览器 `postMessage` 通信。新版学生端不会重新实现播放器。

## 3. 前端：页面如何显示、如何发请求

### 主要文件

- [`frontend/src/app/page.js`](frontend/src/app/page.js)：Next.js 页面入口，渲染学生端主组件。
- [`frontend/src/components/StudentApp.js`](frontend/src/components/StudentApp.js)：学生端主要页面状态、按钮事件、聊天发送和后端请求都在这里。
- [`frontend/src/integration/platform-player-adapter.js`](frontend/src/integration/platform-player-adapter.js)：把平台视频播放器放进页面，并接收播放结束或播放器错误事件。
- [`frontend/src/components/LessonFeedback.js`](frontend/src/components/LessonFeedback.js)：课后逐知识点反馈展示。
- [`frontend/src/app/globals.css`](frontend/src/app/globals.css)：页面样式。

### 页面阶段

`StudentApp.js` 用 `phase` 表示当前页面，主要有：

| phase | 页面内容 |
|---|---|
| `auth` | 提示从平台登录进入 |
| `courses` | 课程选择 |
| `lessons` | 课时选择 |
| `lesson` | 课时介绍和“开始上课”按钮 |
| `video` | 现有视频播放器和进入对话阶段按钮 |
| `discussion` | 课堂复述与讨论聊天 |
| `done` | 课堂结束和知识点反馈 |
| `replay` | 课后回看视频 |
| `postclass` | 课后补完薄弱知识点或自由提问 |

### 前端怎样请求后端

组件里的 `api()` 是统一请求小工具。它会把路径拼成 `/api/...`，把对象转成 JSON，收到错误时显示后端返回的错误文字：

```js
async function api(path, method = "GET", body) {
  const response = await fetch(`/api${path}`, {
    method,
    headers: body ? { "Content-Type": "application/json" } : {},
    body: body ? JSON.stringify(body) : undefined,
  });
  const data = await response.json().catch(() => ({}));
  if (!response.ok) throw new Error(data.detail || `请求失败 (${response.status})`);
  return data;
}
```

`fetch` 是浏览器自带的网络请求功能。比如 `api("/session/start", "POST", {...})` 实际访问 `/api/session/start`。

### 登录令牌与恢复课堂

平台把短期 `launch_token` 放在进入学生端的 URL 中。前端读出它后保存到 `sessionStorage`，并从地址栏移除令牌。然后调用 `/api/session/start`。如果浏览器已有会话编号，就先请求后端恢复上次状态。

这里的 `sessionStorage` 是当前浏览器标签页的临时存储；真正的正式课堂记录由后端写入数据库。浏览器刷新后，前端用会话编号向后端取回状态。

### “开始上课”马上显示视频

前端的 `begin()` 先立即执行 `setPhase("video")`，再向后端请求开始课时：

```js
async function begin(selected) {
  setLesson(selected);
  setVideoEnded(false);
  setPhase("video");
  setPreparation("pending");
  const state = await api(
    `/session/${sessionId.current}/begin/${encodeURIComponent(selected.id)}`,
    "POST"
  );
  setPreparation(state.preparation);
}
```

所以学生不需要等待 AI 提取知识点后才看到视频。视频页面每两秒查询一次准备状态；整理失败时可以点按钮重试。

### 聊天发送和加载动画

发送消息时前端先把学生发言显示出来，再设置 `replyPending`。这个状态会显示 AI 的三个跳动圆点。请求结束后用后端返回的完整消息更新聊天记录。

`handleComposerKeyDown()` 还负责让 Enter 发送、Shift+Enter 换行；中文输入法正在组字时不会误发送。

## 4. 后端：课程接口、课堂状态和数据库

### 主要文件

- [`backend/main.py`](backend/main.py)：FastAPI 应用和学生端 API 路由。
- [`agent/persistence.py`](agent/persistence.py)：会话快照与学习数据的保存和恢复；SQL 操作位于 `agent/database.py`。
- [`scripts/start-platform.ps1`](scripts/start-platform.ps1)：读取项目配置并启动学生端后端。

FastAPI 可以理解成“把 Python 函数变成 HTTP 接口”的框架。前端点击按钮会请求这些接口：

| 接口 | 用途 |
|---|---|
| `POST /api/session/start` | 校验平台令牌、读取课程并创建学生会话 |
| `GET /api/session/{sid}` | 读取会话状态；也会安排尚未完成的知识点准备任务 |
| `POST /api/session/{sid}/begin/{lesson_id}` | 开始课时，马上进入视频阶段并后台准备知识点 |
| `POST /api/session/{sid}/prepare` | 知识点整理失败后重试 |
| `POST /api/session/{sid}/discussion` | 进入复述与讨论并生成开场消息 |
| `POST /api/session/{sid}/message` | 处理课堂聊天的一轮学生发言 |
| `POST /api/session/{sid}/end` | 结束课堂并生成反馈 |
| `GET /api/session/{sid}/feedback` | 读取个人课堂反馈 |
| `POST /api/session/{sid}/postclass/start` | 开始课后对话 |
| `POST /api/session/{sid}/postclass/message` | 处理课后补完或自由提问 |
| `GET /api/session/health` | 检查平台、模型和数据库配置是否齐全 |

`sid` 是 session ID（会话编号）。它用来让每次请求都能找到同一个学生本节课的状态。

### 后端如何向平台取课时

`platform_context()` 把 `launch_token` 发给平台内部接口 `/internal/student/learning-context`，并带上服务密钥。平台验证学生身份和课程权限后，返回课程与已发布课时。新版后端再用 `catalog()` 转成前端需要的课程结构。

因此登录和选课码加入课程仍由平台完成。学生端只接收平台签发的短期令牌，并读取该学生已获准访问的课程。

### 开始课时与后台准备

后端 `begin()` 保存课时编号、视频课堂编号和初始视频材料，把 `phase` 设成 `video`、把 `preparation` 设成 `pending`，之后通过 FastAPI 的 `BackgroundTasks` 执行 `prepare_in_background()`。

准备任务调用 `learning_points(materials)`；成功后把知识点写进会话状态，失败后把错误状态保存下来。这个准备过程不会要求前端等待模型完成。

### 课堂消息如何处理

后端 `/message` 路由会把本轮学生文字和历史消息放进对话状态，然后调用 `dialogue_graph.invoke(dialogue)`。Agent 返回新的状态与 AI 回复后，后端把学生和 AI 两条消息一起提交保存。

简化后的核心关系是：

```python
dialogue["student_text"] = student["text"]
dialogue["messages"] = session["messages"] + [student]
dialogue = dialogue_graph.invoke(dialogue)
assistant = {"role": "assistant", "text": dialogue["reply"]}
commit(session, {"dialogue": dialogue, "messages": session["messages"] + [student, assistant]})
```

### 数据存在哪里

`agent/persistence.py` 调用本目录的 `agent/database.py` 读写平台数据库。正式平台会话会保存：

- `student.student_sessions`：会话及课时基本信息。
- `student.student_messages`：学生和 AI 的逐条消息及所属阶段。
- `student.knowledge_mastery`：知识点掌握状态、星级和证据。
- `student.learning_events`：Agent 状态快照、最终反馈和课堂结束时的反馈快照。

会话快照里包含当前页面阶段、对话状态、知识点准备状态、消息、反馈等内容。因此后端重启后，可以从 `learning_events` 恢复继续中的课堂。

本地显式演示模式没有平台身份，不会写正式学习数据库。正式登录学习走平台令牌路径。

## 5. Agent：AI 如何提取知识点和引导对话

### Agent 不是一个单独的“机器人文件”

Agent 是多个模块组合起来的流程：提示词告诉模型如何工作，LangGraph 规定每一步调用顺序，进度规则代码决定哪个知识点、哪个阶段，以及何时跳转。

### 关键文件

- [`agent/context.py`](agent/context.py)：从已发布视频场景整理资料，包括画面文字和讲解旁白。
- [`agent/knowledge.py`](agent/knowledge.py)：让模型从视频资料提取知识点，并校验知识点是否有视频原文依据。
- [`agent/prompts.py`](agent/prompts.py)：知识点提取、回答评估、课堂导师、各阶段和对话策略的提示词。
- [`agent/graph.py`](agent/graph.py)：课堂 LangGraph 流程和模型调用配置。
- [`agent/progression.py`](agent/progression.py)：逐点复述、轮次限制和阶段跳转规则。
- [`agent/postclass.py`](agent/postclass.py)：课后补完与自由提问的 LangGraph 流程。
- [`agent/feedback.py`](agent/feedback.py)：把每个知识点的学习记录整理为学生反馈。

### 知识点从哪里来

知识点来自当前课时视频的场景，不从旧知识清单中选取。`context.py` 按视频播放顺序读取每个场景的画面文字和 speech 旁白。提示词要求模型只提取视频实际讲清楚的概念、原理或方法，并提供原文证据。

`knowledge.py` 还会用程序校验模型返回的证据：引用必须能在相应视频场景原文中找到，知识点名称也必须出现在引用里。通过校验后，知识点描述采用视频原文片段。校验失败会报错，界面允许重试。

### LangGraph 是什么

LangGraph 是组织 AI 多步骤流程的 Python 库。可以把它理解成流程图：一个节点做一件事，节点之间的箭头表示下一步。

课堂对话图在 `graph.py` 中定义：

```python
builder.add_node("evaluate", evaluate)  # 让模型判断学生回答
builder.add_node("route", route)        # 程序按学习状态决定阶段和下一个知识点
builder.add_node("respond", respond)    # 让模型生成自然语言回复
builder.add_edge(START, "evaluate")
builder.add_edge("evaluate", "route")
builder.add_edge("route", "respond")
builder.add_edge("respond", END)
dialogue_graph = builder.compile()
```

每当学生发一条消息，图就运行一次：先评估，再按代码规则更新进度，最后让模型用合适的阶段提示词回复。

### 课堂阶段与轮数

每个知识点按顺序走：

1. **初始复述**：默认每个点最多 8 轮。学生答得好会提前进入下一个点；答不出来时 AI 给小提示。达到轮数上限后先记下这个薄弱点，继续后面的知识点。
2. **加强复述**：首轮所有点都走完后，对未掌握的点逐个再引导，每点最多 4 轮。首轮超过 5 轮仍没掌握的点会被标记为重点加强，AI 要用简单说法或生活类比重新梳理概念。
3. **深入讨论**：加强后掌握的点才允许进入讨论或出题。仍未掌握的点会记录为待巩固，不会被拿去讨论或出题。
4. **结束**：没有可深入讨论的知识点时，AI 提示学生结束本节课并查看反馈。

这些上限默认由 `STUDENT_AGENT_RECALL_ROUNDS=8` 和 `STUDENT_AGENT_REINFORCE_ROUNDS=4` 控制。进度代码在 `progression.py`，提示词在 `prompts.py`，因此“阶段规则”和“AI 怎么表达”分别放在不同地方。

### 模型配置

`graph.py` 用 LangChain 的 `ChatOpenAI` 接口调用兼容 OpenAI API 格式的模型。配置优先级是：

- 密钥：`STUDENT_AGENT_API_KEY`，其次 `LLM_API_KEY`。
- 服务地址：`STUDENT_AGENT_BASE_URL`，其次 `LLM_BASE_URL`，默认 DeepSeek API 地址。
- 模型名：`STUDENT_AGENT_MODEL`，其次 `LLM_MODEL`，默认 `deepseek-v4-flash`。

模型密钥应放在本机环境或 `.env` 文件里，不要写入前端代码，也不要提交到 Git。

### 课后补完和反馈

结束课堂时，`feedback.py` 根据本次学生回答生成逐点反馈。学生点“与 AI 补完知识点”后，课后图先针对课堂未掌握的点逐项引导。学生独立讲清后，该点标为“课后补完”；未完成项处理完后，课后阶段转成自由提问。课后状态变化会更新个人反馈和数据库记录。

## 6. 怎么顺着代码读一次请求

以“学生发送一条课堂消息”为例：

1. 在 [`frontend/src/components/StudentApp.js`](frontend/src/components/StudentApp.js) 找 `send()`：它读取输入框内容并请求 `POST /api/session/{sid}/message`。
2. 在 [`backend/main.py`](backend/main.py) 找 `@app.post("/api/session/{sid}/message")`：它检查课堂阶段、组装 Agent 状态。
3. 在 [`agent/graph.py`](agent/graph.py) 找 `evaluate()`、`route()`、`respond()`：依次评估、更新进度、生成回答。
4. 在 [`agent/progression.py`](agent/progression.py) 找 `advance()`：根据 `mastered`、`partial` 等结果更新轮数与阶段。
5. 回到 `main.py` 的 `commit()`：保存新的消息、Agent 状态和会话快照。
6. 前端拿到响应后更新聊天内容，并结束三个点的加载动画。

## 7. 启动和常见配置

平台整体启动脚本是项目根目录的 `platform/scripts/start-local.ps1`。新版学生端也有单独脚本：

```powershell
.\student_agent\scripts\start-platform.ps1
```

新版后端默认监听 `127.0.0.1:8001`，前端构建产物在 `frontend/out`，由 FastAPI 同源提供。平台页面通常从 `http://localhost:8088/login` 登录，再进入学生课程。

运行需要配置平台内部访问地址、服务密钥、数据库连接和模型密钥。具体配置名可在 `scripts/start-platform.ps1`、`backend/main.py` 的 `platform_context()`、`agent/persistence.py` 和 `agent/graph.py` 中查到。启动后可访问 `GET /api/session/health` 检查平台、模型和数据库配置。

## 8. 新手修改时从哪里开始

| 想改什么 | 建议先看 |
|---|---|
| 页面文字、按钮或页面切换 | `frontend/src/components/StudentApp.js` |
| 页面颜色、尺寸、布局 | `frontend/src/app/globals.css` |
| 视频如何嵌入、播放结束事件 | `frontend/src/integration/platform-player-adapter.js` |
| 后端接口收什么、返回什么 | `backend/main.py` |
| 知识点怎么从视频提取 | `agent/knowledge.py` 和 `agent/prompts.py` |
| AI 如何判断回答、怎么说话 | `agent/prompts.py` |
| 轮数、跳过和阶段跳转 | `agent/progression.py` |
| 课后补完流程 | `agent/postclass.py` |
| 数据库写入和恢复 | `agent/persistence.py` |

建议一次只改一个模块：先确定前端、后端或 Agent 中哪一层负责目标行为，再顺着第 6 节的调用链检查数据是否正确传递。

## 9. 当前实现范围说明

当前学生端包含平台登录后的课程/课时选择、原视频播放、课堂复述与讨论、逐点反馈、回看视频及课后 AI 对话。全班讨论功能没有接入。

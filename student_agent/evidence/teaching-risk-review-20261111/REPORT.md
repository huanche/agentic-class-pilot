# 知识点教学剩余风险：三子 Agent 验证汇总

主 Agent 仅委派、阅读证据和汇总，没有运行测试。验证范围为复合要求判定、首轮5轮及补强8轮，浏览器验收与教师生成不在范围内。三组均使用真实模型、实际学生命令HTTP和独立临时数据库，学生输入由人工设计，不是自主模型学生。未修改业务代码、未提交部署。

## 结论

当前限额控制在所测场景通过，两个教学问题仍需要讨论处理：高优先的复合项宽判，以及中优先的连续无进展却重复完整帮助。不能因为命令成功或状态按时结束，把教学语义质量算作通过。

## 建议先讨论的解决范围

### 高：复合要求的证据宽判

“在rear之后插入”和“动态分配、无固定队满”是可以分别理解的两个事实。当前把它们放在一个要求里，模型容易匹配到一半就确认整项。已有“复合项须整体满足”的提示仍未解决，本轮不建议仅再添加一句同义要求。

可优先讨论把相互独立的事实整理为分别可判断的要求，但仍由一个整点任务收集证据；不新增学生逐条答题流程，不增加轮数，也不把本应完整理解的因果关系机械拆碎。新提取规则与存量要求的兼容需要一起明确。若保留复合项，必须验证累计证据覆盖全部语义，不能按关键词严格匹配或要求本轮重复历史已答内容。

未提及的部分继续留unconfirmed，不记needs_help；模型讲过不能补成学生证据。以本轮四种对照作为后续修改验收，而不是只检查提示词文本。

### 中：无进展时没有换帮助

已有pointConversation、requirements和teaching_plan足够，暂无证据需要新增状态、帮助阶段或扩大轮数。下一次调整应针对实际生成：先识别最近已提供的无效帮助，学生仍无新表现时，不再完整播放同一实现；用一个卡点定位问题，或只示范必要一步，再让学生完成尚未示范的一步。学生明确只想听解释时，不强制追加复述题。

只拦截逐字重复不够：补强的重复多为换说法后越来越长；应验收教法变化与学生可执行的下一步。

### 暂不改：5/8轮规则

本轮未发现改限额的依据。保留最后一次正确回答可完成、末轮求助先解释后收尾、未掌握内容保留的现有行为。

## 限制与证据

- 复合项原场景直接整点误切未发生，错误完成来自受控状态，不冒充自然长对话结果。
- 首轮三类各一个真实会话；其中concept/memory使用人工规范化内容，design来自真实数组课时归档。
- 补强首轮5次是人工复制一次真实评估的准备状态；补强前7答同sid，第8答因测试脚本复制内部线程锁失败，使用第7答真实快照恢复新sid续跑。它验证了实际8次模型回答及边界，但不是同sid无中断完整8轮。
- 设置/脚本失败保留并排除为产品缺陷，不掩盖失败或把修正断言的重跑算作首次通过。
- 三组输出目录：`../compound-current-20261111/`、`../recall-five-current-20261111/`、`../reinforce-eight-current-20261111/`，各有REPORT.md、脚本与原始JSON。
- 样本用于确认问题存在，不能推算全课程发生率。浏览器、并发、服务重启和全部课程覆盖尚未验收。

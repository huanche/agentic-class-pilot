# 数组 PPT 本地完整链路实测

结论：教师生成、审核发布、学生选课、知识点提取、答题评估、结束反馈和退出恢复的真实 HTTP 主链路已跑通。教师生成发生两次失败；学生教学仍有两处明确的体验问题。本次没有修改业务代码，也没有提交或部署。

## 测试范围与方法

- 使用用户提供的《第07章 数组.pptx》，原文件 52 页，平台实际上传解析得到 52 页、52 个文本块。
- 按缩短教师生成时间的要求，选择第 4–11 页的一维数组内容，生成约 3 分钟预算的 3 页短课。不是整章覆盖，也没有验证实际播放时长。
- 使用隔离测试教师与两名测试学生，经本地 `http://localhost:8088` 正常认证入口、发布接口及学生命令接口操作；教师生成和学生评估均调用真实配置的 DeepSeek 模型。
- 学生输入为人工设计的测试回答，不是另一大模型自主扮演学生。浏览器只确认登录页可访问；本报告属于真实服务 HTTP 全链路实测，未完成浏览器逐按钮、播放及视觉验收。
- 本机 TTS 未运行，按产品选项关闭配音与额外媒体生成；不涵盖语音、字幕同步和视频播放。
- 课时提取出 memory、concept、design 三类共 4 个知识点。未覆盖所有知识类型、整章二维数组/字符串，也未跑满每点 5+8 轮的耗尽场景。

## 实际经过

1. 新建课程、上传解析 PPT、真实模型生成大纲。
2. 初版 4 页课件生成在第 4 页失败：讲解代码却聚焦标题。正常重试后仍失败：只说“现在看代码块”，没有实际讲解。失败输出均保留，没有绕过校验发布。
3. 按正常教师大纲修订，把循环示例与练习合并成第 3 页，重新生成完整 3 页课件，审核后发布成功。
4. 发布前学生选课返回 409；发布后选课、进入课时和知识点准备成功。
5. 主学生会话完成 4 点、8 次学生回答，每点 2 次，没有进入加强轮；最终反馈为 4 掌握、0 待巩固、0 未评估。
6. 第二学生在第一点部分回答后提前结束，重新登录恢复，再进行课后续学并再次结束。

## 问题判断与建议

### 1. 优先处理：教师生成正常重试仍不能修复失败页

**已观察到的缺陷。** 同一任务在第 4 页因两种聚焦/讲解错误连续失败，必须人工修订大纲并重新生成才能走完。校验拦截有依据；不能简单通过放宽校验解决。

建议先核对失败重试是否把具体校验反馈送回生成模型；针对“讲代码聚焦标题”“只报切换口令不讲内容”补失败页修复样例，并保留已经成功的页面。不要把本次两次失败扩大解释为整体生成成功率。

证据：`generation-first-failure.json`、`generation-second-failure.json`、`generation-status.json`。

### 2. 中等优先：编程题的首次任务直接给出核心解法

**实际输出问题，不是掌握状态故障。** 在学生第一次做循环任务前，导师已经要求使用 `for (i = 0; i < 5; i++)` 和 `a[i] = 2 * i + 1`，之后再要求写程序、列结果。它能检查学生是否理解、照着实现，却不足以验证学生能否独立确定边界与公式。

建议区分题目目标和评分参考：首次只给“定义 5 元素数组，用 for 填入 1、3、5、7、9 并检查结果”；学生卡住后再按需提供边界或公式。若本题定位就是带提示练习，则结果不要解释为独立编程能力已被验证。本次等价表达式被正确接受，不支持增加精确字符串匹配。

证据：`view-turn06.json`、`snapshot-turn08.json`。

### 3. 中等优先：课后续学原样重问整道题

**真实发生，但限于续学入口。** 第一个数组定义题已有部分掌握记录，进入课后时仍完整重复最初题目，包括已答对的元素个数等内容。状态没有丢失；问题在重新开场未围绕剩余缺口组织提问。不能把这一现象解释为课堂每轮仍然逐项重复。

建议保留原任务关联，但续学开场利用现有掌握/缺口记录，先确认已经答对的部分，只问剩余内容；不新增一套状态或帮助阶段。

证据：`early-before-exit.json`、`early-task-check.json`（sameOriginalQuestion=true）、`early-continued.json`。

### 4. 较低优先：回复 Markdown 与前端纯文本显示不匹配

真实回复包含加粗、反引号和 C 代码围栏；源码 `student_agent/frontend/src/components/StudentApp.js:254` 与 `:284` 直接输出 message.text，没有 Markdown 渲染。预期会显示原始标记。这一条由真实输出及源码确认，未在已登录的本次学生页面截图验收。

可选择安全渲染 Markdown，或者让模型输出适合纯文本气泡的内容；代码块可读性应单独验收。

### 5. 暂不扩大改造：标准存在重叠、部分解释较长

定义题分别列“元素个数”和“int a[5] 表示 5 个 int 元素”，循环题把目标、约束和成功条件累积成 7 项，确有重叠。但本次每点 2 次回答就完成，未观察到因此耗尽 5 轮，也没有出现答对后逐条逼问的课堂流程。先保留为提取标准去重的候选，不据此改变轮数或整套掌握规则。

定义题强调完整语法中的“存储类型”；导师同时正确解释 `int a[5];` 可以省略存储类型。本次未证明模型把这条合法 C 定义当作语法错误。若教学目标只要求会定义普通数组，是否必须背完整形式属于标准与课程目标的后续校准，不能仅凭这次部分回答断言评估错误。

## 未被本次证实的问题

- 没有复现“讲过就算学生会了”：求助解释后要求状态不变，后续由学生回答才掌握。
- 没有复现“未问内容被记为需要帮助”：提前退出时后 3 点均保持未评估。
- 没有复现“每讲一步强制复述一步”或“答对仍逐条追问”：正常课堂 8 答完成 4 点。
- 切点前有对上一点的简短确认；本次没有复现截图中学生要求解释却直接切换。没有覆盖“达到轮数上限时学生恰好追问”的边界，不能宣布该问题彻底消失。

## 限制与保留

- 大纲生成、后台课件生成均是真实入口，但测试脚本手工构造 stage，未完整复用前端 timing 归一化。最终 plannedDuration 为 45+45+50 秒，部分旁白出现省略号；这两项不能直接归因为标准教师 UI 的时长/截断缺陷，需要前端等价路径复测。
- 没有 C 编译器执行验证；代码正确性由模型语义评估与人工检查，不是编译运行通过。
- 只跑 2 个学生会话；未覆盖并发、服务重启恢复、网络中断、完整 5+8 轮和所有知识类型。
- 测试课程、账号和会话留在本地供回查；凭据仅存本地忽略目录，证据 JSON 按字段脱敏。

# 最新代码首轮 5 轮真实模型验证

## 范围与方法

Matt diagnosing-bugs 流程；先读项目 AGENTS（无根 CLAUDE），不改业务代码、已有测试、共享规划，不 commit。使用最新代码的真实命令 HTTP（FastAPI TestClient，经平台学习协议），实际临时 PostgreSQL 与真实配置模型；输入为人工设计的学生回答，不是动态模拟学生。

数据库复用 conftest 的隔离创建/迁移/销毁流程，独立数据库名，loopback:51080、student_p2_test 角色；未写入本地实际课程与用户数据。模型凭据只在进程内加载。三条会话均从真实首问开始，未伪造前四轮历史。

准备有两处脚本设置错误：兼容文本未使用 canonical compatibility_text、遗漏测试签名环境变量。均在真实模型调用前失败，随后修复脚本，不算产品故障。最终执行 `run.py` 退出 0。保留全部有效命令和状态 JSON。

**没有发现首轮5轮规则执行错误。** 纯提问计入5轮是既有程序规则，本轮只验证执行，不擅自修改政策。concept第5轮先答疑后换点；design第5轮先答疑后补强，不存在还没解释就硬切的本例失败。

## 真实残留问题及重要性

### 中：design 连续无进展时反复播放整份代码

首问正确仅给目标序列、数组长度与for要求，没有泄露边界/公式。但第1答“不会”后，导师已经给出完整 main、赋值循环、打印循环及结果；第2–4答仍不会时，没有有效澄清障碍，第4轮仍给整份代码和三段讲解，且第3/4轮实际回复逐字完全相同（脚本直接比较字符串确认）。这里并非首次出题泄露，而是帮助过宽、连续无进展时没有有效换教法。

证据：`design-reinforce-command-01.json` 至 `-04.json`，尤其 `-04`。学生只有不会，要求状态未因讲解变为掌握，故不是评估状态故障。

建议后续只针对现有 teaching_plan/pointConversation 的生成指令做定向试验：第一次含糊“不会”先定位卡点或示范最小一步；最近已给完整实现且学生无新表现时，不再给整份程序，改成一项尚未示范的局部操作或一个澄清问题。不新增阶段或状态，不增加轮数；用同一序列复测，不以禁止所有完整示范作为规则。

### 低到中：讲完答案后仍让学生复述刚示范的同一步

concept第3轮换柜子比喻后提出b[3]变式，第4轮把b[3]编号0、1、2和越界都完整说出，末尾又问“最后一个合法编号是几”。这是实际无进展对话中的重复帮助，并非退出后合理承接。memory第4轮把学生没确认的缺口称为“你卡在中间那一段”，但学生并未明确说只卡条件判断，应避免把诊断猜测当事实。

建议与上一项合并优化，不单独建立复杂状态。不要因为此语义问题扩大解释为5轮无法终止：本次三条都按时结束首轮。

## 限制

每类只有一个真实会话，不能估计发生率；concept/memory为手工构造规范化课程内容，design为已发布数组课时提取的真实归档知识点。没有重新生成教师课、浏览器验收、完整8轮补强、并发或服务重启；这些由其他子任务或后续负责。未跑编译器验证C代码。

# 补强8轮真实验证（2026-11-11）

## 结论

轮次/状态边界本例通过；教学质量存在中优先问题：连续无进展时反复长篇讲同一解法，未有效拆小或诊断卡点。不能把程序按8轮收尾当作教学整体通过。未改业务代码、测试或共享规划，未commit。

## 方法与诚实边界

- 来源为此前真实《第07章 数组》PPT发布短课的snapshot-turn07.json中的design点、学生错误代码和评估。沿用旧课时过细要求，不重新提取。
- 首轮5条是将其中一次真实错误评估人工复制成5条的seed，不是本次真实执行了5轮首轮。seed.json已明确说明。
- 本次真实执行了补强第1至第8次回答。前7次同sid完成；第8次前脚本deepcopy(session)遇到线程锁不能pickle。该脚本错误不算产品错误。
- 独立临时PG在finally清理。为完成第8次，从第7次真实dialogue快照恢复到新临时库、新sid；保留完整逐点question_history/assessment_history（学生原话完整），导入助手消息。不是无中断同sid连续全8轮。
- 重建快照时两次导入失败分别是旧消息task/episode和导入学生消息生成observation的关联校验，均在模型调用前失败。修正harness只导入助手消息；不改产品。错误不是模型或业务缺陷。
- 正向对照复用了这7次真实补强历史，再提交一次完整等价正确解作为第8次；没有声称正向对照独立跑了另7次。
- 通过实际命令HTTP、实际模型和真实隔离数据库，未替换模型响应；人工设计学生输入。没有访问/修改业务会话或重启共享服务。

## 功能结果

1. 补强计数从0逐次变为8，未超过8、没有因模型反复解释无限加轮。
2. 连续不知道或只复述已会的数组声明，没有被判mastered。已有数组声明和公式两项保持demonstrated，其他5项needs_help始终保留；解释没有产生掌握证据。注意本例seed已有全部剩余needs_help，不能据此声称覆盖了未考查unconfirmed不误标。
3. 第8次学生明确要求解释为什么i<=5越界。09-submit_answer.json里导师先直接答疑，再小结缺口，wrapup/rounds_exhausted，point仍partial。没有突然忽略问题，也没有“你已经都会了”。exhausted-check.json记录边界。
4. finish后反馈仍0掌握、1待巩固；continue_after_class进入remediation；第二次continue不增加消息（reentry-check.json=true）。课后退出后再次继续成功，要求状态仍不变。
5. 第8次改为完整正确等价解i+i+1，判断mastered、wrapup、reinforce_attempts=8；finish反馈1掌握。见16-submit_answer.json和correct-eighth-check.json。

## 实际问题与优先级

**中优先：无进展帮助变成越来越长的重复讲解。** 第1到7次回答后导师回复分别466、652、661、701、829、835、1019字符，反复解释0~4、i<5、逐项算出1/3/5/7/9，并多次完整展示for代码。虽然前几次换了“盒子/走格子”等比喻，但未从学生持续不会识别缺少哪一先修能力，也没有聚焦一个可完成小步。学生每次仍不会，模型却继续整段讲全解。这与“无效就换帮助”的预期有明显距离，不只是个别重复用词。

不建议因此再新增帮助阶段或放宽掌握标准。最小后续方向：生成时明确对比pointConversation最后一次实际帮助，若同一卡点无新表现，先问一个卡点定位问题或只示范一步，避免把整个数组结果和for模板再次全讲。已有教学记录足够，不需要再存一套状态。应用前应与主Agent其他场景共同审阅。

**低优先：课后重入重复长解释。** 11与14两次课后进入又讲同一边界与完整循环；不是整题重考或状态丢失，但对停滞学生帮助不大。可以和上项用相同的历史约束改善。

第8次末轮直接答疑再保留缺口是本例正确行为，应保留现有8轮上限与收尾，不建议为连续不会增加轮次。

## 证据及运行

01至08对应首次补强开场及7次真实答；09是快照恢复后的第8答；10至14是结束和课后续学；15是正向分支空操作start_discussion（没有模型调用），16为正确第8答，17为finish。

run-initial-error.py保留首轮脚本（完成7次后出现harness异常）；run.py为基于08快照的续跑脚本，读取已存证据，绝不重新挑选前7次输出。所有JSON保留原始输入、HTTP响应和dialogue，凭据不写入证据。

模型教学实际运行12次：初次补强开场1 + 7答 + 恢复后第8答1 + 课后开场2 + 正向第8答1。评估与自然回复内部可能不止一个provider请求，因此不把12称为provider HTTP请求数。

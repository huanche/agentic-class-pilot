# 学生端

目录分为 `frontend/`（Next.js 静态页面）、`backend/`（FastAPI）和 `agent/`（LangGraph 复述与讨论）。平台负责登录、选课码加入课程、课程选择及签发课堂令牌；本服务使用令牌读取当前学生已发布的课时。课后补完与自由提问已接入，全班讨论尚未接入。

`apps/` 仅保留服务器现有启动命令使用的兼容入口，教学功能在 `backend/` 和 `agent/`。本地启动脚本是根目录的 `start-platform.ps1`；`scripts/` 只存放服务器部署脚本。验证用例放在 `backend/tests/`，部署工作流会运行它们。

## 课堂流程

平台登录 → 使用选课码加入课程 → 选择课程 → 选择课时 → 教学视频 → 复述与讨论 → 本节课结束。点击“开始上课”后，Agent 只读取当前视频的画面文字和讲解旁白，从视频实际讲清的内容提取知识点。视频嵌入逻辑沿用旧版 `platform-player-adapter.js`。视频页面可直接点击“进入复述与讨论”；播放结束也会给出提示。

平台首次只下发课时目录。点击“开始上课”时，后端携带所选课时 ID 再请求平台，取得该课时的视频地址、画面文字和旁白；其他课时的正文不会进入本次会话。知识点整理随后在后台进行。

点击“开始上课”后，前端立即切换视频，后端先保存课堂与待处理资料，再在后台调用 `agent/knowledge.py` 整理知识点。模型处理不持有课堂锁，不阻塞播放器或状态读取。前端每两秒检查准备状态；完成后可进入讨论，失败可重试，视频仍可继续观看。待处理资料和准备状态保存到数据库，服务重启后读取课堂会重新调度未完成任务。

后台整理从视频画面文字和旁白提取可复述的概念、原理和方法，剔除纯导入、课堂安排、过渡和未解答的问题。模型返回视频中的概念名称和原文依据；后端校验名称和解释确实出现在视频材料中，知识点描述直接保存所引用的视频原文。模型调用或格式校验失败时允许重试；没有实质知识点时提示教师检查视频内容。旧会话在下一次进入讨论或发送消息时重新整理知识点，保留历史对话，重新评估新内容的掌握情况。

对话共用一个页面，开场列出完整清单，再从第一个知识点开始逐项引导。首轮每个知识点最多 8 轮学生发言，不会时先提示；掌握则提前进入下一点，达到上限则留到加强复述。首轮全部走完后，仅对薄弱点加强复述，每点最多 4 轮。首轮超过 5 轮仍未掌握的概念会标记为重点强化，第二阶段会换简单表述或类比重新讲解，再请学生复述。加强后仍未掌握的点记录待巩固，不再进入深入讨论或出题范围。没有任何掌握点时不再出题，提示结束查看反馈。

`agent/progression.py` 控制顺序和计数。首轮上限由 `STUDENT_AGENT_RECALL_ROUNDS` 配置（默认 8），加强阶段上限由 `STUDENT_AGENT_REINFORCE_ROUNDS` 配置（默认 4）；两个值范围均为 1–20。开始课堂时保存上限，刷新不会清零。每次学生针对当前点发送消息计一轮，包括求助和表示不会；模型请求失败不计轮数。旧会话保留已知掌握结果，首次使用新流程时初始化分阶段计数。

结束本课后，`agent/feedback.py` 依据本次实际评估生成逐知识点反馈，区分掌握较好、加强后掌握、仍需巩固、评估未完成和尚未评估。完成页可回看视频，也可进入课后 AI 对话。课后先逐项补完课堂未掌握的知识点；学生独立讲清后标记“课后补完”，全部补完后在同一对话框自由提问。当前反馈作为 `lesson_feedback` 事件写入 `student.learning_events`（`event_id=final`），课堂结束时的原始反馈另存为 `classroom_feedback`。反馈与会话快照仍写入数据库；默认从当前浏览器保存的记录恢复，刷新可继续学习，新的无痕窗口不会读取数据库旧记录。`GET /api/session/{sid}/feedback` 返回更新后的个人反馈。已有跨课次最高掌握度不用于替代本次课的实际结果。

新版本的开场文案、评估提示词、复述/补强/讨论提示词及各类对话策略统一维护在 `agent/prompts.py`；LangGraph 的状态跳转在 `agent/graph.py`。已保存的历史消息保留原文，新进入复述与讨论的课堂使用新的开场。

深入讨论对每个已掌握知识点各提出一个问题，学生回答后进入下一个点，全部完成后进入课堂总结。加强复述后仍未掌握的点不会进入讨论；学生只是求助时仍保留当前题目。每轮学生消息由 LangGraph 调用模型评估与生成回复，阶段跳转由代码规则执行。正式课程会话、消息、知识点掌握度和 Agent 状态快照分别写入平台数据库的 `student.student_sessions`、`student.student_messages`、`student.knowledge_mastery` 和 `student.learning_events`。服务默认只从当前浏览器记录恢复学习状态；如需恢复原来的数据库读取行为，可显式设置 `STUDENT_FRESH_SESSION_MODE=0`。

## 启动

在 `frontend/` 中运行 `npm install` 和 `npm run build`，然后在 `backend/` 中安装 `requirements.txt`。本地平台已配置时，从项目根目录运行：

```powershell
.\student_agent\start-platform.ps1
```

脚本从本机 `platform/.env` 读取服务密钥和数据库地址，并设置 `PLATFORM_AUTH_URL`，监听 `127.0.0.1:8001`。Agent 优先使用 `STUDENT_AGENT_API_KEY`、`STUDENT_AGENT_BASE_URL`、`STUDENT_AGENT_MODEL`；本地未设置时读取本目录 `.env.local` 中的 `AGENT_LLM_*` 配置，仍可用平台的 `LLM_API_KEY` 兜底。数据库可用 `STUDENT_DATABASE_URL` 覆盖。平台启动脚本将 `/app` 和 `/api/session` 转发到该服务。请从 `http://localhost:8088/login` 登录，在平台学生首页加入和选择课程，再点击“进入学习”。平台只为已选课且已发布的课程签发短期 `launch_token`。

若只想独立预览界面，可设置 `STUDENT_NEW_DEMO_PLAYER_URL` 为可嵌入的播放器地址，再手动启动后端。演示模式不连接平台，也不包含平台登录与选课。

构建时前端会输出到 `frontend/out`，由 FastAPI 同源挂载到 `/app`。演示模式无平台身份，仅使用进程内会话，不写入正式学习数据库。

服务器现有 `agentic-student` 服务可继续通过 `apps/server.py` 或 `apps/start.py` 入口运行新后端（生产端口 8000）；本机启动脚本使用 8001。这两个入口只负责加载配置和启动，不包含旧学生端的教学逻辑。GitHub 的学生端部署工作流会安装 `backend/requirements.txt`、构建 `frontend/out` 并检查新服务健康状态。

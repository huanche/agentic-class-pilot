# 学生端

目录分为 `frontend/`（Next.js 静态页面）、`backend/`（FastAPI）和 `agent/`（LangGraph 复述与讨论）。平台负责登录、选课码加入课程、课程选择及签发课堂令牌；本服务使用令牌读取当前学生已发布的课时。课后补完与自由提问已接入，全班讨论尚未接入。

`apps/` 仅保留服务器现有启动命令使用的兼容入口，教学功能在 `backend/` 和 `agent/`。本地启动脚本是根目录的 `start-platform.ps1`；`scripts/` 只存放服务器部署脚本。验证用例放在 `backend/tests/`，部署工作流会运行它们。

## 课堂流程

平台登录 → 使用选课码加入课程 → 选择课程 → 选择课时 → 教学视频 → 复述与讨论 → 本节课结束。教师发布视频时，平台登记该课时的视频版本和场景文字；学生服务后台提取知识点并保存到 `student.published_lesson_knowledge`。同一课时的学生读取这一份结果。视频嵌入逻辑沿用旧版 `platform-player-adapter.js`。视频页面可直接点击“进入复述与讨论”；播放结束也会给出提示。

平台首次只下发课时目录。点击“开始上课”时，后端携带所选课时 ID 再请求平台，取得该课时的视频地址、画面文字和旁白；其他课时的正文不会进入本次会话。旧课程在首次被选中时也会登记一次共享准备任务，供更新前已发布的视频使用。

教师发布后，学生服务从数据库领取准备任务并调用 `agent/knowledge.py`；失败自动重试，课堂页也可手动重试。学生开始上课时只读取当前视频版本的共享结果，不为每个学生调用一次模型。未准备好时可以观看视频，准备完成后进入复述与讨论；服务重启后继续处理未完成任务。演示模式仍在本地准备知识点。

部署时先执行平台迁移 `pub10_published_lesson_knowledge.py`，再更新教师端和学生端服务。三个 GitHub 自动部署工作流独立运行，发布这项跨服务改动时需要确保数据库迁移先完成。本机若已在下一版本分支执行过更高的 Alembic 修订号，可仅按本迁移创建任务表，保留现有迁移版本及数据。

后台整理从视频画面文字和旁白提取可复述的概念、原理和方法，剔除纯导入、课堂安排、过渡和未解答的问题。模型返回视频中的概念名称和原文依据；后端校验名称和解释确实出现在视频材料中，知识点描述直接保存所引用的视频原文。模型调用或格式校验失败时自动重试；没有实质知识点时提示教师检查视频内容。视频更新会产生独立的新版本知识点，不复用旧视频的提取结果。

对话共用一个页面，开场列出完整清单，再从第一个知识点开始逐项引导。首轮每个知识点最多 8 轮学生发言，不会时先提示；掌握则提前进入下一点，达到上限则留到加强复述。首轮全部走完后，加强复述处理未掌握的点，以及第 6～8 轮才掌握、仍需再确认一次的点，每点最多 4 轮。后者要在加强阶段独立解释一次概念，才能进入深入讨论。首轮超过 5 轮仍未掌握的概念会标记为重点强化，第二阶段会换简单表述或类比重新讲解，再请学生复述。加强后仍未掌握的点记录待巩固，不再进入深入讨论或出题范围。没有任何掌握点时不再出题，提示结束查看反馈。

`agent/progression.py` 控制顺序和计数。首轮上限由 `STUDENT_AGENT_RECALL_ROUNDS` 配置（默认 8），加强阶段上限由 `STUDENT_AGENT_REINFORCE_ROUNDS` 配置（默认 4）；两个值范围均为 1–20。开始课堂时保存上限，刷新不会清零。每次学生针对当前点发送消息计一轮，包括求助和表示不会；模型请求失败不计轮数。旧会话保留已知掌握结果，首次使用新流程时初始化分阶段计数。

结束本课后，`agent/feedback.py` 依据本次实际评估生成逐知识点反馈，区分掌握较好、加强后掌握、仍需巩固、评估未完成和尚未评估。初始与加强复述的概念掌握结果和深入讨论的应用题结果分别记录；讨论题答错不会抹掉先前的概念掌握，反馈会同时显示概念掌握依据和讨论题待巩固的依据。完成页可回看视频，也可进入课后 AI 对话。课后按待办队列继续概念复述、加强确认和未完成的讨论题，所有任务完成后才进入自由提问；学生独立讲清后标记“课后补完”，全部补完后在同一对话框自由提问。当前反馈作为 `lesson_feedback` 事件写入 `student.learning_events`（`event_id=final`），课堂结束时的原始反馈另存为 `classroom_feedback`。反馈与会话快照仍写入数据库；有浏览器记录时先验证记录并读取数据库中的最新课时会话，没有浏览器记录时在选择课时后读取数据库中的旧会话，恢复前检查当前用户、课程和视频版本。`GET /api/session/{sid}/feedback` 返回更新后的个人反馈。已有跨课次最高掌握度不用于替代本次课的实际结果。

新版本的开场文案、评估提示词、复述/补强/讨论提示词及各类对话策略统一维护在 `agent/prompts.py`；LangGraph 的状态跳转在 `agent/graph.py`。已保存的历史消息保留原文，新进入复述与讨论的课堂使用新的开场。

深入讨论对每个已掌握知识点各提出一个问题，只有当前题答对才进入下一个点；回答不完整、答错、表示不会或求助时，导师围绕原题提示，仍保留当前讨论题。最后一题答对后先给出简短反馈，再进入课堂总结。学生可主动提前结束，状态快照和个人反馈会记录提前结束及未完成的讨论题。加强复述后仍未掌握的点不会进入讨论。每轮学生消息由 LangGraph 调用模型评估与生成回复，阶段跳转由代码规则执行。正式课程会话、消息、知识点掌握度和 Agent 状态快照分别写入平台数据库的 `student.student_sessions`、`student.student_messages`、`student.knowledge_mastery` 和 `student.learning_events`。服务默认先检查当前浏览器记录，再读取数据库中的最新课时会话；没有浏览器记录时，也会在选择课时后读取数据库中的旧会话。`STUDENT_FRESH_SESSION_MODE=1` 仍控制浏览器快照和普通会话接口的恢复方式；数据库恢复仅在验证平台身份与所选课时后执行。

本节课结束页提供“重置本课学习进度”。确认后，后端按当前平台身份只删除这名学生这一课时的会话、消息、知识点掌握度与反馈，并同步教师端进度；浏览器删除本课快照，旧快照也不能恢复已删除的数据。其他课时保持原样，页面返回未学习的课时列表。

## 启动

教师重新发布同一课时的视频后，学生点击进入或恢复该课时时检查一次课堂 ID、发布时间及场景内容；更新时清除该会话的旧消息、评估、反馈和播放记录，并从新版视频重新开始。学习过程中不定时检查，提交回答和结束课堂也不额外检查。清理只针对当前学生的当前会话，其他课时不受影响。平台暂时不可用时保留原记录；旧版知识点整理任务不会覆盖新版课堂。

在 `frontend/` 中运行 `npm install` 和 `npm run build`，然后在 `backend/` 中安装 `requirements.txt`。本地平台已配置时，从项目根目录运行：

```powershell
.\student_agent\start-platform.ps1
```

脚本从本机 `platform/.env` 读取服务密钥和数据库地址，并设置 `PLATFORM_AUTH_URL`，监听 `127.0.0.1:8001`。Agent 优先使用 `STUDENT_AGENT_API_KEY`、`STUDENT_AGENT_BASE_URL`、`STUDENT_AGENT_MODEL`；本地未设置时读取本目录 `.env.local` 中的 `AGENT_LLM_*` 配置，仍可用平台的 `LLM_API_KEY` 兜底。数据库可用 `STUDENT_DATABASE_URL` 覆盖。平台启动脚本将 `/app` 和 `/api/session` 转发到该服务。请从 `http://localhost:8088/login` 登录，在平台学生首页加入和选择课程，再点击“进入学习”。平台只为已选课且已发布的课程签发短期 `launch_token`。

若只想独立预览界面，可设置 `STUDENT_NEW_DEMO_PLAYER_URL` 为可嵌入的播放器地址，再手动启动后端。演示模式不连接平台，也不包含平台登录与选课。

构建时前端会输出到 `frontend/out`，由 FastAPI 同源挂载到 `/app`。演示模式无平台身份，仅使用进程内会话，不写入正式学习数据库。

服务器现有 `agentic-student` 服务可继续通过 `apps/server.py` 或 `apps/start.py` 入口运行新后端（生产端口 8000）；本机启动脚本使用 8001。这两个入口只负责加载配置和启动，不包含旧学生端的教学逻辑。GitHub 的学生端部署工作流会安装 `backend/requirements.txt`、构建 `frontend/out` 并检查新服务健康状态。

## 回看验证

恢复课时时，课时列表使用目录摘要，当前课时使用恢复记录里的完整播放信息。如果回看地址缺失或播放器报错，可通过 `POST /api/session/{sid}/playback` 重新获取当前课时的播放信息；该接口校验学生、课程、发布版本和课堂绑定，不重启学习，也不修改反馈或对话。

后端验证：`python -m pytest -q student_agent/backend/tests`。浏览器回归验证在 `frontend/` 中运行 `npm ci`、`npx playwright install chromium --only-shell` 和 `npm run test:e2e`。浏览器用例使用模拟接口，覆盖直接回看、返回列表后恢复、从平台重新进入、缺失地址、失败重试及反馈与课后对话保留，不连接正式数据库。

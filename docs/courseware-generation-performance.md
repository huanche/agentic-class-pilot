# 课件生成流水线与耗时记录

后台课件使用有限的画面预生成，并让后一页讲解规划与前一页配音重叠。模型选择、生成提示词、聚焦语义审核、逐页和整课时长校正规则保持原有路径。

后一页使用的上一页讲稿若在校时后改变，后台会等待上一页定稿，并基于最终讲稿重新规划后一页。通过审核、完成配音和校时的页面才写入课件检查点。取消会中止预生成和配音；已有检查点和音频保留。

## 配置与回退

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `COURSEWARE_PIPELINE_ENABLED` | `true` | 设为 `false` 恢复原有逐页串行顺序 |
| `COURSEWARE_CONTENT_PREFETCH` | `2` | 画面预生成窗口，限制为 1–3 页 |
| `TTS_AUDIO_CACHE_ENABLED` | `true` | 设为 `false` 禁用音频缓存，用于冷启动基准或回退 |
| `TTS_AUDIO_CACHE_DIR` | 课堂数据目录旁的 `tts-audio-cache` | 缓存目录，须位于受保护的服务数据卷 |
| `TTS_AUDIO_CACHE_MAX_BYTES` | 256 MiB | 缓存清理目标；写入后最多每分钟清理一次，活跃写入不会被清理 |
| `TTS_AUDIO_CACHE_VERSION` | `1` | 同名模型权重或音色被替换时递增，避免继续命中旧版本 |

缓存有效期为 7 天。键包含教师范围、完整文字、提供商、模型、服务地址、音色、语速和提供商参数，以及凭据的不可逆指纹。文件名和元数据不保存讲稿或密钥。读取时验证文件长度、摘要和可解码时长；错误、取消或损坏的结果不会作为有效缓存命中。缓存不可用时仍执行原有语音合成。相同的并发合成可以共享；取消某个等待者不会取消其他等待者。

## 查看记录

任务记录页的“本次运行耗时”默认折叠，显示各阶段、首个完整页面耗时和缓存计数。范围从确认大纲、提交后台任务后开始，不计教师阅读确认的等待时间，也不包含此前的上传、OCR 和大纲生成。`backgroundGeneration.performance` 随任务保存；执行中每 10 秒更新。每次运行结束还会追加到 `CLASSROOM_JOBS_DATA_DIR/<jobId>.performance.jsonl`，保留失败、取消和显式重试的记录。

`elapsedMs` 是本次运行实际经过的时间；阶段累计时间包含失败尝试，并可能重叠。讲解和校验合计包含讲解规划与聚焦审核；校时阶段也会调用讲解和配音。不能把阶段时间相加当成总耗时。合成请求计数包含失败请求，缓存命中不计作新的提供商语音合成用量。

## 本地对照验证

常规生成测试最多使用 5 页，以幻灯片为主。优先使用“3 页幻灯片 + 1 页互动 + 1 页测验”；需要覆盖全部四种内容类型时，使用“2 页幻灯片 + 1 页互动 + 1 页测验 + 1 页项目活动”。沿用同一份原稿，互动需实际操作，测验需检查答案与每题 5 分钟限制，所有有讲解的页面都要验证配音。小样本的目标讲解时长应随范围缩短；不用整节课的长时长填充 5 页，也不降低模型和质量校验标准。

1. 固定同一 PPT 的 SHA-256、识别内容、已确认大纲、目标时长、模型及语音设置，使用新的测试课堂编号。
2. 原流程关闭流水线和缓存；优化流程使用空缓存测冷启动。独立记录总耗时、首个完整页面耗时、模型调用、审核失败、校时重做和 TTS 时间。
3. 已定稿的同一组讲稿再做一次配音，验证缓存命中及字节一致性；缓存热测试不能代替整课冷启动对照。
4. 两份输出检查页序、知识覆盖、公式与代码、讲解聚焦匹配、每段音频可读、实际播放时长及代表性页面视觉效果。质量审核失败仍走原有失败/显式重试流程。
5. 同时运行的其他生成或 CPU 密集任务会干扰基准；比较记录需保留运行范围和重试次数。真实模型输出存在波动，单次耗时差异不应承诺为固定加速倍数。

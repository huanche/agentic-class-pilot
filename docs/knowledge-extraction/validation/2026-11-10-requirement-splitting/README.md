# 要求拆分提示词：真实入口验证

2026-11-10。按用户确认，仅通过`learning_points`完整提取入口验证，不接后续教学。采用Matt TDD的公开行为测试原则，不以“提示词包含某句话”证明效果。提示词已先修改，本次不冒称测试先于修改或完成新功能Red→Green。

## 结果

| 固定输入 | 旧提示词 | 新提示词 |
| --- | --- | --- |
| 200成功、404资源未找到两个独立事实 | 分开 | 分开 |
| 留一个空位为什么能区分空满 | 保留因果关系 | 保留因果关系 |
| 行编辑的退格与清整行两个构造目标 | 分开 | 分开 |
| 原真实栈队列课时的链队列要求 | 仍混合 | 仍混合 |

**这批样例没有证明新提示词带来了改善。** 自动样例冒烟检查新旧各3通过、1失败；人工复核也确认关键失败：新输出仍是“说明入队只在rear之后插入，因此没有队满问题”。原课本身也用“所以”连接两者，本次规则未能使模型拆开，不能把结构通过当语义通过。

另一个人工发现：两版都把输入的“本课未讲重做”转换成“不实现／不涉及重做功能”的约束。未教某功能，不等于作品必须禁止它。独立目标拆开测试虽通过，该样例整体仍有语义风险。

## 怎么验证的

- 新增显式开启的真实模型测试`student_agent/backend/tests/test_extraction_requirements_live.py`。入口内部照常执行真实Agent、工具校验和编译；没有mock内部模型工厂，没有预写返回值。
- 模型为本机既有配置deepseek-v4-flash。旧版文本来自HEAD（71b40da），新版来自当前未提交提示词；只在外部HTTP边界切换system文本，响应不注入、不修改。每对材料指纹一致。
- 断言针对固定样例，使用状态码／领域词检查要求是否同条，存在措辞覆盖限制；因此又人工阅读所有details。它不是生产校验规则或通用语义评分器。
- 每个样例每版只保留一次成功返回，不足以形成统计结论。此前网络失败和脚本设置失败都独立留档，不覆盖、不算内容判断失败。
- 合计8次成功服务商返回；另有5次网络尝试未得到成功响应（超时/TLS），无法用于内容对照。最早4次脚本HTTP库类型不兼容，未发出请求，修正脚本后才继续。

原27项提取兼容测试仍通过；新增4项真实测试默认跳过，显式开启后得到上述结果。此次没有继续改提示词、业务代码或字段，没有部署、提交、数据库写入或正式发布。

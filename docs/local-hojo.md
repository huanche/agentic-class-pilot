# 本地 Hojo 语音与课件生成入口

教师工作区“生成课件”可选择高保真还原或 AI 增强。高保真需要单份原始 PPTX，读取原文件并保留画布和原始页序；AI 增强可依据多份解析资料重新组织内容。单份 PPTX 的两个入口均先进入提取内容确认，再生成大纲。

大纲上方“本节课概述”随同大纲在同一次模型调用中生成，不增加独立模型调用；若模型未返回概述，则按实际大纲主题、知识点汇总。教师修改后点击“重新生成本节课大纲”，沿用原资料、课时、时长与转换模式。重生成失败保留旧大纲；修改后的概述尚未应用时，确认生成按钮禁用。再次修订使用原始要求加最新概述，避免旧版本指令重复叠加。

## 启动本地语音

在仓库根目录运行：

```powershell
.\start-hojo-local.ps1 -Models both -Threads 4
```

仅需要固定音色时，使用 `-Models 40m`。依赖、权重、音色样本与日志均写入 `teacher_agent/.runtime/hojo-local/`；不会提交 Git。脚本固定官方代码版本，记录模型仓库版本与文件 SHA-256，并保存上游许可证。

在 `teacher_agent/.env.local` 中加入：

```dotenv
TTS_HOJO_BASE_URL=http://127.0.0.1:13306/v1
TTS_HOJO_ENABLED=true
```

重启本地教师服务后，在外围“设置 → 语音合成 → Hojo TTS（本地）”选择模型和音色。40M 提供 2 个中文、13 个英文固定音色；80M 提供官方中文参考音色，并可上传 1～30 秒参考音频创建克隆音色。克隆录音保存在当前 Hojo 服务的 runtime 目录，换服务后需重新添加。试听和正式后台任务都会携带选定的模型与音色。

保持 `TTS_HOJO_MODELS` 未设置可按任务选择 40M 或 80M。若运营方设置此变量，沿用现有服务端模型固定策略。Kokoro 选项继续可用，接入 Hojo 不会自动修改旧课件配音。

服务仅监听 `127.0.0.1:13306`，可用 `HOJO_API_KEY` 保护本地接口。仅输出原速 PCM WAV；播放倍速由现有课件播放器控制。模型在进程内保温、推理串行化，切换模型时卸载上一模型。长文本按句子与单词边界分段，保留完整文本；每段音频正常后才返回，仍交给课件原有音频缓存和时长实测逻辑。

## 实测与资源

官方参考数据并非所有 CPU 的速度承诺。[40M 官方说明](https://github.com/HojoAI/Hojo-TTS-Light/blob/main/Hojo-TTS-Light-40M/README.md) 给出的短句 CPU RTF 约 0.71（1 线程）/0.28（20 线程），长段落约 1.02/0.59，RSS 约 750 MB～1.2 GB。磁盘包大小不代表运行内存，云端启用前应单独测试资源容量。

2026-10-23 Windows 本机 4 线程功能冒烟中，36 字中英混读：40M 冷启动约 9.65 秒生成 6.98 秒音频；后续一次约 11.07 秒。80M 官方音色冷启动约 34.33 秒生成 6.70 秒音频。这些测试与开发编译同时运行，不作为稳定性能基准，也未达到用户引用的 RTF 0.23。经教师服务的 80M 克隆接口使用合成音频作为参考，已成功注册并生成可解码 WAV；不代表真人音色相似度已评测。

原始记录位于本机 `teacher_agent/.runtime/hojo-local-20261023/`。本次接入先验证本地功能，不自动部署云服务器或改变云端默认配音。

官方来源：[40M 模型](https://huggingface.co/HojoAI/Hojo-TTS-Light-40M)、[80M 模型](https://huggingface.co/HojoAI/Hojo-TTS-Light)、[Apache-2.0 源码](https://github.com/HojoAI/Hojo-TTS-Light)。

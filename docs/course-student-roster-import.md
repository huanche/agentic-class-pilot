# 教师端学生名单导入

## 使用流程

授课管理页“学生与学习状态”右上角点击“上传学生名单”，选择文字版 PDF（最多 10 MB、50 页、2000 人）。预览提取的学号、姓名、专业、年级、性别，补充或纠正字段后确认关联并保存。

系统只建议关联本课程已选课且注册姓名唯一匹配的账号。重名或昵称由教师手动选择，未注册或未选课者可暂不关联。当前注册系统没有独立 username 字段，匹配使用注册姓名 full_name；下拉框同时显示邮箱便于区分。再次打开按钮可管理待关联名单。

资料按课程保存，点击已关联学生卡片，在学习详情页查看真实姓名、注册名称、年级、学号、专业、性别及原有学习统计。资料导入不创建账号，不自动选课，不修改全局账号资料或学习评估。

重复上传以课程和学号定位记录，保留原有账号关联、手动补充的年级和本次未包含的历史记录；变化列显示原信息供核对。确认保存才写入。多人编辑期间若名单已变化，保存返回冲突，须重新打开核对。

## PDF 支持范围

支持有“学号”“姓名”表头的文字表格，按列位置和学号行提取，支持跨行姓名。扫描图片、加密文件及无法识别的排版会显示解析错误，不以空名单冒充成功。没有年级字段时留空，不从学号猜测。PDF 在教师服务内解析，不调用外部模型，也不保存原 PDF。

## 上线与数据影响

新增平台迁移 `roster15`，前置版本 `roster14`。升级仅创建 `course_student_profile` 表，包含课程、学号、姓名、专业、年级、性别和关联账号；不 UPDATE、DELETE 或覆盖已有用户、课程、选课、成绩或评估数据。

发布前须确认平台当前迁移版本并备份数据库。在审核并批准后，由平台部署流程执行迁移到 `roster15`，随后发布相匹配的平台 API 和教师端代码。不能先发布依赖新表的 API 再补迁移。若数据库低于 `roster14`，须另行审查其间迁移；不能把升级到 head 视作只新增此表。

本次开发未迁移本地业务数据库，也未操作云端数据库。数据库验证仅在独立测试服务器创建随机临时数据库，测试后删除。

回滚应用时可保留新表；不要执行 `roster15` 的 downgrade，除非已明确批准删除已导入名单。回滚迁移会删除该表中的名单资料。

上线验收：有权教师上传、预览和保存；无权教师拒绝访问；重名/昵称人工关联；重复上传保留历史名单；点击学生显示五项身份资料；学生原有课程进度和评估保持一致。

## 验证入口

- 教师端：`tests/server/student-roster-pdf.test.ts`、`student-roster-route.test.ts`、`class-roster-route.test.ts`。
- 可选实际 PDF 验证：设置 `ROSTER_PDF_FIXTURE` 后运行 PDF 测试；不将学生名单或解析出的个人资料提交仓库。
- 数据库：根目录 `tests/test_course_student_profiles.py`，须显式设置指向隔离测试服务器的 `ROSTER_TEST_DATABASE_URL`；测试新建独立临时库，不使用现有业务库。
- 契约：`scripts/check_integration_contracts.py`、`scripts/generate_integration_clients.py --check`。

# 课件生成耗时与并行配置

课件的生成耗时和播放时长是两项指标。当前生成流程包含页面内容、讲稿与聚焦目标共同生成、独立校验、TTS 实测以及最多两轮时长校正；等待这些请求不会增加学生听到的课程时长。

## 当前可用的提速方式

服务器设置 `PARALLEL_SCENE_CONCURRENCY=2`，即可启用项目已有的有界流水线：

- 提前请求后续页面的内容，按大纲顺序消费结果，不等所有页面返回才显示第一页。
- 同一页最多两段讲稿同时配音，各自保存音频引用，按原有动作顺序播放。
- 页面组装、讲稿与聚焦校验、时长校正继续执行；模型、语速和教学内容深度保持原配置。

这只能缩短可重叠的请求等待。单个模型请求、供应商超时和必要的校正仍需要时间，不能承诺固定的总生成秒数。

## 配音账户不可用时

Qwen 返回 `Arrearage`、无效密钥等明确的账户错误时，API 返回不可重试的账户错误，页面暂停生成。串行时不再请求后续讲稿；并行时不再启动排队的讲稿，并等待已在途请求结束后统一清理本页临时音频，避免把部分配音页面误报为完成。已保存的完整页面保留。临时网络错误及 HTTP 429 限流仍使用现有退避重试。

账户恢复后通过失败页面的重试入口继续。代码修复不会恢复欠费账户的服务额度。

## 运维切换与回退

使用 `generation-concurrency-tuning` 工作流：

1. `apply=false` 只检查线上并发配置和模型，不重启。
2. 在课件页面已保存的边界运行 `apply=true, concurrency=2`。工作流备份私有环境文件，以原镜像重建容器并执行健康检查；健康或配置检查失败时恢复环境文件和原镜像。
3. 页面刷新后从已保存的页继续生成。刷新会丢弃当时未完成页面的请求，因此不要在长请求中间反复刷新。
4. 若供应商出现持续限流或错误，运行 `apply=true, concurrency=0`，恢复串行流程。原始环境文件的私有备份仍保留在服务器，不上传为 CI 产物。

工作流不会输出 API Key，不修改课件 JSON，不重新生成已保存页面，也不会发布到班级。

## 验证

`teacher_agent/tests/hooks/use-scene-generator-retry.test.ts` 覆盖两个并行请求的上限、乱序完成后讲稿/音频/聚焦绑定保持原序、取消时等待在途请求并回收音频。`tests/server/provider-config.test.ts` 覆盖配置读取、关闭和上限约束。

上线后还应检查实际日志中的重叠请求、供应商错误、已保存页面数以及每段讲稿对应音频文件是否齐全。以真实页面耗时评估效果，不能把单元测试中的并行能力当作线上提速比例。

# 知识点怎么教

已在本工作树实现，未部署。2026-11-05。验证范围见[实施记录](implementation.md)。

**程序决定教哪个知识点、什么时候换点和结束；Agent 负责当前点怎么问、怎么追问，以及判断学生是否掌握。**

## 1. 先把内容和进度存好

State 就是一份随对话保存的学习记录，里面放：

- 本课知识点，按原来的顺序排列；每个点带着 type 和具体内容。
- 每个点的掌握情况、判断依据、学生之前的回答和已用轮数。
- 每个点已经会的部分、剩余缺口、已经给过的帮助，以及帮助后学生的表现。
- 当前阶段、正在回答的题目，以及对话记录。

程序根据这些记录选出当前知识点。刷新或重新进入时接着学，不重新计数。原来的题目也要保留，尤其是 design，不能追问到一半换了题。

这些记录每轮更新，不等首轮结束才总结。学生原话和实际给过的帮助单独保留；“已经会什么、还缺什么”是 Agent 的判断，不能当作学生原话。

## 2. 三种类型，问法和掌握依据不同

| 类型 | 怎么问、怎么追问 | 什么时候算掌握 |
| --- | --- | --- |
| memory：记住 | 请学生回忆；少说了什么，就追问什么 | 必要内容准确，允许换一种说法 |
| concept：理解 | 请学生解释原因、关系或过程；哪里没讲清，就追问理由或推演 | 能讲清关键关系，不能只报结论 |
| design：做出来 | 给一个具体任务；围绕学生的结果，追问或帮助修正 | 实际做出的结果和过程符合要求，接受不同正确做法 |

依据直接使用知识点已有字段：memory 的 requiredElements、concept 的 understandingPoints，以及 design 的 capability、constraints、successCriteria，不另加评分标准。

每轮只问一个主要问题。允许学生分几轮说清；不要重复问已经答对的部分，也不要把“懂了”或照抄 AI 答案当作掌握。

提示后能自己答出来、解释清楚，或者自己修正作品并说明原因，就可以算掌握，不需要额外出一道题确认。

memory 的正确答案可能和提示措辞相同，不能只因说法相同就判为照抄；要结合提示给出了多少、学生自己补出了什么判断，不额外要求解释原因。

## 3. 学生回答后，一次 Agent 运行做完这一轮

1. **程序准备材料。** 给 Agent 当前知识点、对应的教学提示词、原题和学生回答。
2. **Agent 评估并调用工具。** 告诉工具：已经掌握、只掌握部分、存在误解，还是明确不会，并说明依据；单纯提问或说不清时，也如实提交。
3. **工具执行程序规则。** 更新当前点的学习记录、增加本轮计数，再由程序决定继续当前点、换到下一点、进入加强阶段，还是总结。
4. **Agent 根据工具结果回复。** 继续当前点就追问缺口；换点就先反馈上一回答，再按新点的 type 提问；进入总结就不再出题。
5. **程序一起保存本轮结果。** 回复成功后保存进度、题目和对话，再等待学生下一次回答。

这是一次 Agent 运行，内部通常会请求模型两次：先提交工具，再根据工具结果回复。工具只执行程序逻辑，不再调用模型评估，也不负责写教学回复。

例如，学生说“Push 是插入，Pop 是删除”：Agent 判断还缺操作位置，通过工具记录“部分掌握”；程序决定继续当前点；Agent 再问“这两种操作发生在栈的什么位置？”

工具不能让 Agent 自选下一点或修改轮数。同一条回答只计一次，回复失败不先扣轮数。首次开场没有学生回答，直接生成第一问，不做虚构评估。

## 4. 按固定顺序推进，保留轮数限制

新建三类型课时会话使用：**首轮逐点教学 → 只补强未掌握点 → 总结。** 取消统一的深入讨论阶段。

- 首轮每点最多 5 轮；已经掌握可以提前换点，不要求问满。
- 首轮全部走完后，按原顺序补强未掌握点，每点最多 8 轮，掌握后提前换点。
- 首轮已经掌握的点不再回头确认；补强结束仍未掌握，就记录待巩固。
- 最后一轮答对仍按掌握处理；求助、不会也计一轮，模型失败不计轮数。

一轮指一次成功处理的学生输入，不是一次模型调用。新会话按 5/8 轮执行；旧会话保留原来的 8/4 轮和阶段。

首轮按类型开展教学：memory 回忆、concept 解释、design 实际构造，不要求 design 先背概念才能开始做题。

## 5. 补强从缺口接着教

进入补强时，Agent 读取原题、学生回答、已会部分、剩余缺口和已给帮助，不重新从头问。

例如学生已知道 Push 是插入、Pop 是删除，但仍误认为发生在两端，就直接围绕操作位置解释、追问，不再问 Push/Pop 的含义。

memory 补遗漏或混淆的事实；concept 换例子解释没懂的关系；design 保留原题和学生方案，从出错或没完成的步骤继续。之前的提示没有效果，就换解释方式或示范必要的一小步，不重复同一句提示。记录不清楚时先针对性澄清，不重启整道题。

学生回答后更新缺口，已经解决的部分不再追问。本次课堂补强最多用完 8 轮，不再开启新一轮补强；课后可由学生主动继续。

## 6. 什么时候结束

目标是全部掌握，但不能为了达到目标一直问下去。

首轮全部掌握就进入总结；否则补强未掌握点，补强走完后进入总结。最后仍通过“结束本课”保存反馈，分清已掌握和待巩固的点。**课堂结束不代表全部掌握。** 课后继续未完成的知识点，也使用相应 type 的教学方式，不再为新流程生成统一深入讨论的待办。

## 7. 总结让学生看到什么

先用一句话说明已掌握和待巩固的知识点数量，再分两部分列出：

| 部分 | 每个点写什么 | 示例 |
| --- | --- | --- |
| 已掌握 | 具体能说清或完成什么 | “你能说明 Push、Pop 的作用，以及它们都在栈顶进行。” |
| 待巩固 | 已会部分、剩余缺口、一个具体的下一步建议 | “你能写出操作序列，但有一步取走了非栈顶元素。下次从这一步继续，每次 Pop 前先标出栈顶。” |

反馈只整理 State 中已有的表现和缺口，不重新评分。提示后自己答清楚的也归为已掌握，不另分低等级；记录不足就写“本次尚未确认”，不说学生不会。**不展示分数、星级和轮数。**

“本次尚未确认”放在待巩固区单独注明，不编造具体错误。学生提前结束时，没有学到的点标“尚未学习／评估”，单独列出和计数，不当作已经发现缺口的点。

## 8. 课后怎么继续、怎么退出

学生点击“继续巩固”后，程序按原顺序选择未完成的点，Agent 按正常教学方式引导：有原题和缺口就接着教，尚未学习的点从第一问开始。课堂用完轮数不妨碍课后继续。

课后提供随时退出的按钮，退出保留进度，不算全部掌握；下次进入接着学。全部知识点掌握后结束引导、更新反馈，不强制再考。已全部掌握时再点击入口，只提示“本课知识点已全部掌握”，不重新出题。

旧会话不自动切换到新流程；没有类型的旧知识点继续原教学方式。已有[一节真实课时的模型实测](validation/2026-11-06-live-model/README.md)，并对追问重复和切点问题完成[原因定位与回放修复](validation/2026-11-06-reply-fixes/README.md)；回放结果不代表所有会话质量。

# 自动绕回误解：初次尝试

真实导师和独立学生角色均为deepseek-v4-flash。原真实课时两个concept点，业务代码未改，无数据库、未部署。

结果：4次已提交输入、13次真实模型请求（导师9、学生4），两点均被程序记为掌握。**这不等于达标。**

## 实际缺陷

- 导师第1次回复说“(8+1)%8，也就是0号位置”，算术错误；学生第2答提出正确结果为1。第2次工具known_parts仍写“能算出(8+1)%8=0”，同一评估的gaps却写正确结果为1，记录自相矛盾。
- 第3答只说明假溢出成因和绕回，导师便将整个循环队列判掌握；完全没有问队空、队满、预留空位，也没有学生表现证明这些understandingPoints。
- 第4答只讲动态结点和内存是否够用，链队列便被判掌握；没有评估front/rear和出队前判空。
- 未形成连续重复追问，但这是提前结束导致的，不能据此称教学通过。

学生角色在第3答已接受提示，未持续保留原设误解，未触发5/8上限或补强。该场景未充分施压；另保留更严格变体persistent_wrap。

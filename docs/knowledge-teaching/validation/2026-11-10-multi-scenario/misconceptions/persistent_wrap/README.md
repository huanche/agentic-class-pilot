# 更严格持续误解变体：实际进入补强

保留初次人设未充分持续的场景，另开此变体。学生仍每轮读取最新提问动态作答，但设定保留“普通队列也自动绕回、front==rear可以表示满、空队可直接删除”的错误认知。未指定导师应该判什么结果。实际学生仍会部分学会，不能称模拟了永远不会的学生。

真实请求29次（导师20、学生9），8次学生作答提交成功；第9次在生成总结时失败。未部署、无数据库，业务代码未改。

## 实际覆盖

- 循环队列首轮5次仍partial，程序按限额切到链队列，没有因旧点仍有缺口而继续占用首轮。
- 链队列第1答说空结点可直接删，被识别为misconception；导师解释NULL与最后一个结点，学生第2答说明先判空和rear置空，被判掌握。
- 然后回到循环队列补强，引用原先front=3/rear=2的缺口，未从假溢出定义重新问起。
- 第1次补强学生能写条件但仍质疑为何留空位，保持partial；导师用if判空/判满对照澄清。这些问法有相似主题，但不是原先整段照念的重复循环。
- 第2次补强学生自己说明相等时无法分辨空满、需额外计数器或标志位，工具判mastered；随后模型直接输出普通中文而非JSON，入口失败。完整原文与工具参数都保留。
- 失败轮未提交：循环队列仍partial，recall_attempts=5、reinforce_attempts=1。未实际覆盖补强8次上限，不能称全边界通过。

## 仍发现的问题

导师在第2–3次提问中把普通队列的非法rear=8继续代入循环队列状态，计算后称其“一般状态”，并描述再入队rear变成1。下标范围为0~7时rear=8不应当作合法循环指针状态；讲解混淆了普通队列的越界示例与循环队列的不变量。没有追加校验或改业务规则掩盖此问题。

这场主要验证到首轮限额、错误识别、补强承接和失败不计数；格式稳定性未通过。

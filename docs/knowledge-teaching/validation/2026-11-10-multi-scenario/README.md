# 多子Agent困难场景实测

2026-11-10。按用户要求，3个子Agent并行运行困难学生，主Agent检查恢复与故障重试。原课循环队列/链队列两个concept点，原业务代码，真实deepseek-v4-flash。学生逐轮读取真实导师最新问题，独立上下文，不看导师State或标准答案。

**结论：不能把此前happy path的完成当成教学可靠。** 本批12个有效会话中，6个自然发生格式错误而中断；另6个虽流程完成，也普遍存在只答局部便判整个知识点掌握。仍有计算和指针约定错误。

后续已核对代码与原课时，并做离线单变量重放：[场景、结果与原因](causes.md)。仅诊断，尚未修复。

## 暴露的问题

1. **把一小问答对当整个点掌握。** 例如只答假溢出，就跳过循环绕回、队空队满；只答链式入队，就跳过出队判空。甚至工具明确提交mastered并同时列出剩余gaps，程序仍按mastered推进、清空gaps。
2. **最终总结不按JSON返回，导致整轮失败。** 6个样本都有实际输出原文，失败前后State保持一致，候选评估没有偷偷保存。这次已拿到此前偶发格式错误缺失的现场。
3. **讲解和判答本身出错。** 有“(8+1)%8=0”“(7+1)%8=3”等错误；还混淆“rear是当前待写位置”和“写入后rear更新位置”。源知识点的“下次入队位置”表述也需与同课约定一起核对，不能只靠改回复措辞。
4. **总结和State不一致。** 文本承认空满等内容未展开、需要巩固，State却已经全部掌握、没有缺口。

没有再观察到原来长串照念同组选择题，但这不能抵消上述缺陷。优先应处理掌握判断与剩余缺口的矛盾、总结格式，再核对知识内容与指针约定。**本轮只测试、记录，没有修业务代码。**

## 覆盖边界和完整证据

- 实际覆盖了首轮5次切点和进入补强；补强第2次遇格式失败，**没有覆盖补强8次耗尽**。
- 人设未实际触发的初始样本已标明，补场也单独留档，不冒充覆盖成功。
- 恢复/重试只证明内存教学服务层表现，不证明HTTP幂等、数据库持久化、浏览器退出竞态或真实服务商宕机恢复。
- 仍只有两个concept点；没有在本批覆盖memory/design。双方为同型号模型模拟，不是真人学习效果或总体可靠性统计。
- [误解组](misconceptions/README.md)、[含糊与跑题组](unclear-offtopic/README.md)、[质疑与照抄组](challenge-copy/README.md)。每个样本有完整对话、真实模型输入、工具评估和State。

已核对所有样本的教学代码哈希未变、成功输入与评估计数一致、失败轮State不变；真实学生角色没有内部工具消息。未部署、未使用正式数据库或发布入口。完整产物已做敏感值与链接检查。

## 真实模型抽样：改善与失败都保留

真实deepseek-v4-flash扮演导师和独立学习者，后者只看可见对话，无预写回答。原课循环队列、链队列两个concept点。

| 内容 | 观察 |
| --- | --- |
| 循环队列 | 5次回答，依次记录假溢出、绕回、队空、队满和一般状态；不再首答后就把整个点完成 |
| 链队列 | 3次回答，继续确认出队判空、对比和受限操作，最终State全部demonstrated |
| 复合要求风险 | “入队在rear之后插入、无队满”被模型从头尾指针/动态分配回答中过度确认；定向追加“每项整体满足”说明后，仍判demonstrated。该语义风险未解决，不算全部教学验收通过 |
| 额外追问 | 导师还问了元素个数公式，超出一般状态条目本身；程序没有把这个额外问题作为新的完成条件 |
| 原课资料 | rear约定冲突仍沿用旧材料，没有在本轮改教材 |

8次学生输入对应27次模型请求：导师19、学习者8，其中2次工具多余字段被框架反馈后修正。第8次回答已成功应用，State进入wrapup，随后实验脚本写run.json遇OSError/Errno22；这不是已证实的教学服务失败。保存了[原失败状态](run-artifact-error.json)，从已保存State调用无模型的finish完成反馈，没有重算任何作答。精确文件系统原因未确定。

随后定向回放使用相同链队列问题、回答与前置State，最终提示词的3次真实请求（含工具参数修正）仍复现复合项宽判。**完整8答是初版逐项提示，定向回放是追加复合项说明后的提示，不冒充最终版本整段无失败通过。** 本批共30次真实请求，没进入补强，不能代替困难场景全量回归或真人效果验证。

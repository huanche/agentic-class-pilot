# 教学方案实现细节（备查）

先读[教学方案](plan.md)。这里只列实施时需要对接的内容。已实现，未部署。2026-11-05。结果见[实施记录](implementation.md)。

## 1. State 每个知识点保存什么

2026-11-10起，新建typed会话增加`mastery_version=1`。没有此标记的旧会话保持原协议，不把旧掌握判断自动转成逐项证据；内容协议和原`flow_version=4`不变。

| 新记录 | 内容 |
| --- | --- |
| requirements | 从memory.requiredElements、concept.understandingPoints、design.capability/constraints/successCriteria生成，id为字段名:序号；初始unconfirmed，后续needs_help或demonstrated |
| 每项表现 | evidence、程序保存的studentText、具体gap；未更新项保持原状，新证据可将原先已说清项改为需帮助 |
| question_targets / latest_question / question_history | 每次实际提问和关联要求、阶段及帮助类型；task_question仍是最初原题 |
| assessment_history | result为本问结果，point_result为程序汇总整点结果，answer_assessment保留本次工具原文，并记录目标及对应实际问题 |

新工具`AnswerAssessment`只允许answer_result（correct/partial/misconception/unanswered）、evidence、updates和next_step；updates用requirement_id关联当前点，并给出demonstrated或needs_help和依据。模型不能直接提交整点mastered。一答可更新多个要求，未问过/无新证据的项不更新。单纯提问允许assessment=null。

程序根据全部requirements汇总status、known_parts和gaps；只有全部demonstrated才mastered。其余gaps区分“尚未确认”与已发现的问题。反馈中仅未确认的标“本次尚未确认”，不当作学生不会。历史、原题与逐项证据随原snapshot事务保存。

保留已有的知识点内容、掌握状态、判断依据、回答历史和轮数；新增 known_parts、gaps、next_step、help_history 和 task_question，分别保存以下记录：

| 记录 | 内容 | 谁来更新 |
| --- | --- | --- |
| 已会部分 | 学生已经准确表达或完成的内容 | Agent 评估后，通过工具写入 |
| 剩余缺口 | 遗漏、具体误解、尚未完成的步骤 | Agent 评估后，通过工具写入 |
| 已给帮助 | 实际发出的提示、解释、例子或示范 | 回复成功后，由程序关联到本轮和当前点 |
| 学生表现 | 学生原话，以及帮助后答出了什么 | 程序保存原话，Agent 提交判断 |
| 当前题目 | 原题及学生已有方案的消息关联 | 程序保存和恢复，不因追问覆盖原题 |

例如：

```text
知识点：栈的基本操作
状态：部分掌握
已会：Push 是插入，Pop 是删除
缺口：误认为插入和删除发生在两端
已给帮助：提示过“操作集中在栈顶”
学生表现：只重复“栈顶”，还没解释清楚
```

每轮更新，不在首轮结束后再调用模型统一总结。学生原话、导师实际回复与 Agent 判断分开保存。已会部分和缺口可按新回答修正，历史回答继续保留；不建立逐项评分表或额外语义审核。

## 2. 一条回答如何处理

新会话另有`reply_version=1`：程序按requirements原顺序选第一项未完成要求；同一目标且本问含糊/未回答则clarify，同一目标仍未完成则explain，新目标有缺口则correct，否则ask；没有当前点则summarize。计划通过`teaching_plan`交给模型，不采用模型建议的目标或最终正文中的字段。

评估工具与通常两次模型请求保持不变。最终直接接收非空文本，不解析JSON。首次实际全文保存为原题，后续全文、程序目标与planned_action进入question_history/help_history。外部学习记录标unclassified_tutor_text、guidedPolicy=null，不把计划动作当实际帮助分类。没有reply_version的旧会话保持旧协议。程序仍不能保证模型实际文字完全遵循计划。

程序从 State 按固定顺序选当前点，传入原题、上述学习记录、学生回答，以及当前 type 的系统提示词。

一次 Agent 运行中：

1. Agent评估当前回答，调用提交评估工具，提交本问结果与各要求的证据更新。单纯提问或表达不清时如实记录，不伪造掌握。
2. 工具在本轮工作副本中更新该点记录，调用程序推进逻辑计数和选点；工具不再调用模型。
3. 工具返回更新后的当前点、阶段、原题、学习记录和继续/换点/总结动作。
4. Agent 读取工具结果生成最终回复。换点后，系统提示词同步使用新点的 type；先反馈旧点，再问新点。
5. 程序关联实际发出的题目及帮助，将回复、State 和学习记录一起保存。

首次开场直接生成第一问，不提交评估。一次运行通常包含工具前、工具后两次模型请求，不等于一次模型请求。

模型输入按职责整理：评估看当前点累计进度、最近两次表现和帮助，并单列最近实际问答；生成只看更新后的当前点和新计划，旧点只留简短反馈依据，不重放旧导师回复或评估工具参数。完整历史继续留在 State，不新增语义校验。原因与真实回放见[追问修复记录](validation/2026-11-06-reply-fixes/README.md)。

工具不能指定下一个知识点、修改限额或直接写正式数据库。同一输入重复调用工具只应用一次进度更新；回复失败不单独保存评估和计数，沿用原命令重试与事务。内部工具循环的技术预算与学生轮数分别处理。

## 3. 程序推进规则

- 首轮按 points 原顺序，每点最多 5 轮；掌握就提前换点。
- 首轮走完后，按原顺序只处理未掌握点，每点最多 8 轮；掌握就提前换点。
- 不再设置“后期掌握仍需确认”，不再进入统一深入讨论阶段。
- 本阶段最后一轮掌握时，优先按掌握处理；求助、不会也计学生轮数，模型失败不计。
- 补强从原题和首轮缺口继续，补强走完后不再开启新补强轮次。
- 首轮全部掌握，或补强全部处理完后，由程序进入总结。耗尽轮数不改变真实掌握状态。
- 提示后学生自己答出、解释清楚或修正正确，可以掌握；不强制另出一道题。
- memory 不因答案与提示同措辞就判照抄，结合提示程度和学生自行补充的内容判断，不额外要求解释原因。

新建三类型会话使用 flow_version=4 和 5/8 轮；旧快照和无 type 的内容保持原流程。课堂补强不重复开启，不禁止学生主动进入课后继续；课后沿用正常引导，全部掌握或学生主动退出时结束，不自行套用课堂限额。旧会话不自动升级，不删除既有讨论题或学习记录。

## 5. 总结反馈

从 State 的掌握状态、已会部分、缺口及实际回答整理反馈，不在总结时重新评估。内部轮数继续供程序推进使用，学生反馈不展示分数、星级和轮数。提示后自己完成的点仍归为已掌握；记录不足标“本次尚未确认”。

“本次尚未确认”在待巩固区单独标注，不虚构错误。提前结束时尚未学到的点单独显示、计数为“尚未学习／评估”，不与已发现缺口的点混淆。

待巩固点给一个对应原题、具体缺口的下一步建议；继续巩固时恢复这些记录。检查反馈没有把 AI 讲解当学生表现，没有给已掌握点强制安排新题。

## 6. 课后入口和退出

进入时由程序检查实际掌握进度：全部掌握就提示完成，不启动新题；否则按固定顺序继续未完成点。有记录则接原题和缺口，没有开始过的点生成第一问。每轮仍通过 Agent 工具更新 State，全部掌握时结束引导并更新反馈。

随时退出按钮保留已提交进度，退出不改变掌握结论，重新进入继续原进度。通过现有可中断的 finish 命令取消在途回复，已用独立数据库验证退出后不写入迟到结果。

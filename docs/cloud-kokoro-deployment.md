# 云端 Kokoro 配音与回退

教师端和 TTS 分开部署。Kokoro 使用 CPU，默认中文音色“小伊”（`zf_xiaoyi`），
模型随 Docker 镜像发布，启动时无需访问模型下载网站。

## 发布顺序

1. 合并代码前，PR 分别构建教师端和 Kokoro 镜像；PR 不部署生产服务。
2. 主分支推送触发 `teacher-deploy`，构建、更新教师端并进行健康检查。
3. 教师端发布成功后，在同一个提交上手动运行 `kokoro-deploy`。
4. Kokoro 先启动并真实合成一段“小伊”音频，通过后再切换教师端环境配置。
5. 教师端重新创建容器以载入环境文件；Docker 的普通 restart 不会重新读取 env-file。

两个工作流共享部署锁。替换教师端前会等待最近仍活动的生成任务，最多等待十分钟；
超过时间会保留当前服务。该检查不能替代持久化队列，后台任务仍不支持跨服务重启恢复。

## 隔离与限制

- 容器：`agentic-kokoro`，仅映射 `127.0.0.1:13305`，不开放公网 TTS 端口。
- 镜像：`zmzm1443/agentic-teacher:kokoro-<提交前七位>`；与教师镜像使用不同标签。
- 限制：1 个 vCPU、1 GiB 内存、不使用交换区、同一时刻合成 1 段。
- 单次模型推理最多 128 个音素，按标点和词边界分批，沿用模型的停顿与拼接逻辑。
  完整讲稿仍返回一段 WAV；原先每批最多 510 音素会在长讲稿上超出内存限制。
- 可写目录：`/opt/agentic-class-pilot/teacher_agent/.runtime/kokoro/runtime`。
- 配置备份和实测：同级 `releases/<版本与时间>/`，目录权限 700；环境备份权限 600。
- 不移动原有课程、数据库或音频数据。原 Qwen Key 保留，只通过开关暂时禁用托管 Qwen。
- `COURSEWARE_JOB_CONCURRENCY=1`、`PARALLEL_TTS_CONCURRENCY=1` 限制并发，减少低配服务器争用。

该资源限制优先保证网站可用。并发生成会排队，云端实际速度应以部署后的 WAV 实测为准。

## 验收

工作流输出 TTS 健康状态、真实 WAV 时长/生成耗时、容器资源用量，并验证教师端重新载入
本地 TTS 配置。登录教师端后，在“模型与语音设置 → 语音合成 → Lemonade TTS（本地）”
选择音色并执行“测试 TTS”。新课件使用提交时选定的音色；旧课件需要重新配音。
PR 构建检查短句及 306 字中英混合讲稿；云端配置切换前也必须完整合成该长讲稿，
并确认模型进程未重启，避免短句通过但真实课堂配音因内存不足失败。

## 回退

安装过程中失败会恢复部署前的环境文件、原 TTS 容器，并重新创建教师端容器。
成功后的配置备份仍保留在工作流输出的 `releases/…` 目录。

需要切回部署前的配音配置时，在服务器上恢复该目录中的 `teacher-prod.env` 到
`~/teacher-prod.env`，然后用项目的 `server-deploy-teacher.sh` 以相同教师镜像标签重新部署。
必须重新创建容器，普通 restart 不会应用恢复的配置。可停止 `agentic-kokoro` 释放其内存，
保留容器与模型以便恢复。

代码回退基线为 Git 标签 `pre-background-kokoro-20261018`，对应发布前的主分支。
教师端部署脚本保留当前和上一版 `main-*` 镜像；Kokoro 使用独立 `kokoro-*` 标签，不被该清理删除。
代码与配音配置可分别恢复，本次没有数据库结构迁移。

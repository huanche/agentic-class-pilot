# 全部解耦工作的执行边界与验收

> 2026-10-26 顺序调整：优先尝试“所属服务内部视图/查询层 + 稳定只读 API”，不把平台副表、物理拆库或事件总线当成解耦必经步骤。只有直接 API 无法满足经过验证的可用性/性能要求，且团队接受副本一致性成本时，才启动下文的 outbox/投影方案。远端 `main` 已重构学生端目录；任何学生端开发必须先整合并复核新代码，不能继续在旧 `apps/integration/` 上叠加改动。

面向团队和 AI 的职责、关键流程与契约导航见[三端架构与接口](architecture-boundaries.md)；本页记录实施顺序与验收门槛。

## 2026-10-28：当前决策与下一段执行顺序

**先继续按小切片完成数据与接口解耦，不合并生产 `main`。** `decouple-implementation` 已推送到独立分支，`integration-contracts` 的 5 个任务在提交 `17e8e9a` 全部通过；这只覆盖契约、生成客户端兼容和部分平台适配。新接口开关仍默认 `legacy`，跨服务直查与数据库权限尚未清除。根目录 `decouple` 的浏览器手测不等于独立工作树的新路径验收。`main` 上的 `platform/**`、`teacher_agent/**`、`student_agent/**` 推送会触发对应生产部署，不能把合并当作服务器测试的第一步。

1. **先封住已知功能缺口。** `/api/quiz-grade` 对普通教师或学生可能被平台授权拒绝（HTTP 403），失败时简答题当前会给半分。按教师预览和学生已选课且已发布课堂分别定义授权，修复后核对真实成绩；音频翻页时 `play()` 被 `pause()` 中断的日志单独处理。两项均与接口切换分开提交，避免以“页面继续播放”误判习题通过。
2. **逐条迁移剩余跨表读取。** 先列出平台对教师课堂、工件、资料、知识包、图谱和学生旧会话对教师课堂的直查，固定各调用的授权、排序、空值、下架和故障语义。由数据所属服务提供最小只读 API，更新契约并生成客户端。只读请求先用受限采样对比旧结果；写请求只保留一个权威写入方，不双发。
3. **在隔离环境打开新路径。** 独立测试数据库、对象存储位置、服务端口/域名和密钥；可与现有服务器共机，但不得连接生产数据卷或向生产服务发写请求。分别打开各开关，跑发布→选课→学习→学情→下架/撤销、旧课程别名、未授权访问、服务故障与回滚。记录逐项结果和版本号；团队可在该隔离入口手工验收。
4. **最后回收数据权限。** 新接口稳定后建立平台受限运行角色，在隔离库验证平台不能读取 `teacher`/`student` 表，且三端业务仍通过；保留回退窗口和迁移演练。未完成前不删除旧实现或撤销生产权限。
5. **再做服务内部模块边界。** 平台与学生端的 Python 导入边界、教师端的 TypeScript 依赖方向可以分别试用 Import Linter 和 dependency-cruiser：先报告现状，再只阻止新增违规，清理旧违规后设为 CI 阻断。它们不检查 SQL 跨表、HTTP 契约或业务权限，不能替代第 2–4 步。

生产合并按可回退的服务/能力切片进行；每片先有构建检查和隔离环境人工验收，明确生产自动部署、数据库迁移与回退步骤后再合并。不能把当前 270 个变更文件的独立分支直接视为一次可安全上线的发布包。

对应 2026-10-19 的五批实施计划，基线为本地 `decouple` 的 `9676da7`。这是执行约束和当前状态，不是“全部完成”报告。

## 必须修正的原计划假设

1. **双读先观察，不能先返回新副本再比较。** 原链路继续权威返回，投影只作采样比较。副本命中但落后、下架事件迟到、旧发布事件重放都必须检测；“未命中才回源”不足以保证一致性。
2. **事件不能只是发布后 HTTP 通知。** 发布/下架与 outbox 写入须同事务提交；异步派送至少一次，平台以事件 ID 幂等、课程内递增版本去乱序，保留撤销 tombstone。接收确认应在落库后。历史回填、重试、死信、积压指标、对账不可省略。
3. **不把 HTTP 状态当作就绪与业务成功。** 教师健康接口 200 仍可能报告数据库不可用；建课新建 201/已有 200。生成器与测试现已覆盖这类差异。
4. **不把全面移除 /internal/ 字符串当作验收。** 路由提供方、生成产物、契约和测试本来就必须包含路径；应禁止业务代码绕过客户端，而不是盲删路径。
5. **缓存鉴权有权限撤销风险。** 必须先确定撤销/下架时效，按身份、方法、资源隔离缓存；默认失败关闭。不能用平台故障时继续读敏感内容来满足“无 503”。
6. **会话入库不等于多实例可用。** 还需 session lease、过期接管、并发版本、单写者、幂等学情、流连接重连与共享资源；这是 SaaS 生产前提，不宜归为锦上添花。
7. **文件短不等于解耦成功。** 拆分依据依赖方向与数据归属，不以 800 行硬上限改变稳定模块。模型拆分必须保留旧 import 和 SQLModel 元数据注册顺序。
8. **职责迁移并非纯重构。** 学生独立模式、旧账号/课程码/上传入口是否保留，须先确定兼容策略；未确定前不删入口。原已转交学生负责人条目也不自行认领为已完成。

## 三端职责与数据归属

| 范围 | 权威来源 | 跨端依赖及约束 |
| --- | --- | --- |
| 用户、浏览器会话、选课、课程所有权、平台 UUID/教师 ID 映射、BYOK | 平台 | 教师/学生端通过后端契约读取；服务密钥不能代替最终用户权限；BYOK 不进入发布投影 |
| 编辑中的课程、资料、知识包、课堂场景、发布版本 | 教师端 | 平台目前跨 schema 读取；先封装只读适配器，之后仅消费可靠发布快照 |
| 课堂执行、对话、播放进度、掌握度、学习事件 | 学生端 | 平台目前聚合 student schema；先明确读模型，学情写入保持唯一权威链路 |
| 学习目录/进入课堂的授权结论 | 平台权限 + 教师当前发布状态 | 投影不是独立授权依据；未选课、所有权不符、已下架、版本落后须失败关闭 |
| 路由、内部 API、学习上下文、宿主消息 | contracts | 允许新增可选字段；破坏性更改升版本并保留兼容窗口 |

上述表是服务归属，不代表当前已具备组织级租户隔离。平台模型目前以 user/course/enrollment 的用户和课程关系为主；若 SaaS 包括学校/企业租户，还需另行明确租户边界、配额和跨租户隔离验收，不能以完成本次解耦代替。

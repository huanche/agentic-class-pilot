# 复合要求与重复帮助修复

本轮使用 Matt diagnosing-bugs / TDD，沿用已确认的提取接口及学生命令 HTTP 测试入口。没有增加状态字段或模型调用步骤，没有修改选点、掌握汇总或5/8轮规则。未提交、未部署。

## 修复

1. 新提取：在已有列表字段的工具描述中明确独立事实分项，因果关系仍作为完整关系；不把分项变为逐条考试，不把插入位置伪装成容量性质的原因。
2. 存量课程：不迁移或重编号已有要求。评估工具已有 evidence 字段先核对各含义的累计学生证据，再决定 updates；要求复合项的每个事实分别有依据，缺少未考查部分时省略更新、保持 unconfirmed。历史学生回答可以补足，教师讲解不能补足。
3. 帮助选择：连续两次 unanswered / unclear 时使用已有 clarify 动作，定位题意、先修或操作卡点；学生明确提问仍优先直接解释。
4. 回复生成：依据 pointConversation 对照最近无效帮助，不再次展示完整实现或换说法后讲得更长；宽泛“不会编程”不作为重放完整程序的具体卡点。下一步不能是复述本轮刚展示的答案。明确请求完整示范仍允许提供。

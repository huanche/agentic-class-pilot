# Design 首次任务泄露解法修正

本次只修改提取规则和 design 教学类型规则，不新增字段、不迁移旧课程、不调整选点、轮数或掌握汇总。

## 修改

- 提取阶段区分真实题设与示范实现，capability 不再要求照写参考代码，constraints 不把示范边界和公式当作唯一条件，successCriteria 接受等价实现。
- 首次任务保留具体目标和必要限制，把需要学生确定的边界、起点、公式留给学生；明确指定的公式或算法继续保留。旧课程中的示范实现也不应直接照抄为题干。
- 学生主动求助后仍可解释必要的一步，后续等价解仍可被接受。

## 验证经过与限制

真实模型测试入口为 learning_points 和 session-facing service.start_discussion/classroom_turn，不写数据库，不重置已有课程。测试文件 test_design_task_live.py 默认跳过，使用 DESIGN_TASK_LIVE=1 和唯一 DESIGN_TASK_RUN 名称启用。输出保存在对应目录。

原始失败：../arrays-e2e-2026-11-11/view-turn06.json 已同时给出 for 边界和赋值公式。修改前本次 baseline 的首次任务与提取抽样却均通过初版检查，说明故障并非每次重现；不能声称新规则在受控对照中证明成功率提高，也不是一次完整确定性的 Red→Green。

首次修改 updated-1：3 个用例自动通过，但人工复核发现题干仍给了“从下标0开始”，且只要求“5个奇数”，遗漏原任务的指定序列。因此该轮不是完整语义通过。已加强规则与检查，不覆盖记录。

最终 updated-2：3 个真实模型用例全部通过并人工复核：

1. 数组示范提取为可复用的循环赋值能力，不把 i<5 或 2*i+1 写成能力/强制约束；保留覆盖合法下标和不越界的标准。
2. 明确给定公式的反向用例，在提取和首次题干中均保留 2*i+1，让学生自己确定下标范围。
3. 使用原课时已存的过细 design 要求：首次题干明确目标 {1,3,5,7,9}，没有给下标起点、循环边界或公式；学生求助后解释0到4的边界但不判掌握；随后接受 i+i+1 的完整正确解。

最终首次题干：“请写一段 C 程序：定义 int a[5]，用 for 循环给数组的每个元素赋值，使最终数组内容为 {1, 3, 5, 7, 9}。写完后，再说明你如何确认这 5 个元素都是奇数。”

离线相关回归首次为58通过、33跳过。部分 PostgreSQL 命令测试因未启用独立测试数据库跳过；未把跳过视为通过。最终回归结果见工作记录。

准备阶段有两次配置失败（未加载模型凭据、平台占位凭据401），不计入模型行为结果。最终在进程内加载已有教师 DeepSeek 凭据完成实测，未修改凭据文件。

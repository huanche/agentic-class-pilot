# 修复重复追问和切点夹带旧题

Status: resolved

用户要求先定位原因，再修复；不部署。沿用已确认的学习命令接口测试，外部模型 HTTP 是唯一替身。

## 证据与原因

- 原始实测第20次回复程序已选链队列，但正文仍追问循环队列；第37–43次连续近似追问。
- 修改前真实模型重放：卡住场景仍重复同一组二选一；切点场景虽然本次没有继续追问旧题，仍长篇讲解旧点。模型表现具有不确定性。
- 生成请求中 previousPoint 是评估前完整快照，含旧 next_step/task_question/help_history；工具评估参数和最近十条消息也带着旧任务。系统指定新 focus，但旧行动要求仍有多个来源。
- 卡住场景实际收到帮助记录，不能归因于丢 State；评估生成的 next_step 重复了刚才无效的方法，回复沿用，没有具体比较和调整要求。重复的模拟学生输入放大了现象，但不能解释导师为何不换教法。

## 验证

先在公开命令接口验证生成请求不再携带旧任务行动要求，再重放原真实场景检查教学行为；离线合同检查不证明模型教学质量。保留原报告与原始失败。

## Answer

先复现命令接口生成请求携带旧 next_step 的失败，再按评估/生成整理输入；真实命令测试复现重复选择题和连续重复图示，再增加最近实际问答对照，并使生成只执行新计划。完整 State 历史未删，未增加状态字段、语义校验、轮数或掌握规则。

最终真实模型通过命令接口连续三次作答及原始场景连续三次回放；切点回放不再追问旧题。仍有局部重复和冗长，不宣称所有模型回复已保证。后端256通过、3跳过（2项专用平台库、1项默认关闭的真实模型测试），真实模型测试单独开启后通过。未部署。详见[记录](../../../student_agent/docs/knowledge-teaching/validation/2026-11-06-reply-fixes/README.md)。

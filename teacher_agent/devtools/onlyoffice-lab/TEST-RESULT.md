## 未通过或未完成的部分

1. **旧式“下一次点击后隐藏”未正确执行。** 原稿第八页的说明框使用 `subTnLst/set`、`masterRel="nextClick"`、`afterEffect="1"` 和 `style.visibility=hidden`。ONLYOFFICE 原生放映后这些说明框仍叠在画面上，因而不能把这个试验判定为动画高保真通过。没有用 AI 重画来掩盖该差异，也没有改原稿动画 XML。
2. **未完成五页全程无干预配音验收。** 测试浏览器在第四页第九段之后多次出现 HTMLAudioElement `paused=true`，当时尚未收到 `ended`，应用也没有执行停止。这一观察只能证明音频被暂停，尚不能确定暂停的发起者。将浏览器显示后仍复现，不能简单归因于后台节流。随后停止该连续运行，单独检查第五页全部动画。增加媒体暂停记录后，21:06:06 再次在第一页配音 1.18 秒处记录到 `media-paused`，当时 `document.hidden=false`；动画和“继续”按钮随音频一起进入暂停，状态保护已验证。不能报告 50/50 段全程连续播放通过，也不使用这一轮的总墙钟时间评估速度。
3. 原生引擎的字体替代、特殊旧动画、嵌入音视频和其他 PPT 文件尚未普遍验收。已准备开源中文字体包，但本轮没有安装到宿主或测试引擎，也没有复制 Windows 商业字体。

## 试验播放器的兼容处理

- 修正插件会话 URL：ONLYOFFICE 会追加语言参数，且 SDK 会从插件 HTML 相对地址读取 `config.json`；两个入口均经过会话校验。
- 消息限定为本页面的插件窗口、同源与随机会话，不使用任意全局编辑器调用。
- 启动后明确跳到目标页；导航入参从 1 开始，事件索引从 0 开始；等待换页过渡，避免把第一组点击误用于结束过渡。
- 配音按真实结束事件推进，预取最多后三段。播放器新增对独立媒体暂停的状态保护，使动画与“继续”按钮跟随音频暂停；这一保护不代表已找到测试浏览器暂停的根因。
- 提供仅回退试验网关和两个试验容器的 `cloud-stop.sh`。正式教师应用始终没有切换到实验渲染器。

## 后续建议

在把 ONLYOFFICE 作为正式高保真模式前，需要先完成旧式隐藏指令的等价兼容转换，并在教师日常浏览器完成五页 50 段的连续音画回归。原始样本应保留为对照；兼容转换应另存副本并记录动画差异，不能再声称修改后的 XML 与原稿字节一致。
